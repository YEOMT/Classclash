# 05. 검증·인수 조건·최종 납품

## 1. 결과 표기 원칙

동봉 인수 조건은 **214개**이며, 모두 초기 상태가 **NOT_RUN**이다. 이 명세는 이 조건들의 실제 실행 결과를 포함하지 않는다. 문서 작성·JSON 구문 검사·테스트 목록 작성이 실제 게임 검증을 뜻하지 않는다.

Codex는 각 항목을 PASS / FAIL / NOT_RUN / BLOCKED / NOT_APPLICABLE 중 하나로 기록한다. NOT_APPLICABLE에는 사유가 필요하다. 시험 대상 커밋, 자산 해시, 실행 명령, 설정, 시간, 기기·브라우저, 실제 증거 경로를 기록한다.

이전 원격 문서의 PASS를 새 아트·새 AI·새 배포에 그대로 옮기지 않는다. 서버 내부 AI 시험, 독립 WebSocket 클라이언트 시험, 브라우저 시험, 물리 기기 시험은 구분한다. Headless/SwiftShader/물리 GPU도 구분한다.

## 2. 회귀 시험의 층

### A. 정적·콘텐츠 검사

타입·lint(기존 도구가 있으면)·스키마·18영웅/36스킬 참조·자산 manifest·PNG 투명도·frame bounds·socket·원본 해시·license provenance·비밀 값 노출·package clean build를 검사한다.

### B. 순수 전투 시험

격리된 같은 초기 상태에서 이동·충돌·슬롯·거리·판정·상태·공성을 실행한다. 서버 시간을 임의 조작해도 운영 경로를 별도 가짜 구현으로 바꾸지 않는다. 고정 seed는 시험에만 적용하며 운영 뽑기와 섞지 않는다.

### C. 방·경제·상태 시험

사람과 AI의 같은 명령 경로, 정답 보상 1회, 구매 원자성, 생존 중 금지, 사망 중 퀴즈, 재접속, 중복 출정, 판별 버전, 재경기 초기화를 검증한다.

### D. 브라우저 E2E

실제 앱을 빌드하고 실제 서버와 연결한 브라우저로 진입한다. mock 전투로 만든 영상은 E2E가 아니다. 사람1+AI29 전체 경기, 호스트·학생 카메라, 퀴즈 입력·사망 정비·성장·재출정·시상·재경기를 포함한다.

### E. 부하·성능

독립 30학생 WS+호스트, 30AI 게임, 렌더링 스트레스, 저장·재접속 병행을 분리해서 측정한다. 모두 한 개발 PC에서 동시에 돌려 서로 간섭시킨 결과를 장치 성능이라고 단정하지 않는다.

### F. 공개 배포

실제 공개 origin의 HTTPS/WSS·외부 참가·버전·영구저장·재접속을 확인한다. 공급자 콘솔의 '배포 성공'만으로 완료하지 않는다.

## 4. 전체 수업 흐름 시험

### 4.1 사람 1명+AI 29명

호스트 생성→학생 참가→30명 채우기→20문제→정비→성장/뽑기→라인 선택→출정→10문제 중 사망→문제 이어 풀기→정비·교체→수동 재출정→넥서스 파괴→시상→새로고침한 결과 동등성.

두 번째 출정에서는 레벨·강화가 다른 영웅 인스턴스를 선택해 성장 이전이 없는지 확인한다. 생존 중 조작 금지를 UI와 서버 직접 요청 양쪽에서 시험한다.

### 4.2 AI 30명

호스트 한 명으로 전 과정을 완주한다. AI들은 실제 학습/지갑/창고/정비 경로를 사용한다. 특정 봇이 정비를 끝내지 않아 전장이 비거나, 같은 라인으로 동시에 갈아타는 정체를 기록한다.

### 4.3 재경기

첫 경기 종료 후 **3회 연속 재경기**를 완주한다. matchId, 퀴즈, 지갑, 영웅 생존, 창고, 이벤트 ACK, 카메라, 오디오, 렌더러 구독, 메모리, 방 참가자는 각각 적절히 초기화/유지되어야 한다. 이전 경기 투사체·사망 화면·보상이 남으면 실패다.

### 4.4 소규모·비균등 상황

10명,20명,홀수 참가 인원,한 라인에 몰린 출정,한 학생 장시간 정비,재접속 중인 학생이 있어도 전체 진행이 멈추지 않는다. 전투 중 실제 연결 끊김을 봇으로 몰래 대체하지 않는다.

## 5. 성능 목표와 측정 방법 [제안]

| 항목 | 초기 수락 목표 | 측정 조건 |
|---|---|---|
| 서버 전체 틱 | p95 ≤40ms, p99 ≤50ms | 30명 실제 엔진, DB·방송 포함, 운영 설정 |
| 틱 누적 지연 | 지속 증가 없음 | 13분 이상 1배속, actual tick/wall time 추적 |
| 호스트 프레임 간격 | p95 ≤20ms, p99 ≤33.3ms | 실제 GPU, 1920×1080 또는 기록된 해상도, 모든 전장 표시 |
| 학생 프레임 간격 | p95 ≤33.3ms | 지정 시험 장비, 퀴즈·전투 동시 표시 |
| 명령 응답 | p95 ≤500ms | RTT 약100ms 이하의 명시된 시험망, durable ACK |
| 정상 접속 이벤트 | 중복 피해 0·필수 사건 유실 0 | 생성→수신→소비→표시 로그 대조 |
| 자원 중복 | 0 | 재전송·새로고침·연결 변경 경계 |
| 진행 중 메모리 | 무제한 증가 없음 | 3회 재경기 후 안정화·유지 객체 비교 |

이는 지원 기기의 성능 보증이 아니라 개발 수락 목표다. 실제 기기 사양·GPU/소프트웨어 렌더링·브라우저·네트워크·서버 크기를 반드시 함께 적는다. 60fps 평균만 제시하지 말고 p95/p99·긴 프레임·GC·입력 지연을 남긴다.

### 5.1 밀집 스트레스

실제 경기에서 관측한 최대 개체 수를 기준으로 추가 여유를 둔다. 초기 합성 스트레스는 영웅30+4웨이브 미니언112=142 이동 유닛, 구조물14, 동시에 여러 투사체·24개 정도의 지속효과를 포함하는 장면으로 시작할 수 있다. 이는 부하 시험용 장면이지 운영에서 개체를 강제로 늘리는 규칙이 아니다.

전투 중 누적 미니언을 임의로 삭제하거나 다음 스폰을 생략해서 통과하지 않는다. 필수 효과를 생략하지 않되 장식 입자의 밀도와 텍스트 수를 조절할 수 있다. 학생의 화면 밖 렌더링 생략과 호스트 전체 전장 표시를 구분한다.

## 6. 밸런스·완주 분포

기본 검증 조건은 표준 AI 30명·동일 정책·고정 40시드다. 목표: 40경기 중 최소 28경기가 600~780초, 중앙값도 그 범위. 이는 기존 명세를 잇는 목표이며 실제 결과가 아니다.

각 seed에 승패, 종료 시각, 첫 처치, 타워별 파괴 시각, 넥서스 첫 피해, 최대 유닛 수, 정체·경로 실패, 영웅 선택/성장, 틱 비용을 기록한다. 관측 상한에서 미완주한 seed도 분모에 포함한다. 양팀 방향을 바꾼 거울 시험으로 좌우·순서 편향을 별도로 확인한다.

튜닝 중에는 한 번에 바꾼 축을 좁혀 인과를 추적한다. 40경기 수행이 차단되면 완료된 수와 이유를 보고하고 완주 분포 PASS를 선언하지 않는다. 목표 시간에 맞추려고 퀴즈 채점·뽑기 확률·강제 피해·승리 규칙을 몰래 바꾸지 않는다.

## 7. 네트워크·장애 주입

테스트 전용 환경에서 왕복 지연 50/150/300ms, 짧은 단절 2/10초, 일시적인 전송 정체, 학생 새로고침, 호스트 재접속, 서버 정상 재시작, 저장 오류를 시험한다. WebSocket(TCP)의 순서 보장을 무시한 가짜 패킷 손실 수치를 쓰지 말고, 실제 시험이 지연·단절·애플리케이션 재전송 중 무엇인지 표시한다.

검증: 정답·구매 ACK 경계, currentQuestionId 유지, 퀴즈 마지막 문항 뒤 쿨 시작, 재출정 중복 방지, 오래된 소켓 권한 차단, 이벤트 재전송 중복 효과/피해 방지, 종료 결과 재접속 동등성, 서버 재시작의 데이터 내구성.

## 8. 시각 시험은 자동 검사와 사람 판단을 분리

PNG 존재·프레임 색상 변화·18개 silhouette hash 차이는 미적 품질의 증명이 아니다. 실제 화면 비교와 동작을 검토한다. 전투 시각은 1배속 영상과 프레임 스텝에서 release/impact를 대조한다.

기준 영웅 세 명과 나머지 15명 전부를 확인한다. 특정 직업만 보기 좋고 나머지가 이전 인형으로 남으면 전체 리워크 완료가 아니다. 성능 모드에서도 모든 영웅과 스킬 의미가 남아 있는지 확인한다.

## 9. 필수 개발 산출물

- 기존 프로젝트에 통합된 전체 실행 소스, 완성 자산 원본/아틀라스/manifest.
- `BASELINE_AUDIT.md`, `ART_STYLE_GUIDE.md`, `ASSET_PROVENANCE.csv`, `VISUAL_REVIEW.md`.
- `BALANCE_CHANGELOG.md`, `ENGINE_CHANGELOG.md`, 새 테스트와 시나리오.
- `TEST_REPORT.md`: 실제 PASS/FAIL/NOT_RUN·실행 환경·증거.
- `DEPLOYMENT.md`, 실제 환경 설정 예시, 배포 파일, backup/restore/rollback 절차.
- `DEPLOYMENT_REPORT.json`: 실제 URL·커밋·자산 해시·외부 시험.
- Git commit SHA, push 확인, PR URL/병합 상태, 배포된 SHA.
- 이전/이후 스프라이트 비교, 호스트·학생 전투 캡처/영상, 혼자 AI 시험하는 간단한 안내.

구현 기준: 로컬/원격 커밋, 보존한 미업로드 아트
완료 범위: 아트 / 매치엔진 / VFX / UI / 서버 / 배포
