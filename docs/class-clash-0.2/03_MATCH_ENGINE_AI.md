# 03. 매치엔진·이동·자동전투 AI

## 1. 구현 방식과 보존 경계

기존 `src/server/combat.ts`, `combat-geometry.ts`, `src/shared/heroes.ts`, `combat-types.ts`를 실제로 읽고 확장한다. 현재에도 표적 선택, 공성 목표, 공간 해시, 경로, 액션, 상태이상, 스킬 판정이 있으므로 중복된 두 번째 전투 엔진을 만들지 않는다. 필요한 경우 작은 모듈로 분리하되 공개 상태·저장 버전·테스트 계약을 보존한다.

팀파이트 매니저 2의 소스나 비공개 규칙을 복제하는 문서가 아니다. 아래는 **Class Clash의 현재 규칙에 맞춘 구현 제안**이다. 역할 분화, 덜 흔들리는 판단, 전투 합류, 합리적 후퇴, 실제 공성 완료가 목표다.

## 2. 서버 시뮬레이션의 기본 계약

- 기존 20Hz 고정 틱을 기준으로 한다. 실제 벽시계 지연 때문에 한 틱의 이동 거리·피해량을 임의로 확대하지 않는다.
- 명령은 검증·순서화하고 한 학생의 뽑기/성장/출정 요청을 같은 상태 버전에서 중복 실행하지 않는다.
- 전투 단위는 `matchId`, `entityId`, `deploymentId`, `ownedHeroInstanceId`, `heroDefinitionId`를 구분한다.
- 행동 단위는 `actionId`, `startTick`, `release/impactTick`, `recoverEndTick`, `cancelTick`, `targetId`, `lockedAim`을 가진다. 현재 타입의 대응 필드를 우선 사용한다.
- 판정·재화·승패는 서버만 확정한다. 렌더링 FPS·애니메이션 프레임 선택이 피해를 결정하지 않는다.
- 여러 피해가 같은 틱에 발생하면 팀 순서 때문에 일방적 선공이 생기지 않도록 현행 동시 정산 계약을 유지·검증한다. 같은 틱 양 넥서스 파괴는 무승부다.
- `Math.random` 호출 순서나 화면의 렌더 순서가 전투 결과에 영향을 주지 않는다. 시험용 결정적 난수와 운영 뽑기의 난수를 분리한다.

## 3. AI의 세 계층

### 3.1 참가자 관리자: AI 학생

퀴즈·재화·보유 영웅·정비·라인 선택을 수행한다. 전투에 출정한 영웅을 직접 움직이지 않는다. 사람과 같은 규칙을 사용한다.

### 3.2 라인 전황: 지역 전술 맥락

진영별·라인별 활성 유닛, 현재 전열, 적 위협, 공략 가능한 구조물, 사용 가능한 공격 자리, 합류 공간을 계산한다. 초기 갱신 1~2Hz, 큰 사건(타워 파괴·교전 급변)은 즉시 무효화할 수 있다. 이는 자동전투 참고 정보이지 학생에게 생기는 새로운 실시간 지휘 권한이 아니다.

### 3.3 개별 영웅/미니언

각자의 주변 상황과 역할에 따라 표적·자리·평타·스킬·짧은 후퇴를 선택한다. 전술 재평가는 기본 5Hz로 분산하고, 이동·충돌·활성 공격·투사체는 모든 고정 틱에서 처리한다. 전체 캐릭터를 매 프레임 동시에 다시 판단시키지 않는다.

## 4. 매 틱 처리 순서

다음은 구현 순서의 의사코드다. 함수 이름은 현재 코드에 맞게 대응한다.

```text
processValidatedCommandsInOrder()
if paused: persistNecessaryCommandsAndReturn()

advanceAuthoritativeTick()
expireStatusesAndReleaseExpiredReservations()
spawnDueWavesAndAlreadyConfirmedDeployments()
buildSpatialIndexAndPerceptionSnapshot()
refreshDirtyLaneContexts()

for unit in deterministicFairOrder:
    if dead: continue
    if spawning: advanceSpawnState(); continue
    if forcedMovement: advanceSweptForcedMove(); continue
    if hardCC: cancelOnlyInterruptibleAction(); continue
    if committedAction: advanceExistingAction(); continue
    if tacticalEvaluationDue:
        updateThreatAndIntent()
        selectOrKeepTargetAndSlot()
        evaluateSkillCandidates()
        chooseExecutableAction()
    advanceMovementOrBasicAttack()

advanceProjectilesAndPersistentEffectsWithSweptCollision()
resolveScheduledImpactsUsingExistingSimultaneousResolution()
resolveDeathsAndReleaseOwnedReservations()
updateStructureProtectionAndWinState()
appendNumberedCombatEvents()
persistCriticalChangesAndPublishAtScheduledCadence()
```

한 틱 안에서도 명령·상태 갱신·충돌·피해 순서가 결정적이어야 한다. 이 순서로 기존 resolver를 무작정 교체하지 말고, 현행 동작과 테스트를 확인하고 필요한 최소 변경만 한다.

## 5. 역할별 행동 상태

기본 상태는 SPAWN, ADVANCE, FORM_UP, APPROACH, BASIC_WINDUP, BASIC_RECOVER, CAST, REPOSITION, RETREAT, SIEGE, DEAD 정도로 구분한다. 실제 타입명이 이미 있으면 그대로 유지한다.

| 역할 | 전진 중 | 교전 중 | 위험 시 | 공성 중 |
|---|---|---|---|---|
| 탱커 | 전열의 열린 자리 | 아군 후열 보호, 앞선 적 접촉, 진입 조건 평가 | 아군이 따라오는 범위에서 짧게 후퇴 | 미니언·아군을 확인하고 선두 |
| 근접 딜러 | 전열 바로 뒤/옆 | 공격 가능한 측면 자리, 지속 접촉 | 접근 불가 표적을 오래 추격하지 않음 | 빈 공격 자리로 접근 |
| 암살형 | 전열 측면 | 실제 접근 가능한 후열에 제한된 진입 | 착지/도주 공간 없는 돌진 억제 | 공성 포기하고 맵 끝 적을 쫓지 않음 |
| 사수 | 전열 뒤 | 유효 사거리에서 공격, 필요할 때만 거리 조절 | 안전한 공간이 있으면 짧은 이동 | 사거리 끝에서 안정적으로 공격 |
| 마법사 | 후열 | 군집·병목·접근 위협에 스킬 | 무리한 근접 진입 금지 | 실제 구조물 적용 계수대로 공격 |
| 지원가 | 아군 근처의 후열 | 회복·보호·정화와 가능한 평타 | 지원 사거리 안의 안전한 자리 | 구조물 앞에서 혼자 선두 금지 |
| 근접 미니언 | 웨이브 앞 | 가까운 유효 적과 전열 형성 | 복잡한 영웅식 도주 금지 | 실제 공격 자리 확보 |
| 원거리 미니언 | 웨이브 뒤 | 사거리 정지·발사 | 막혔을 때 짧은 자리 조절 | 뒤쪽에서 지속 사격 |

## 6. 전열과 이동

### 6.1 길 진행도

윗라인·아랫라인의 polyline과 폭을 사용한다. 전진·후퇴를 전역 x만으로 판단하지 않고 해당 경로의 진행도(s), 중심선에서의 횡오프셋(d)으로 표현한다. 합류 구역은 양 라인 공용 영역으로 명시한다.

출정 때 선택한 라인은 살아 있는 동안 바뀌지 않는다. 중앙 비보행 지역을 잘라 넘어가는 길을 만들지 않는다. 본진 공용 구역에서는 양 라인의 적·아군을 함께 고려하지만, 방어한다고 반대 라인 중앙으로 자동 이사하지 않는다.

### 6.2 지역 전열 추정

가장 앞에 있는 한 명만 전열로 삼지 않는다. 주변의 건강한 근접 유닛·실제 교전 위치·아군 군집을 사용한 중간값/가중 분위수를 활용한다. 혼자 돌진한 암살자가 전열 전체를 끌고 가지 않아야 한다.

원거리와 지원가는 지역 전열 뒤의 역할별 선호 거리를 둔다. 단, 전열이 없다고 영원히 멈추지 않는다. 주변 적이 없으면 다음 공성 목표로 전진하고, 적이 있으면 자기 사거리·체력·아군 접근 시간을 보고 제한적인 교전을 한다.

### 6.3 경로와 국소 회피

이미 구현된 경로 탐색과 공간 해시를 개선한다. 우선순위는 정적 지형/살아 있는 건물 회피→경로 진행→주변 유닛 간격 유지→역할 위치다. 벽을 뚫기 위해 분리 벡터가 지형 충돌을 무시하면 안 된다.

경로 재계산은 목표의 의미 있는 이동, 경로 차단, 목표 파괴, 일정 시간 진행 불가에서만 수행한다. 모든 유닛이 매 50ms마다 A*를 실행하지 않는다. 유닛 반경을 고려한 통로 검사와 끝점 접근 가능성을 검사한다.

아군끼리 작은 겹침은 부드럽게 해소하되 적/구조물 관통이나 오랫동안 같은 점에 겹치는 것을 허용하지 않는다. 충돌 해결의 반복 횟수와 최대 밀림을 제한해 떨림과 연쇄 발사를 막는다. 길이 좁아질 때는 선착순/안정된 우선순위를 사용한다.

### 6.4 이동 실패 복구

이동 명령이 있는데 충분한 시간 동안 진행도가 거의 변하지 않으면 `stuck` 진단을 남긴다. 초기 탐지창은 1.2초 정도를 시험하되, 공격·시전·CC·의도적 대기는 제외한다.

복구 순서: 불필요한 예약 해제→인접 합법 자리 탐색→짧은 후퇴/측면 보정→국소 경로 재탐색→접근 가능한 다른 표적. 장애물을 무시한 순간이동·생존 유닛 삭제·임의 피해로 해결하지 않는다. 스폰도 같은 규칙이며, 스폰 구역에 충분한 수용 공간을 확보한다.

## 7. 표적 선택과 안정성

### 7.1 후보 필터

생존·적군 여부, 같은 라인 또는 공용 구역, 보호된 구조물 제외, 접근 가능한 경로, 유효 감지 거리, 합법 공성 단계부터 검사한다. 점수가 높아도 실제 공격할 수 없는 표적은 제외한다.

현재 위협과 실제 이동 가능한 적을 판단한다. 상대의 미래 정답, 다음 뽑기 결과, 아직 시작하지 않은 스킬이나 난수 결과는 읽지 않는다. 전장에 드러난 시전·투사체·현재 상태를 이용한 위협 예측은 허용한다.

### 7.2 초기 점수식 [제안]

각 항목을 0~1로 정규화하고 같은 스케일에서 비교한다.

```text
score(target) =
  0.22 * reachability
+ 0.18 * attackReadiness
+ 0.18 * threatToNearbyAllies
+ 0.12 * realisticFinishChance
+ 0.12 * roleAffinity
+ 0.10 * localFocusValue
+ 0.08 * objectiveValue
- 0.25 * exposureRisk
- 0.15 * travelCost
- 0.12 * congestionCost
```

가중치는 별도 AI 설정에 두고 재현 시험으로 조정한다. 이 값을 원작 알고리즘이나 최종 밸런스로 표시하지 않는다. 탱커는 후열 위협 제거, 암살자는 안전한 후열 접근, 지원가는 지원 대상과 공격 대상을 별도로 평가한다.

### 7.3 표적 유지

현재 표적이 유효하고 새로운 후보 점수의 우위가 작으면 유지한다. 초기 최소 유지창 0.6~1.0초, 교체 우위 0.12 정도를 시작값으로 시험한다. 표적 사망·경로 단절·위험 급증·명백한 넥서스 마무리 기회는 즉시 재평가한다.

준비 동작을 시작한 공격은 일반적인 점수 변화로 취소하지 않는다. 대상 무효·하드 CC·명시적인 치명 위험 등 계약된 사유만 취소한다. 표적 변경과 방향 변경을 로그로 남겨 초당 반복 횟수를 측정한다.

## 8. 근접 공격 자리와 원거리 자리

### 8.1 근접 슬롯

공격 대상의 충돌 반경과 자기 반경, 사거리를 사용해 접근 가능한 호 위에 슬롯 후보를 만든다. 수용 개수를 모든 대상에 고정 4개처럼 제한하지 않는다. 큰 구조물은 여러 명이 때릴 수 있고 작은 적은 둘레에 맞게 제한된다.

슬롯 비용 = 이동거리 + 지형/건물 충돌 + 다른 아군 예약 + 위험 노출 + 현재 위치 변경량. 슬롯 예약은 짧은 TTL을 가지고 도착·행동 유지 중 갱신한다. 죽음·표적 변경·출정 교체·연결 상태와 무관한 전투 종료 때 해제한다.

빈 자리가 없으면 가까운 다른 적 또는 접근 가능한 대기 자리를 선택한다. 이미 때리는 아군을 밀어내고 같은 자리를 반복 요구하지 않는다. 사거리는 중심 거리가 아닌 충돌체 가장자리 간격을 사용한다.

### 8.2 원거리·마법·지원

사거리의 적당한 안쪽에 들어오면 멈추고 실제 공격을 수행한다. 위협이 없는데 최대 사거리 경계만 쫓아 앞뒤로 흔들리지 않는다. 측면 공간과 후퇴 공간을 별도로 검사한다.

원거리 카이팅은 공격 준비·발사·최소 회수 동작을 끝낸 후 실행한다. 발사 전 무한 취소, 장애물로의 후퇴, 더 위험한 포탑 쪽으로 도망가는 이동은 금지한다. 후퇴할 합법 공간이 없으면 가능한 공격·스킬을 수행하며 끝없이 떨지 않는다.

## 9. 평타·스킬 의사결정

### 9.1 공통 후보 평가

해금·쿨타임·침묵/기절·사거리·필수 대상 수·지형·착지 조건을 통과한 기술만 후보가 된다. 단순히 skill1→skill2→평타 순서로 먼저 준비된 것을 선택하지 않는다.

효용은 유효 피해, 실제로 예방할 위험, 유효 회복, 보호할 아군, 공성 기회, 시전 중 노출, 긴 기술을 소비할 기회비용을 포함한다. 너무 완벽한 조건만 기다리며 평생 스킬을 아끼지 않도록, 가치가 충분하고 기회가 사라질 상황에서는 사용한다.

평타는 스킬이 마땅하지 않은 동안 계속 유지한다. 지원가도 회복할 아군이 없고 안전한 공격이 가능하면 적절히 평타를 사용한다. 마법사가 자기 큰 스킬만 기다리며 아무것도 하지 않으면 실패다.

### 9.2 역할별 발동 조건

- 광역 피해: 현재 또는 시전 뒤 짧은 예측 시간의 군집. 예측은 실제 현재 속도와 공개 움직임만 사용한다. 영웅이 있으면 미니언 다섯 마리보다 언제나 우선한다는 단순 규칙은 피한다.
- 단일 처치: 실제로 접근·명중 가능한 저체력 적. 이미 죽었거나 다른 공격으로 확실히 해결될 적에 모든 기술 낭비를 줄인다.
- 치유: 부족 체력과 곧 닿을 공개된 피해를 함께 고려하되, 미래 피해를 무제한 정확히 아는 AI를 만들지 않는다.
- 보호막: 주변 교전·진행 중인 공격·투사체 등 위협 존재. 실효 없는 중첩과 풀 지속시간 낭비를 줄인다.
- 정화: 현재 해제 가능한 상태가 있는 아군. 자기 기절 중에는 사용할 수 없다는 기존 정책을 유지한다.
- 돌진/도약: 출발/도착/경로, 아군 지원, 착지 후 위험, 충돌체를 확인한다. 스킬에 없는 무적·벽 통과·관통을 추가하지 않는다.
- CC: 상태의 종류와 면역·연속 제한을 확인한다. 이미 제어 중인 적에 무조건 겹치지 않고 다음 위협을 고려한다.

### 9.3 스킬 정의와 표현의 단일 기준

현재 36개 스킬 ID·해금·상태·피해 타입·계수·사거리·쿨타임을 우선 보존한다. 동작과 효용 개선 때문에 변경이 필요하면 `BALANCE_CHANGELOG.md`에 구값/신값/이유/시험을 남긴다.

예: 현재 얼음술사의 빙결 감옥은 `root`로 정의되어 있다. 얼음에 갇혔다는 그림만 보고 `stun`으로 바꾸지 않는다. root는 자발 이동 제한, stun은 행동 제한이라는 구분을 UI·판정·AI 모두에 맞춘다.

단일/선형/관통/부채꼴/원형/직사각형/돌진/도약/지속/연타는 서로 다른 판정 경로를 유지한다. 모든 기술을 큰 원형 범위 피해로 단순화하면 불합격이다.

## 10. 판정·투사체·상태이상

### 10.1 충돌

빠른 투사체·돌진은 이전 위치에서 새 위치까지 swept collision을 사용한다. 틱 사이를 지나간 작은 적을 놓치지 않는다. 관통은 실제 통과 순서·최대 대상 수·대상별 중복 히트 제한을 적용한다.

근접·범위 판정은 선언한 지점과 facing, 크기에 따른다. 시전자 사망 후에도 이미 발사된 독립 projectile은 source snapshot을 보존하며 기존 규칙대로 진행한다. 시전 전 사망했는데 새 projectile이 생기면 안 된다.

### 10.2 상태와 취소

현행 방어력·보호막 상한·피해 감소 상한·연속 CC 제한을 먼저 고정한다. 이동불가/기절/침묵/강제 이동/도발의 영향을 각각 표로 기록한다. 구조물 면역은 모든 스킬에서 동일하게 적용한다.

강제 이동은 화면상 위치만 바꾸지 않고 서버 경로·충돌을 거쳐야 한다. 벽에 밀려 겹친 유닛을 무한히 진동시키지 않는다. 띄우기의 높이는 표현 좌표이며 실제 지면 위치와 충돌 정책은 서버가 정한다.

### 10.3 유효 기여 기록

초과 피해·풀HP 치유·흡수되지 않은 보호막을 모두 점수로 더하지 않는다. 같은 아군 피해 사건에 여러 지원 효과가 겹친 경우 중복 보조 기여를 제한한다. 피해 출처·소유 학생은 시전자 사망이나 교체 이후에도 올바르게 연결한다.

## 11. 타워·넥서스 공성

### 11.1 합법 목표

각 라인 외곽 타워가 살아 있으면 그 라인의 내곽 타워는 보호한다. 어느 한 라인의 두 타워가 파괴되면 수호 타워 접근이 열린다. 수호 타워 2개가 모두 파괴되면 넥서스 공격 가능. 다른 라인 타워가 남아 있다는 이유로 열린 공성을 막지 않는다.

보호된 건물을 경로 장애물로 보는 정책과 피해 면역은 구분한다. 공격할 수 없는 건물에 장시간 평타를 반복하거나 UI에 피해 숫자가 뜨지 않도록 한다.

### 11.2 진입 판단

지역 아군 전열, 타워 현재 대상, 도착할 미니언, 자신의 체력과 방어 기술, 적 수비수, 공성 목표 체력을 사용한다. 적의 미공개 쿨타임 전체를 알고 판단하지 않는다.

탱커는 아군이 뒤따르고 버틸 여지가 있으면 선두가 된다. 원거리·지원가는 이유 없이 혼자 먼저 포탑 사거리 안으로 들어가지 않는다. 미니언이 있을 때 합류하여 공격할 수 있는데도 전원이 사거리 바깥에서 구경하면 실패다.

### 11.3 포탑의 어그로

기존 규칙을 명문화·회귀검사한다. 기본 미니언 우선과 타워 영역에서 아군 영웅을 공격한 적 영웅으로의 어그로 전환, 현재 유효 표적 유지, 사망/이탈 때 재선택을 구분한다. 사거리를 넘긴 대상에게 포탄을 새로 발사하지 않는다. 이미 날아간 포탄의 정책은 기존 정의를 따른다.

탱커와 미니언이 타워 타깃을 매 틱 바꿔 무한히 공격을 취소시키지 못하게 한다. 타깃 전환은 액션과 연결되어야 한다.

### 11.4 마무리 기회

방어자가 적고 합법 공성 대상이 낮은 HP이면 구조물 마무리 가치를 높인다. 반대로 전멸할 위험이 크면 단지 넥서스가 보인다는 이유로 일렬로 자살하지 않는다.

구조물 뒤 먼 적을 쫓다가 포탑/넥서스를 방치하지 않는다. 공격 준비가 시작된 공성 중 사소한 적 이동 때문에 취소하지 않는다. 둘러싼 수호 타워 사이에서 가까운 표적이 계속 바뀌면 target hysteresis와 슬롯 예약을 적용한다.

## 12. 후퇴·추격·교착 방지

### 12.1 후퇴

후퇴는 본진 귀환과 자동 치유를 새로 도입하는 것이 아니다. 위험한 타워 범위·장판·근접 위협에서 **짧게 안전한 자리로 이동**하는 행동이다.

체력만으로 판단하지 않는다. 현재 위협, 아군 지원, 공격해 마무리할 기회, 이동할 안전한 공간을 함께 본다. 탱커가 항상 가장 먼저 도망가고 사제가 앞에서 맞는 결과를 막는다. 후퇴 상태에 최소 유지창과 재평가 조건을 두어 진입/후퇴가 0.2초마다 뒤집히지 않게 한다.

### 12.2 추격

시간·경로거리·전열에서의 이탈·새 위험에 상한을 둔다. 잡을 수 없는 빠른 적을 타워 뒤까지 쫓지 않는다. 현재 역할·스킬로 마무리 가능한 짧은 추격은 허용한다. 아군 전체가 도망가는 한 명을 따라가 빈 타워를 놓치는지 시험한다.

### 12.3 교착 진단

다음 수치를 주기적으로 수집한다.

- 이동 의도와 실제 진행도의 차이.
- 행동 가능하지만 의미 있는 행동이 없는 시간.
- 초당 표적·진입/후퇴 상태 전환 수.
- 타워 주변에서 돌기만 한 시간.
- 아군·적 전열 거리, 포탑에 실제 피해가 들어간 시각.
- 정비 중 봇의 결정 없이 머문 시간.

의도적인 홀드·CC·시전·사망 대기는 결함 시간에서 제외한다. 증상별 재현 시드를 저장한다. “경기가 오래 걸림”을 이유로 타워 HP부터 계속 줄이지 않는다.

## 13. 경기 길이 튜닝

목표는 통상 600~780초의 실제 전투다. 로비·20문제 시작 퀴즈·첫 준비 시간은 경기 시간에 포함하지 않는다.

순서는 **이동 실패 제거 → 제대로 공격하는지 확인 → 사망 후 공성 창 확보 → 구조물/미니언/영웅 수치 조정 → 후반 공성 보조의 완만함**이다. 현행 8배·16배의 후반 배율은 효과와 부작용을 확인하고 줄이거나 매끄럽게 바꿀 후보이지, 조용히 유지·삭제할 고정 규칙이 아니다.

시험은 같은 시드·같은 학습/구매 봇 정책·같은 팀 구성으로 before/after 비교한다. 40개의 완주·미완주를 모두 기록하고 좋은 시드만 골라 통과시키지 않는다. 13분에 HP를 강제로 깎거나 승자를 뽑지 않는다. 15분 시험 관측 상한은 테스트 러너 종료일 뿐 게임 종료 규칙이 아니다.

팀 규모 30/20/10과 극단 조합도 시험한다. 30명 균형 조건의 목표를 작은 방에 무조건 적용하지 말고 별도 분포를 보고한다. 라인에 학생이 몰린 상황을 강제 재배치로 숨기지 않는다.

## 14. AI 학생

### 14.1 로비

개별 추가/제거, 팀 지정/이동, 기초·표준·숙련 프로필, 균형/성장/수집 성향, 10·20·30명까지 채우기. 호스트가 학생으로 시험 중이면 그 학생을 포함해 총원을 센다. 로비에서만 변경하고 전투 중 임의 봇 추가로 경제 균형을 바꾸지 않는다.

### 14.2 공정성

현행 학습 확률·응답 시간은 유지한다. AI도 20문제·10문제·30초 쿨·가격·뽑기 확률·성장·사망 대기·수동 출정 명령 경로를 사용한다. 고난도 봇에게 추가 골드·공격력·회피 확률·즉시 부활을 주지 않는다. 동일 영웅·성장 상태의 전투 AI는 사람과 같다.

AI의 퀴즈 답 선택이 시뮬레이션 정책인 것은 표시하되, 채점·보상 원장을 건너뛰지 않는다. 독립 클라이언트 30개 시험을 서버 내부 AI 30명으로 대체하지 않는다.

### 14.3 정비 정책

체크 순서: 현재 거래 완료→사용 가능한 영웅 확인→부족한 역할과 성장 효용 평가→예산 내 구매/성장→선택 라인→대기 충족→출정 명령. 예비 영웅의 낮은 레벨과 기존 주력의 성장 손실을 함께 판단한다.

라인 점수는 활성 아군 수의 불균형, 역할 부족, 열린 공성 목표, 본진 위험을 사용한다. 양 라인으로 완전히 균등할 필요는 없지만 모두 같은 순간 같은 라인으로 바꾸는 동기화를 피한다. 플레이어별 안정된 결정 지연과 비용 차이를 둔다.

구매 실패·돈 부족·창고 가득 참·쿨타임에는 유효한 다음 행동으로 넘어간다. 무효 명령 반복과 끝없는 뽑기를 막는다. 정비 중 퀴즈를 시작한 봇은 일정한 정책으로 끝내거나 이어 풀기를 보존하고 출정하며, 대기시간 내내 매 틱 구매하지 않는다.

## 15. 엔진 개발자 진단 도구

시험 모드에 다음 읽기 전용 오버레이를 제공한다: 충돌체, 현재 표적, 예약 슬롯, 경로, 감지/공격 범위, 상태, 선택 이유, 스킬 후보 점수, 지역 전열, 구조물 보호 상태, 틱 비용. 운영 학생 UI에서는 노출하지 않는다.

`DecisionTrace`는 중요 상태 변화에서만 기록하고 프레임마다 문자열을 만들지 않는다. 로그에는 matchId·tick·entityId·reasonCode·선택/대안 점수·주변 요약을 담는다. 개인정보·세션 토큰·문제 정답은 로그에 남기지 않는다.

핵심 비교 장면: 1:1 근접, 5:5 혼합, 15:15 본진, 사수에게 접근하는 전사, 암살자 진입과 보호, 사제 위기 치료, 타워에 들어가는 미니언과 영웅, 넥서스 마무리. 각 장면은 고정 시드와 동일 상태에서 재현 가능해야 한다.
