# 02. 아트·애니메이션·이펙트·UI 제작 명세

## 1. 아트의 성공 기준

목표는 팀파이트 매니저 2를 연상시키는 간결하고 명쾌한 픽셀 전투이되, **Class Clash의 오리지널 캐릭터와 화면**이다. 사용자가 제공한 예시는 얼굴·머리·몸 비율, 의상 덩어리, 읽기 쉬운 자세를 판단하는 기준으로 삼는다. 원작의 그림 파일을 추출하거나 그대로 추적하지 않는다. 재사용하는 에셋은 수정·배포 권한과 출처를 실제로 확인한다.

다음 문제를 이번 작업에서 없앤다.

- 직업마다 같은 몸통에 무기와 색만 바뀌는 모습.
- 얼굴이 빈 마스크처럼 보이거나 눈·입의 크기가 방향마다 달라지는 모습.
- 관절을 회전시킨 것만으로 팔·다리가 늘어나거나 활과 손이 떨어지는 모습.
- 머리·후드·갑옷·손·무기가 한 덩어리로 섞여 읽히지 않는 모습.
- 비슷한 프레임을 수백 장 만든 뒤 “애니메이션 완성”이라고 판정하는 방식.
- 공격하는 척하지만 실제 타격 순간과 모션이 다른 모습.

코드 자체가 저품질의 원인은 아니다. 코드로 아틀라스 패킹, 팔레트 검증, 프레임 재생, 반복 가능한 이펙트를 처리하는 것은 적절하다. 문제는 **미적 검수 없이 단순 도형과 동일한 관절 변환으로 모든 인체·얼굴·포즈를 대체하는 제작 방식**이다.

## 2. 자산 원본과 제작 파이프라인

### 2.1 권장 구조

```text
assets/art-source/
  heroes/<heroId>/        # 원본 프레임, 편집 파일, 팔레트, 메타데이터
  minions/
  structures/
  terrain/
  effects/
  ui/
  licenses/
public/assets/v2/
  atlas/                 # 빌드 파생물
  manifests/
scripts/
  pack-art.*
  validate-art.*
docs/art/
  ART_STYLE_GUIDE.md
  ASSET_PROVENANCE.csv
  VISUAL_REVIEW.md
```

경로는 현행 코드에 맞춰 조정할 수 있다. **원본과 생성물의 분리, 버전 구분, 빌드가 원본에 쓰지 않는 원칙**은 유지한다. 기존 `public/assets/heroes/`를 쓰더라도 manifest와 해시로 구버전 혼입을 방지한다.

### 2.2 아틀라스 로더 변경

현재 원격 렌더러는 영웅당 288프레임·64×64 셀과 고정 애니메이션 구간을 코드에 가정한다. 새 자산도 반드시 이 양식을 맞추기 위해 빈 프레임을 채우지 않는다.

manifest가 아래를 제공하도록 한다.

- heroId, assetVersion, sourceHash, atlas URI, 프레임 사각형.
- 프레임별 발 기준 pivot, 필요하면 trim 이전의 원본 크기.
- 방향과 동작별 프레임 목록, 누적 시간 또는 phase 구간.
- 발사 위치·손 위치·무기 끝 위치 등의 socket.
- windup, release, recover, cancel 전환 메타데이터.
- 표시용 bounds와 충돌 radius의 분리.

프레임 수, 아틀라스 크기, 방향 수를 코드 안의 `i<288` 루프로 단정하지 않는다. 자산 누락은 오류 화면과 재시도·진단으로 표시하며, 영웅을 투명하게 숨기거나 이모지로 교체하고 PASS하지 않는다.

같은 텍스처를 여러 화면에서 쓰면 공유 참조를 관리한다. 화면 종료 때 해당 화면의 Sprite·구독·타이머만 정리하고 공유 base texture를 중복 파기하지 않는다.

## 3. 캐릭터 기본 디자인

### 3.1 비율과 해상도

24×32, 32×32, 8방향 288프레임 같은 과거 숫자를 미적 목표보다 우선하지 않는다. **최신 개선본의 비율을 먼저 확인**하고, 일반 체형은 대략 28~40px 폭·36~52px 높이의 몸체 범위에서 실제 화면을 비교한다. 이는 제작 비교 범위이지 필수 고정 사이즈가 아니다. 큰 탱커·전설은 구별되는 큰 체형을 허용하되 충돌체를 자의적으로 키우지 않는다.

기본 포즈는 서 있을 때부터 균형이 있어야 한다. 머리·목·어깨·골반·발 위치를 캐릭터별 설계표로 고정한다. 모든 직업을 같은 키와 어깨 폭으로 만들지 않는다. 경장 궁수, 갑옷 성전사, 로브 화염술사는 얼굴·머리 표현의 문법은 같고 몸의 윤곽은 달라야 한다.

### 3.2 얼굴과 픽셀 규칙

- 작은 얼굴에서는 눈·머리카락·턱과 얼굴 방향이 먼저 읽혀야 한다. 불필요하게 큰 입·동공·코 구멍을 넣지 않는다.
- 정면·측면·후면의 머리 크기를 유지하고 후면에 앞얼굴이 남지 않도록 한다.
- 외곽선은 배경과 분리될 정도로 분명하되, 모든 내부 부위를 두꺼운 검정선으로 나누지 않는다. 색상 외곽선과 제한된 어두운 선은 모두 허용한다.
- 1px 눈·금속 반짝임 등 의미 있는 단일 픽셀은 허용한다. 무작위 노이즈와 필요 없는 디더링을 금지하는 것이지, 단일 픽셀을 일괄 금지하는 것이 아니다.
- 명암은 같은 광원 기준의 2~3단계 덩어리를 우선한다. 피부·의상·무기 재질을 구분한다.
- 팀 구분을 위해 캐릭터 전체를 파랑/빨강으로 덮지 않는다. 고유 팔레트+발밑 링+HP 바+장비의 작은 팀 표식을 사용한다.
- 같은 영웅의 초상화·창고 카드·전장 스프라이트가 서로 다른 캐릭터가 되지 않는다.

### 3.3 캐릭터별 금지 사항

성전사는 방패·갑옷·몸이 따로 떠다니면 실패다. 궁수는 활을 쥔 손과 시위를 당긴 손이 구분되어야 한다. 화염술사는 모자와 로브만 움직이는 인형이 아니라 몸통·팔·지팡이가 연결된 시전 동작이어야 한다.

수도승·사제·음유시인은 지원 방식의 손동작과 소품을 구분한다. 전설은 무작정 커다란 광원이나 날개로 화면을 덮지 않고 독특한 실루엣과 기술 구조로 차별화한다.

## 4. 방향·좌표·레이어

월드 이동은 연속적인 2D이며, 영웅의 방향 표현은 8방향을 기준으로 유지한다. 8장을 모두 별도 그림으로 만들지 않아도 되지만, 좌우 대칭은 장비 위치와 손잡이·등 장비·후드 구조가 일관될 때만 사용한다. 비대칭 장비는 전후 레이어 또는 전용 프레임으로 해결한다.

발 pivot은 모든 방향·동작에서 일정한 의미를 가진다. 점프는 월드 발 좌표와 시각적 높이를 분리한다. 쓰러진 시체의 피벗도 임의로 원점으로 이동하지 않는다. 장비의 회전 중심이 손에서 벗어나지 않도록 socket을 검증한다.

출력 좌표는 마지막 단계에서 필요에 따라 픽셀 스냅하고, 서버 좌표·충돌체·속도를 반올림하지 않는다. nearest-neighbor를 기본으로 하되 임의 뷰포트에 전체 지도를 맞추는 축소가 항상 정수 배율일 수는 없다. **전체맵 보존을 우선**하며 1366×768·1920×1080 실제 캡처에서 가장자리 떨림과 얼굴 소실을 검사한다. 모든 화면에서 정수 확대를 강제해 지도를 잘라내지 않는다.

기본 레이어: 지면→지면 예고/장판→발 그림자→유닛/구조물(y 정렬)→비행 투사체/상체 효과→체력·상태 표시→HUD. 중요한 장판이 건물 뒤에 완전히 사라지지 않도록 경계선 레이어를 별도로 둘 수 있다. 거대한 이펙트를 항상 맨 앞에 그려 전장을 가리지 않는다.

## 5. 애니메이션 제작 규격

프레임 수는 다음 범위를 **시작점**으로 삼고, 원본 아트와 동작에 맞춰 조절한다.

| 동작 | 초기 범위 | 반드시 읽혀야 할 내용 |
|---|---:|---|
| idle | 2~4 | 무기 무게·호흡. 캐릭터 전체가 젤리처럼 늘어나지 않음 |
| walk | 4~6 | 교차하는 발, 무게중심, 장비의 작은 지연 |
| basic | 4~7 | 준비·실제 타격/발사·회수 |
| skill 1 | 5~9 | 영웅의 반복 역할이 보이는 고유 동작 |
| skill 2 | 6~12 | 전황을 바꾸는 큰 포즈와 명확한 끝 |
| hurt | 1~3 | 맞은 방향·반응. 평타마다 긴 경직을 추가하지 않음 |
| death | 4~7 | 균형 상실→쓰러짐→정지 |
| spawn | 2~4 | 본진에 등장, 전투 흐름을 방해하지 않는 간결함 |

### 5.1 모션과 판정의 연결

서버 액션을 `startTick → windupEnd/releaseTick → active intervals → recoverEndTick`으로 해석한다. 렌더러는 이 타임라인에 맞춰 프레임을 선택한다. GIF의 고정 FPS가 서버 판정을 결정하지 않는다.

- 근접 공격: 손·무기 궤적이 적을 향해 뻗는 시점과 서버 hit tick을 맞춘다.
- 원거리: release 시점에 실제 projectileId 생성, hit는 비행·충돌 결과다. release 때 피해 숫자를 먼저 띄우지 않는다.
- 연타: 각 서버 hit index와 애니메이션의 각 주먹/베기 대응. 한 타격 효과를 여러 번 중복 재생하지 않는다.
- 시전 중단: cancel tick 이후의 발사/착지 효과를 재생하지 않는다. 이미 생성된 독립 투사체·장판은 기존 규칙대로 유지한다.
- 공격 속도 변화: 서버 타임라인 길이에 맞춰 구간을 조절하고 중요한 release 포즈를 건너뛰지 않는다.
- 대기·이동만 부드럽게 보간한다. 공격 취소를 숨기기 위해 이미 끝난 공격을 다시 이어붙이지 않는다.

### 5.2 궁수 필수 검수 장면

활을 든 팔은 표적 방향으로 뻗고, 반대 손은 시위를 얼굴 근처로 당긴다. 당김 때 상체가 약간 열리고, 발사 순간 손과 시위의 관계가 바뀐다. 화살이 socket에서 생성되어 목표로 이동하고 팔은 회수된다. 정면·측면·대각선에서 활이 얼굴이나 몸을 관통하면 실패다. 연출을 위해 모든 화살을 유도탄으로 바꾸지 않는다.

### 5.3 성전사·화염술사 필수 검수 장면

성전사는 무기 공격과 방패 강타를 다른 궤적으로 표현한다. 성역 방패는 아군 개별 보호막이 실제 부여된 대상에만 생긴다. 화염술사는 평타 화염구, 폭발 스킬, 지속 장벽의 모양과 시간 구조가 다르다. 지팡이를 든 팔의 위치와 불꽃 발사점이 맞아야 한다.

## 6. 미니언 리워크

근접·원거리 각 1종을 기본으로 두 팀 변형을 제작한다. 기존 수치와 수량을 보존한다. 기본 키는 영웅의 약 55~70% 수준을 **비교용 출발점**으로 삼고, 실제 전체맵에서 역할이 읽히는 크기로 결정한다.

근접은 작은 갑옷·검/방패, 원거리는 더 가벼운 형태·활/투사 무기를 사용한다. 영웅의 복잡한 장식과 경쟁하지 않는다. 진영 색은 작은 주요 면과 깃발·바닥 표식으로 표시한다.

미니언에도 idle/walk/attack/hurt/death가 있어야 한다. 걷기 프레임 두 개를 공격처럼 재사용하거나, 발이 정지한 채 미끄러지는 것을 금지한다. 실제 공격 준비·발사·적중이 연결되어야 한다. 개별 애니메이션 위상은 고정 ID 기반 작은 차이를 줄 수 있으나 서버 공격 주기와 피해 시각을 바꾸지 않는다.

웨이브 등장 시 근접 3기를 앞에, 원거리 4기를 뒤에 배치한다. 교전 중에는 자연스럽게 흐트러지되 아군끼리 장기 교착되지 않는다. 출현 수를 줄여 성능을 맞추지 않는다.

## 7. 지도·건물

기존 충돌·동선 위에 새 지형·길·가장자리·나무·돌·본진 바닥을 입힌다. 장식이 길을 좁혀 보이거나 통과 가능한 공간을 벽처럼 보이게 하지 않는다. 변경된 walk mask는 실제 nav/충돌과 비교한다.

- 길: 낮은 시각적 잡음, 전열과 투사체를 구분하기 쉬운 명도.
- 중앙 지형: 두 라인을 분리하는 배경 역할. 자동으로 새로운 이동 경로가 되지 않음.
- 외곽/내곽 타워: 실루엣과 장식의 차이로 단계가 읽힘.
- 수호 타워: 더 강한 장갑·핵심 광원·발사 동작. 두 개가 겹쳐 하나처럼 보이지 않음.
- 넥서스: 최종 목표임을 분명하게 표시, 체력 상태와 보호 상태를 구별.
- 건물 상태: 정상→손상→파괴. 파괴 잔해의 충돌은 기존 게임 정책과 일치. 그림만 길이 열린 것처럼 보이게 하지 않음.

구조물 공격은 포구/보석의 작은 준비 광원→실제 포탄→적중. 판정 전의 예고와 결과를 구별한다. 타워 사거리 원은 디버그 또는 선택 시 표시할 수 있으나 전투 중 항상 커다랗게 덮지 않는다.

## 8. 이펙트: 기술의 구조가 보여야 한다

### 8.1 전투 효과의 세 등급

**A. 필수 의미 효과:** 발사체, 유효 장판의 영역, 위험 예고, 핵심 타격, 보호막, 속박/기절 상태, 치유 수신, 사망, 구조물 파괴. 호스트 전체맵에서 모두 표현한다.

**B. 식별 보조 효과:** 영웅별 궤적, 적중 스파크, 작은 상태 아이콘, 고유 룬. 개체가 많아도 표현 의미를 유지한다.

**C. 장식 효과:** 추가 잔상, 작은 불티·먼지, 주변 반짝임, 중복 피해 숫자. 성능 모드에서는 이것부터 줄인다.

“A를 모두 보인다”는 것은 프레임마다 모든 장식 입자를 무한히 생성한다는 뜻이 아니다. 각 전투 사건에 대응하는 필수 시각 신호를 최소 1회·유효 기간 동안 정확하게 보여준다는 뜻이다.

### 8.2 기술 모양의 문법

| 분류 | 고유 표현 | 금지 |
|---|---|---|
| 검·도끼 | 무기 궤적에 맞는 짧은 호, 접촉 스파크 | 모든 공격의 거대한 원형 폭발 |
| 주먹·봉 | 접촉점 중심 충격, 리듬이 다른 연타 | 공격마다 화면 전체 흔들림 |
| 화살·볼트 | 얇은 선형 투사체·발사 반동·착탄 | 사거리와 다른 위치에서 피격 |
| 불 | 둥근 팽창→짧은 잔불, 지속 장벽은 지면 영역 | 모든 적을 가리는 흰 화면 |
| 얼음 | 각진 파편·서리·상태 구속 | root를 stun처럼 모든 행동 정지로 표시 |
| 번개 | 실제 연결된 대상 사이 분기선·짧은 발광 | 공격하지 않은 대상까지 연결 |
| 치유 | 대상에게 수렴/상승하는 빛, 실제 회복 기록 | 풀HP 대상의 무의미한 치료 폭발 |
| 보호막 | 몸을 감싸는 간결한 경계·흡수 반응 | 시전자 주변 원 하나로 모든 대상 대체 |
| 룬 | 표식의 누적과 연결·공명 순서 | 상태와 무관한 랜덤 기호 |
| 충격파 | 실제 판정 모양과 같은 지면 전파 | 시각 범위 밖에 피해 |

### 8.3 시야와 색

효과 중심은 짧게 강하고 외곽은 읽을 수 있게 남긴다. 대규모 장판은 내부 불투명도를 낮추고 경계를 분명히 한다. 적/아군 판별에 색뿐 아니라 경계 패턴·아이콘·방향성을 보조한다. 영웅과 팀을 구분하기 위해 불을 파란색으로 바꾸는 식의 무조건 색 교체는 하지 않는다.

지면 피해 장판은 얼굴보다 아래, 치유/보호막은 대상과의 관계가 보이는 층에 둔다. 이름과 HP 바가 장판을 완전히 덮지 않게 한다. 호스트에는 모든 피해 숫자를 요구하지 않으며, 학생은 자기 영웅과 근접 교전에 집중한 수치를 볼 수 있다.

### 8.4 타격감과 소리

서버 시간을 멈추는 전역 hit stop은 금지한다. 필요한 강타에 한해 시각 포즈 홀드·짧은 무기 반동·국소 충격 효과를 사용한다. 넉백은 실제 스킬 규칙에 있을 때만 발생한다. 모든 평타에 과한 넉백·추가 경직을 넣지 않는다.

오디오는 검·둔기·주먹·화살·화염·얼음·치유·타워를 구분한다. 동시 재생 수를 제한하고 동일 소리를 합치되, 시각적 피드백까지 삭제하지 않는다. 호스트는 전장 믹스, 학생은 자기 영웅 주변 중심으로 재생한다. 퀴즈 화면에서는 전투 소리를 낮추고 문항 피드백을 읽기 쉽게 한다. 음소거·음량 설정과 브라우저 첫 사용자 입력 후 활성화를 제공한다.

## 9. 호스트 UI

### 9.1 레이아웃

상단 스코어판, 가운데 전체 전장, 하단 또는 접이식 외곽 정보 영역을 둔다. **전장 자체에는 양 넥서스·2라인·12타워가 항상 모두 들어온다.** 자동 확대·관전 대상 추적·킬 장면으로 카메라 이동은 금지한다.

상단: 양팀 이름/색·처치 수·넥서스 HP·남은 일반/수호 타워·경기 시간. 승리 판단은 넥서스라는 사실을 UI에서도 분명히 한다. 수호 타워와 일반 타워를 같은 숫자 하나로만 표시하지 않는다.

기본 HUD는 큰 맵을 확보한다. 상세 참가자 30명의 긴 통계표를 기본 화면에서 펼쳐 전장을 줄이지 않는다. 펼쳐도 맵을 가리지 않게 별도 패널·드로어 크기와 캔버스를 재계산한다.

### 9.2 상태와 교사 제어

방 코드·QR은 로비에서 크게, 전투 중에는 필요할 때 간단히 열 수 있다. 일시정지·재개·종료는 명확히 구분하고 종료에는 확인을 둔다. AI 참가자 수·연결 끊김·미준비 인원·진행 단계가 보인다.

영웅 호버/클릭은 읽기 전용: 학생 이름, 영웅, 등급, 레벨, HP, 두 스킬 준비 상태, 해당 경기 실제 기록. 전투 지시 명령을 보내지 않는다. 호스트도 전투 도중 특정 학생을 강화하거나 표적을 지정하는 새 권한을 갖지 않는다.

## 10. 학생 UI

### 10.1 생존/관전

자기 영웅 추적 카메라는 진행 방향 앞쪽을 조금 더 보여주고, 짧은 방향 전환에는 급히 흔들리지 않는다. 안전한 줌 범위를 제공해 자기 영웅과 주변 전열·적·포탑을 함께 볼 수 있다. 전장 모서리에서는 카메라를 클램프한다.

고정 정보: 영웅 초상·이름·역할·등급·레벨·HP·두 스킬 아이콘·재화·퀴즈 가능/진행/남은 쿨타임. 스킬 아이콘은 **읽기 전용**이다. 클릭하면 직접 스킬 발동되는 버튼처럼 보이게 하지 않는다.

퀴즈 창은 전투 캔버스와 동시에 유지하며 화면 크기에 따라 측면 또는 하단에 놓는다. 휴대폰 세로에서는 전투가 작아져도 문제 본문·보기·제출 버튼의 가독성을 우선한다. DOM 입력을 Canvas 전체 리렌더와 강하게 묶지 않는다.

### 10.2 사망 전환

사망 알림은 작고 분명하게 표시한다. 문제를 풀던 학생에게 정비 모달을 강제로 덮어 선택 중인 보기를 없애지 않는다. '정비하기'로 즉시 이동할 수 있고, 이어 풀던 퀴즈로 돌아갈 수 있다. 영웅이 죽은 동안 화면은 사망 주변의 읽기 전용 전황 또는 정비 배경을 보여주며 다른 영웅으로 자동 조종 대상을 바꾸지 않는다.

### 10.3 정비 화면

상단: 현재 재화·출정 가능까지 남은 시간·선택 영웅. 가운데: 동일 크기의 영웅 카드와 역할/등급 필터. 카드에는 이름·초상·Lv·강화·두 스킬 해금 상태를 compact하게 표시한다. 선택 카드만 세부 설명·업그레이드 비용을 보여준다.

하단의 흐름은 '영웅 선택 → 필요 시 성장/뽑기 → 위/아래 라인 → 출정'이다. 라인별 아군 **활성 영웅 수와 역할 구성**을 표시하되 학생을 강제로 이동시키지 않는다. 출정 불가 사유(대기·선택 없음·통신 중)를 버튼 옆에 문장으로 표시한다.

뽑기 창은 비용·등급 확률·대상 풀·현재 재화를 결제 전에 보인다. 추첨 결과는 서버 확정 후 보여주고, 가짜 슬롯 릴 때문에 추가 과금되거나 진행이 막히지 않게 한다. 중복 인스턴스는 성장 차이를 쉽게 구분한다.

### 10.4 읽기·접근성

한국어 본문과 퀴즈는 읽기 좋은 UI 폰트를 사용한다. 픽셀 글꼴을 모든 한글에 강제하지 않는다. 핵심 버튼 터치 영역은 약 44 CSS px 이상을 기준으로 검증한다. 키보드 탐색·초점 표시·실수로 이중 제출 방지, 색 구분 보조, 음소거·효과 감소를 제공한다. 화면이 좁아도 돈·출정 버튼·선택 결과가 잘리지 않는다.

## 11. 로비·시상식·결과 UI

로비는 양팀 카드 열, 사람/AI 구분, 연결/준비 상태, 퀴즈 설정, 10/20/30명 채우기와 개별 AI 추가·제거를 제공한다. 정원 초과·게임 중 참가 제한 등 기존 정책을 명확하게 안내한다.

시상식은 실제 승리팀·넥서스 결과→개인 활약→학습 성과→재경기 순서로 구성한다. 기존 시상 항목을 먼저 보존하며 지원·탱커가 단순 피해량 때문에 항상 밀리지 않게 **실제 유효 치유/흡수/CC/공성 기여**를 따로 보여준다. 기여를 중복 집계하여 지원가가 항상 MVP가 되는 것도 막는다. 검증되지 않은 종합 점수 가중치를 새로 꾸미지 않는다.
