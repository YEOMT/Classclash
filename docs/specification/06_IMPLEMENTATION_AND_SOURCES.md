# 클래스 클래시 구현 순서와 참고 기준

## 1 Codex가 끝내야 하는 작업

‘한 번에 플레이 가능’은 메뉴와 전투가 따로 놀지 않는 첫 버전을 뜻한다. 내부 개발은 여러 단계로 나눠도 좋지만 최종 제출은 방 생성부터 재경기까지 연결된 게임이어야 한다. 아래 단계 하나만 마치고 후속 작업을 제안하는 것으로 요청을 완료 처리하지 않는다.

| 단계 | 만들 내용 | 다음으로 넘어갈 실제 확인 |
| --- | --- | --- |
| A 저장소와 실행 | 기존 파일·AGENTS.md 확인, 패키지 구성, 실행 명령, 공용 schema, 방 생성·참가 | 깨끗한 설치에서 호스트 1개와 학생 2개가 같은 로비를 봄 |
| B 수업 흐름 | 시작 20문제, 준비, 카운트다운, 개인 지갑, 10문제/30초, 정비·시상·재경기 | 가짜 전투용 종료를 이용한 임시 통합 시험 후 실제 전투 연결 준비 |
| C 자동 전투 기반 | 정확한 2라인 지형·12타워·2넥서스·미니언28·공격/이동/공성 | 미니언 단독 경기에서 양쪽 라인과 타워 해금·넥서스 종료가 실제 작동 |
| D 대표 6명 액션 | 성전사·격투가·야만인·궁수·화염술사·사제의 실제 도트·타격·지원 | 근접/원거리/광역/지원의 동작 차이를 전체맵과 학생 카메라에서 확인 |
| E 18명 전원 | 나머지 12명과 전체36스킬, 역할·등급 풀, 성장·강화·쿨타임 | 모든 영웅과 스킬을 전투 테스트 장면에서 실제로 사용 |
| F AI 학생 | 로비 추가·제거·팀·프로필, 퀴즈·정비·출정 관리자 | 사람0+AI30, 사람1+AI29가 기본 흐름을 끝까지 수행 |
| G 연결과 복구 | 명령 중복 방지, 체크포인트, 재접속, 다중 탭, 느린 연결 | 퀴즈·뽑기·출정 도중 연결을 끊어도 중복 자산·중복 영웅 없음 |
| H 최종 검수 | 150 기본 인수 조건·전투50·영웅19·화면·부하·경기 길이 | 실제 결과 보고, 알려진 실패 분리, 3회 재경기, 설치·빌드 재현 |

D의 6명은 애니메이션 기반을 확인하는 내부 순서다. 최종 영웅 수를 6명으로 줄이는 허가가 아니다. B의 임시 강제 종료·가짜 전투 상태는 테스트 전용 모듈로 제한하고 최종 수업 모드에서는 정상 넥서스 파괴만 결과를 만든다.

## 2 모듈 구현 계약

### 2.1 전투 엔진

정적 영웅 정의, 계산된 성장 스탯, 소유 인스턴스, 한 번의 출정 전투 유닛을 별도 자료형으로 만든다. 자료를 복사할 때 두 학생이 같은 영웅 정의 객체의 hp를 함께 수정하는 오류가 생기지 않게 한다. 구조물·미니언·영웅은 서로 필요한 속성만 갖고 공용 damage/status 파이프라인을 사용한다.

공격과 스킬은 데이터 주도 규격을 사용하되 타입별 실행기를 명시적으로 둔다. 단일 근접, 직선 관통, 투사체 폭발, 위치 장판, 다단히트, 돌진, 반격, 치유, 보호막, 버프, 정화, 표식/폭발이 필요하다. 모든 스킬을 공통 ‘가까운 적에게 원형 피해’ 실행기로 바꾸지 않는다.

경로와 진형은 지도 데이터에서 나오며 뿔·검·이펙트 크기를 충돌 반경으로 착각하지 않는다. 버그 수정 시 동일 고정 시드의 전투 장면을 재현하고 원인이 해결됐는지 확인한다. 전투 엔진을 크게 바꾸어 해결할 때 다른 역할의 이동·지원·공성을 함께 회귀 검사한다.

### 2.2 아트 생산

18명마다 완전히 별개 엔진을 만들 필요는 없다. 도트 팔레트·신체 부위·손잡이·무기 피벗·상태 포즈를 공유 도구로 제작할 수 있다. 다만 최종 실루엣과 타격 자세, 무기와 스킬의 모양은 영웅마다 달라야 한다. 생성 스크립트로 도트를 만들더라도 같은 사각 몸통의 색만 바꾸는 대체물은 안 된다.

아틀라스는 본체·무기/동작·발사체·지면 효과·피격 효과·UI 초상 등 실제 batching과 유지보수가 쉬운 단위로 묶는다. 파일이 없으면 영웅을 조용히 숨기지 말고 개발 빌드에서 asset error를 내고 CI에서 존재를 검증한다. 실행 중 원격 이미지 검색이나 동적 AI 이미지 생성을 하지 않는다.

시각 검수에는 정지 스크린샷만으로 충분하지 않다. 최소 성전사 방패 강타, 격투가 연타, 야만인 큰 베기, 궁수 발사·착탄, 화염 장판, 사제 치유, 룬 연결 폭발, 고대의 존재 균열, 수호령 결계를 실제 시간축에서 녹화해 확인한다. 호스트 전장 축소 상태에서도 누구의 행동인지 읽혀야 한다.

### 2.3 교육 UI

화면은 한국어가 기본이다. 퀴즈 버튼에는 한 번에 10문제와 다음 가능 시각이 명확해야 한다. 정비 화면에서 비용을 보기 전에 눌러 돈을 잃게 하지 않는다. 일반·고급·전설을 색만으로 구분하지 않고 텍스트/아이콘을 함께 사용한다. 체력·팀·잠긴 타워·스킬 해금 상태도 색 외 표식을 갖는다.

학생 이름과 긴 문제는 레이아웃을 밀어내지 않고 줄바꿈 또는 명시적 말줄임을 한다. 버튼 터치 영역은 최소 44×44 CSS px를 기본으로 한다. 사용자의 키보드·터치 포커스를 전투 이벤트가 강탈하지 않는다. 키보드로 보기 선택과 제출, 창고 선택, 출정까지 가능해야 한다.

## 3 중요한 초기 결정표

다음은 사용자 확정 요구를 구현 가능한 규칙으로 완결하기 위해 추가한 결정이다. 최초 승인된 기존 게임 규칙이라고 주장하지 않는다. Codex가 다른 선택으로 바꾸려면 구체적 이유와 영향을 CHANGELOG에 적는다.

| 결정 | 선택 | 이유/변경할 때 지킬 것 |
| --- | --- | --- |
| 자원 단위 | 정답 1개=1원 | 2원/10원 뽑기와 단위 일치 |
| 0정답 참가 | 무료 일반 영웅 1회 선택 | 참가 불능 방지, 무료 골드 반복 지급 금지 |
| 일반/고급 나머지 확률 | 80/20/0 및 30/60/10 | 전설10% 사용자 요구 보존, 시험 후 고급 가치 조정 가능 |
| 역할별 고급 풀 | 전체 및 탱커·근접·마법 | 전설 없는 역할에 가짜10%를 표시하지 않음 |
| 중복 영웅 | 독립 인스턴스 | 창고·개별 성장 원칙을 단순하고 명확하게 적용 |
| 레벨5/스킬2 | Lv2·Lv5 해금 | 빠른 첫 선택과 후반 완성 구분 |
| 강화 | 위력/생명 합계3회 | 무한 수치 성장 방지 |
| 사망 대기 | 5초 출정 잠금, 이후 수동 | 정비 판단 보장, 자동 재출정 없음 |
| 첫 미니언과 주기 | t0, 이후20초 | 사용자 첫스폰 요구와 웨이브 리듬 |
| 기본 팀 제한 | 팀당15 | 30명 두 팀 정원, 14:13 가능 |
| 수호 타워/넥서스 | 한 라인 개방→수호2→넥서스 | 라인 선택에 실제 전략 가치 |

| 동시 넥서스 파괴 | 같은 틱이면 무승부 | 배열 처리 순서로 승자를 만들지 않음 |
| 초기 퀴즈·준비 제한 | 기본 없음, 교사 제어 | 학생의 학습 속도 차이 대응 |
| 30인 기준 | 사람+봇 합계, 호스트 제외 | 시험과 교실 정원 일치 |
| 실제 서버 | Node 권위 + WebSocket | 호스트 탭 중단에 전투가 멈추지 않게 함 |

지도 초안의 일반 타워는 최종 명세에서 A 내곽 x360·외곽 x520, B 외곽 x1016·내곽 x1176으로 둔다. 일반 타워 표면 사거리는180이다. 초기 도식의 x440/600/936/1096와 사거리220 조합은 중앙 첫 접전을 양쪽 타워가 동시에 사격하는 배치를 만들어 교정했다. 최종 구현은 02와 balance.defaults.json의 정합한 좌표를 따른다. 기존 두 라인 도식 HTML은 이 명세를 대신하는 실제 맵 데이터가 아니다.

## 4 검증 결과 작성 규격

TEST_REPORT에는 각 인수 ID의 PASS / FAIL / NOT_RUN을 기록한다. ‘정적 확인’, ‘순수 엔진 시험’, ‘실제 서버 통합’, ‘브라우저 E2E’, ‘실제 사람의 시각 검토’, ‘실제 학교 기기’ 중 어떤 방식인지 표시한다. 계획한 테스트의 개수와 실제 통과한 개수를 섞지 않는다.

필수 결과 항목:

1. 실행 명령, 커밋 SHA, Node·브라우저·OS 버전, 측정 하드웨어.
2. 18명/36스킬 콘텐츠 검증과 참조 자산의 누락 여부.
3. QUIZ·경제·출정 idempotency, 끊김·복구·동시성 시험.
4. 사람0+AI30 전체 경기, 사람1+AI29 직접 참가 전체 경기.
5. 30개 독립 클라이언트 전송/수신, 호스트·학생 FPS와 서버 tick p95.
6. 30명 표준 AI의 40개 고정 seed 경기 시간. 중앙값과10/25/75/90백분위, 600~780초 경기 수, 13분 이후 완주와 미종료 건.
7. 동일 방3회 재경기와 자원·사망·이벤트 잔존 여부.
8. 대표 액션 영상과 전체맵 가독성 평가, 미완성 아트 목록.
9. 배포 주소 유무, 외부 접속 실제 성공 여부, 실기기 미검증 항목.

실기기 시험을 하지 못했다고 로컬 구현을 중단할 필요는 없다. 다만 그 칸은 NOT_RUN으로 남긴다. 브라우저가 없는 환경에서 DOM 모형만 실행했다면 브라우저 검증 완료로 적지 않는다. 전설이 세 번 나왔다고 10% 확률이 검증됐다고 주장하지 않는다.

## 5 참고 자료와 확인 범위

### 5.1 사용자 대화가 설계의 원천

진영·라인·탑·퀴즈·경제·정비·전설3명·호스트 이펙트·AI로비 요구는 이 대화의 최신 지시를 기준으로 한다. 기존 배틀로얄·경마왕·주식왕·DS사커에서 이어받을 것은 방 생성, 학생 로비, 퀴즈 보상, 게임 운영, 실제 기록 시상식, 재접속·재경기 안정성이다. 각각의 기존 전투 엔진·통신 경로를 새 저장소에 그대로 복사하라는 요구는 아니다.

사용자가 제공한 대상 저장소: https://github.com/YEOMT/Classclash.git

2026년10월26일 명세 준비 중 GitHub 조회에서는 빈 저장소였다. 이 문서는 원격에 게임 소스를 올렸다는 의미가 아니다. Codex가 실제 작업할 때 저장소 상태를 다시 확인한다.

기존 DSsoccer 참고 주소: https://yeomt.github.io/DSsoccer/

이번 정리는 사용자 대화와 보관된 기존 게임의 구조를 참고한 것이다. 위 주소의 현재 운영 빌드 전체를 시험했다거나 다른 모든 게임의 최신 파일을 분석했다고 주장하지 않는다. 새로운 서버와 방 네임스페이스를 사용하고 다른 운영 게임 데이터는 건드리지 않는다.

### 5.2 Teamfight Manager 공식 자료

**공식 상점 소개:** https://store.steampowered.com/app/1372810/Teamfight_Manager/

확인한 내용은 영웅마다 고유 특성과 스킬이 있고, 조합 선택이 중요하다는 설명이다. 원작의 짧은 데스매치와 세트당 궁극기 횟수는 클래스 클래시의 10~13분 넥서스 공성 규칙에 그대로 적용하지 않는다.

**Team Samoyed의 공식 업데이트:** https://steamcommunity.com/app/3009300/allnews/

전투 개선 공지에는 넥서스를 끝낼 기회 우선, 포탑 아래 망설임과 무익한 추격 감소, 상황에 맞는 방어 스킬 사용, 잘못된 범위 판정 수정, 유효 표적 없는 광역기 사용 방지 등의 사례가 있다. 클래스 클래시는 이러한 실패 유형을 자체 AI 규칙과 시험으로 구체화했다. 원작 내부 알고리즘을 입수했다는 뜻은 아니다.

이 명세에서 실제로 확인한 것은 공식 텍스트 설명과 업데이트다. 원작 애니메이션 원본을 프레임별 측정한 자료는 없다. 따라서 프레임 수·원본 픽셀 크기·스탯·AI 점수식은 모두 클래스 클래시의 독자적 초기 설계다. Codex의 제작 단계에서는 접근 가능한 공식 플레이 영상과 스크린샷을 실제로 보고 참고 특징을 기록한다. 이미 보았다고 허위로 적거나 원작 에셋을 추출하여 커밋하지 않는다.

## 6 최종 인계 체크

- 사용자 확정 규칙과 임시 수치가 구분되어 있다.
- 18명 영웅과36개 스킬의 정의가 있으며, 최대 레벨 스킬은 정확히2개다.
- 살아 있을 때 학생이 바꿀 수 있는 것과 사망 후 정비 행동이 분명하다.
- 첫20문제와 전투10문제/30초, 보상·중복·사망·재접속이 이어진다.
- 고급10% 전설과 역할 풀의 예외가 UI·서버·봇·테스트에 일치한다.
- AI 학생 추가가 장식용이 아니라 실제 자원·성장·출정 흐름으로 연결된다.
- 전체맵 모든 기능성 이펙트와 학생 카메라가 같은 전투 사건을 재생한다.
- 구현자가 미정의 필수 규칙을 새로 발명하지 않고 작업을 시작할 수 있다.
- 실제 게임 구현·시험·배포 완료를 이번 문서 작성 결과로 오인하지 않는다.
