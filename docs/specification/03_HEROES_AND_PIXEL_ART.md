# 클래스 클래시 영웅과 도트 액션 구현 명세

이 문서는 첫 플레이어블 버전에 들어갈 18명 영웅의 전투 데이터와 도트 애니메이션 규격이다. 사용자가 명시한 아홉 전형 영웅과 세 전설 영웅을 모두 포함한다. 추가 고급 영웅 여섯 명, 희귀도 배치, 아래 전투 수치는 구현을 진행하기 위한 **초기 설계값**이다. 영웅의 종류와 행동을 생략한 채 색상만 다른 캐릭터로 대체해서는 안 된다.

## 1. 공통 적용 규칙

### 1.1 우선순위와 단위

- 사용자의 최신 요구, 통합 마스터 명세, 공통 전투 명세, 이 영웅 데이터 순서로 해석한다. 문서 간 값이 어긋나면 통합 시 한쪽을 고치고 기록한다. 런타임에 서로 다른 규칙을 병존시키지 않는다.
- 좌표와 거리의 단위는 `world unit`이다. 기준 전장은 1536 × 768이다. 아래 수치는 화면의 CSS 픽셀이나 모니터 해상도에 비례해서 바꾸지 않는다.
- 시간은 초, 속도는 world unit/초다. 성장으로 파생하는 최대 체력과 공격력은 01의 공식대로 계산 끝에 한 번 정수 반올림한다. 전투 중 피해·남은 체력·보호막은 실수 정밀도를 보존하고 화면 표시에만 정수 반올림한다. 매 피해 단계마다 반복 반올림하지 않는다.
- 서버 시뮬레이션은 20 Hz를 기준으로 한다. 시전·피해 시점은 가장 가까운 과거 틱으로 당기지 않고 다음 유효 틱으로 올린다. 클라이언트 애니메이션은 서버 시간축에 보간한다.
- 공격 사거리 `R`은 **표면 사이 거리**다. `gap = max(0, distance(source.center, target.center) - source.radius - target.radius)`이고 `gap <= R`일 때 사거리 안이다. 이 규칙 덕분에 영웅보다 몸체가 큰 포탑을 근접 영웅이 정상 타격한다.
- 원형·부채꼴·선형 스킬은 별도의 충돌 도형을 쓴다. 도형과 대상의 충돌 원이 겹칠 때 맞는다. 단순히 모든 대상의 중심이 원 안에 있어야 한다고 처리하지 않는다. 대상 탐색 사거리와 광역 효과 반경을 혼동하지 않는다.
- `P`는 현재 레벨·강화를 적용한 공격력, `H`는 현재 최대 체력이다. 모든 치유·보호막 계수도 같은 `P`에서 계산하므로 지원 영웅 강화가 작동한다.
- 피해는 기본적으로 `rawDamage × 100 / (100 + targetArmor)`다. 물리·마법 색상은 시각 분류이며 첫 버전에 서로 다른 방어력 체계를 추가하지 않는다. 방어무시가 명시된 스킬만 예외다.
- 성장 공식은 `H = round(H0 × (1 + 0.12 × (Lv - 1)) × (1 + 0.08 × vitalityEnh))`, `P = round(P0 × (1 + 0.10 × (Lv - 1)) × (1 + 0.06 × powerEnh))`, `armor = armor0 + 2 × (Lv - 1)`이다. 강화 횟수는 `powerEnh + vitalityEnh <= 3`이다. 비용은 경제 명세를 단일 원본으로 사용한다. 이동속도·사거리·공격주기·CC 시간이 레벨·강화에 따라 자동 증가하지 않는다.

### 1.2 평타와 두 스킬

영웅은 평타와 정확히 두 개의 해금 스킬을 가진다. 초기 설정은 Lv.2에 스킬 1, Lv.5에 스킬 2 해금이다. 전설 영웅도 세 번째 액티브나 숨겨진 독립 패시브를 더하지 않는다. 표식·중첩처럼 특별한 메커니즘은 해당 스킬의 일부로 명시한다.

평타의 `attackInterval`은 다음 공격 시작까지 필요한 전체 주기다. `windup` 뒤에 근접 타격 또는 발사체 생성이 발생한다. 평타 후딜은 `ceilTick(min(0.30초, 0.20 × attackInterval))`이며, 그 뒤 남은 평타 쿨다운 동안에는 이동·표적 평가·허용된 스킬 사용을 할 수 있다. 전체 공격주기를 행동 잠금으로 처리하지 않는다. 공격의 확정 타격 전에 다른 표적을 향해 타격 이벤트를 옮기지 않는다. 원거리 평타는 발사 시점이 피해 시점이 아니다. 발사체가 실제 충돌할 때 서버가 피해를 판정한다.

기본 스킬 규약은 다음과 같다.

1. 쿨다운은 시전 시작 때 예약·소모한다. 시전 도중 죽거나 강한 CC로 끊기면 피해·치유는 발생하지 않고 쿨다운은 되돌리지 않는다.
2. 사망·정비·벤치에 들어가도 해당 영웅 인스턴스의 쿨다운 종료 시각을 보존한다. 시간 자체는 계속 흐른다. 재출정으로 즉시 초기화하지 않는다. 동일 종류 영웅 복제본을 번갈아 꺼내 쿨다운을 우회하지 못하도록 `effectiveReadyAt = max(instanceReadyAt, playerHeroTypeSkillReadyAt)`도 적용한다. 다른 영웅 종류끼리의 스킬 쿨다운을 공유하지는 않는다.
3. 같은 틱에 두 스킬을 시작하지 않는다. 구체적 우선순위가 없으면 생존 구제 → 아군 구제 → 확정 CC/킬 → 광역 효율 → 일반 피해 순이다.
4. 범위에 아무도 없을 때 공격 스킬을 쓰지 않는다. 치유·정화 스킬은 유효한 아군 조건을 확인한다. 효과를 다 낭비하는 시전으로 쿨다운을 소모하지 않는다.
5. 타격 확정 전에 표적이 죽거나 사거리를 벗어나면 공통 전투 명세의 유효성 재검사를 따른다. 투사체·고정 위치 광역은 이미 생성되었다면 독립적으로 진행한다.
6. 별도 표기가 없으면 근접·원거리 평타의 구조물 배율은 100%, 피해 스킬은 35%다. 표기한 배율은 방어 계산 전에 곱한다. 치유·보호막·정화·밀치기·감속·스턴·도발·표식은 구조물에 적용하지 않는다.
7. 잠긴 구조물은 스킬 관통으로 우회 공격할 수 없다. 보호 중인 넥서스 앞까지 관통한 화살이라도 피해를 주지 않는다.
8. 스턴·공중 띄우기는 행동 불가 시간으로 처리한다. 같은 대상에게 더할 때 지속시간을 단순 누적하지 않고 `max(existingUntil, now + duration)`으로 갱신한다. 연속 강한 CC가 2초 상한에 도달해 강제로 종료되면 2초 동안 강한 CC 면역을 준다. 짧은 CC의 자연 종료나 정화 자체가 새 면역을 주지는 않는다. 감속은 가장 강한 것만 적용하고 최대 50%다. 넉백은 공통 전투 규칙의 충돌·맵 경계 제한을 따른다.
9. 같은 종류 보호막은 같은 시전자에게서 재적용될 때 잔여량에 더하지 않고 큰 값과 더 긴 만료 시간으로 갱신한다. 서로 다른 시전자 보호막 합은 대상 최대 체력의 35%까지다. 보호막은 실제 흡수량만 방어 기여로 기록한다.
10. 치유는 부족한 체력만 채운다. 실제 회복량만 기록한다. 부활·구조물 수리·무한 보호막 같은 우회 기능을 만들지 않는다.

개별 영웅 표에 적힌 표적 수·체력 조건·예외는 해당 스킬의 최종 사용 조건이다. 공통 전투 문서의 일반적인 군집 수·회복 효율 조건을 추가 AND하여 스킬을 사실상 봉인하지 않는다. 생존 여부·해금·소유권·CC·사거리·지형·공성 잠금은 모든 스킬의 필수 공통 검사를 유지한다. 보호막은 개별 조건과 함께 현재 근접 위협 또는 0.8초 이내 예상 피해가 있는지 검사하여 안전한 빈 곳에서 반복 사용하지 않는다.

## 2. 일반 영웅 9명

각 스킬의 `시전`은 효과 생성까지의 선딜이고 `회복`은 효과 생성 후 다음 행동을 시작하기까지의 잠금 시간이다. 투사체는 생성 후 이동 시간이 추가된다. 다중 타격은 해당 스킬 블록에 기재한 타임라인을 우선한다.

### 2.1 성전사

**역할:** 앞줄 유지와 가까운 아군 보호. 흰 망토, 둥근 금빛 방패, 짧고 두꺼운 둔기를 사용한다. 철갑기사보다 가볍고 밝은 실루엣이다.

- 평타: 방패를 당기고 무기를 어깨 뒤에서 60도 내려친다. 타격 프레임에 둔기 머리가 표적 방향으로 나오며 금빛 짧은 십자 불꽃이 생긴다.
- 기본 AI: 아군 원거리보다 40~70 앞에 선다. 이미 아군을 때리고 있는 근접 적을 우선한다. 보호막을 위해 전투 한가운데를 횡단해 먼 아군을 쫓지 않는다.
- 약점: 추격 속도와 단일 피해가 낮다. 두 갈래에서 공격받거나 장거리 집중 사격을 받으면 혼자 전선을 해결하지 못한다.

| 스킬 | 해금 | 발동 조건과 표적 | 효과·판정 | 시간 | 구조물 |
|---|---:|---|---|---|---|
| 방패 강타 | 2 | 간격 22 이내 적. 아군을 공격 중인 적 영웅 우선 | 단일 `1.30P` 피해, 스턴 0.60초. 타격 직전에 간격 30까지 허용 | CD 8초, 시전 0.25초, 회복 0.25초 | 피해 35%, 스턴 없음 |
| 성역 방패 | 5 | 반경 110 안에 현재 교전 중인 아군 영웅 2명 이상 또는 HP 40% 이하 아군 1명 | 자신 포함 최대 4명에게 `2.0P + 0.07H` 보호막, 3초. HP 비율 낮은 아군 우선 | CD 18초, 시전 0.40초, 회복 0.25초 | 효과 없음 |

방패 강타는 몸통을 2 world unit 낮췄다가 방패를 앞으로 5만큼 내민다. 성역은 바닥에 낮은 금빛 원이 먼저 생기고 대상 몸 옆에 반투명 방패 조각이 붙는다. 큰 원이 캐릭터 몸을 불투명하게 덮지 않는다.

### 2.2 검사

**역할:** 단일 적을 안정적으로 압박하는 가벼운 전위. 푸른 짧은 상의, 긴 얇은 검, 몸통보다 길게 보이는 칼날이 특징이다.

- 평타: 옆 베기 → 반대 옆 베기 두 포즈를 번갈아 사용한다. 피해 수치·주기는 같으며 포즈만 순환한다.
- 기본 AI: 접근 가능한 가장 가까운 전열 목표를 잡고 끝까지 교환한다. 마무리가 가능한 적이 60 이내이고 현재보다 30 이상 멀지 않을 때만 재표적한다.
- 약점: 광역 공격과 다수 포위. 받아치기로 발사체 전부를 막거나 스킬 피해를 무효화하지 않는다.

### 2.3 격투가

**역할:** 짧은 주기의 근접 압박과 짧은 방해. 붉은 권투 장갑, 드러난 팔, 낮은 중심 자세로 다른 근접 영웅과 구분한다.

- 기본 AI: 작은 빈 공격 자리를 찾아 적의 좌우에 붙는다. 몸집 큰 탱커를 관통해서 후방을 노리지 않는다.

| 룬 공명 | 5 | 210 안 자신이 표식한 적이 2명 이상 또는 표식한 적 영웅 HP 35% 이하 | 시전 순간 합법 표적 최대 3명 예약. 0.55초 뒤 각 예약 표식 대상 위치 반경 42 폭발 `1.80P`, 30% 감속 1.5초. 표식 소모. 한 대상이 여러 폭발에 겹쳐도 최초 100%, 두 번째부터 25%, 총 150% 상한 | CD 18초, 시전 0.55초, 회복 0.30초 | 피해 20%, 감속·표식 없음 |

표식은 시전자별이다. 여러 룬 마법사가 서로의 룬을 터뜨리지 않는다. 예약 표적이 죽으면 해당 폭발은 시전 때 예약했던 마지막 유효 위치에 발생하되 다른 표적으로 재배정하지 않는다. 공명은 유효 표식이 있을 때만 쿨다운을 쓴다.

삼중 룬은 마법사가 책 위로 팔을 들어 세 작은 기호를 찍는 동작이다. 공명은 룬들이 가느다란 선으로 연결되는 0.3초 예고를 거쳐 각 자리에서 터진다. 연결선 자체에는 피해가 없으며 지도 전체를 가르는 길이로 늘리지 않는다.

### 4.2 고대의 존재

**역할:** 느린 충격의 누적과 분명한 전방 강타. 뿔 없는 커다란 석제 가면, 어두운 청동 몸체, 길고 무거운 팔을 가진 근접 딜러다. 골렘보다 날렵한 허리와 비대칭 고대 문양으로 구분한다.

- 평타: 양팔 중 한쪽을 뒤로 당겼다가 몸통과 함께 내려친다. 평타의 선딜과 후딜을 명확히 남긴다.
- 기본 AI: 이미 교전 중인 가까운 전열을 부순다. 낮은 체력의 후열을 보자마자 돌진하는 암살자 행동을 하지 않는다.
- 약점: 길고 눈에 띄는 공격 준비. 이속이 특별히 빠르지 않고 자체 회복이 없다.

| 스킬 | 해금 | 발동 조건과 표적 | 효과·판정 | 시간 | 구조물 |
|---|---:|---|---|---|---|
| 파쇄 인장 | 2 | 간격 20 이내 적. 이미 자신의 인장이 있는 적 우선 | 단일 `1.60P`, 6초 인장 1중첩, 최대 3. 3중첩에 도달하면 즉시 모두 소모해 추가 `1.20P`와 0.70초 스턴. 인장 시간은 새 중첩 때 갱신 | CD 4초, 시전 0.35초, 회복 0.30초 | 피해 30%, 인장·추가폭발·스턴 없음 |
| 태고의 균열 | 5 | 전방 길이 145·폭 38 안 적 3명 또는 영웅 2명. 또는 자신과 인접한 적 영웅 HP 30% 이하 | 두 손을 들어 0.60초 뒤 전방 균열 생성. 앞 45/95/145 거리 구간에 0.10초 간격으로 피해 판정. 각 대상 최초 1회 `2.60P`, 최대 30 밀치기. 좁은 선 위 실제 대상만 타격 | CD 19초, 시전 0.60초, 회복 0.40초 | 피해 30%, 밀치기 없음 |

인장은 전설의 평타에 무조건 붙는 숨은 패시브가 아니다. 파쇄 인장을 실제 세 번 맞혀야 폭발한다. 다수의 고대의 존재가 서로의 중첩을 합치지 않는다. 첫 인장 이후 4초, 8초의 공격 기회가 필요하므로 표적 유지·생존이 중요하다.

균열의 땅 갈라짐은 3구간이 실제 시간차로 뻗는다. 전장 배경을 영구 변경하지 않는다. 카메라를 강제로 확대하거나 다른 전투를 가리는 흑색 전면 컷인을 쓰지 않는다.

### 4.3 수호령

**역할:** 아군의 위험한 순간을 보호막과 짧은 결계로 받아내는 탱커. 푸른 흰색 수호 짐승 가면, 큰 어깨 망토, 둥근 손 방패를 가진 영체다. 발은 땅에서 1~2픽셀 떠 있지만 충돌·이동은 정상 보행을 따른다.

- 평타: 손바닥의 작은 푸른 충격. 자신의 몸을 완전히 투명하게 만들어 전장 식별을 떨어뜨리지 않는다.
- 기본 AI: 아군 다수가 따라오는 전열을 유지한다. 가장 멀리 있는 빈사 아군을 구하려고 다른 라인으로 순간 이동하지 않는다.
- 약점: 직접 피해와 추격력이 낮다. 보호 범위가 비어 있거나 아군이 분산되면 가치가 떨어진다.

| 스킬 | 해금 | 발동 조건과 표적 | 효과·판정 | 시간 | 구조물 |
|---|---:|---|---|---|---|
| 영혼의 호위 | 2 | 간격 110 안 HP 60% 이하 아군 영웅. 자신도 가능. 최근 피해가 큰 대상 우선 | 단일 `2.70P + 0.06H` 보호막 3초, 감속 효과 하나 해제. 스턴·속박은 해제하지 않음 | CD 8초, 시전 0.25초, 회복 0.25초 | 사용 불가 |
| 수호 결계 | 5 | 자신 중심 105 안 교전 중 아군 영웅 3명 또는 HP 45% 이하 아군 2명 | 3.5초 고정 영역. 안의 아군이 받는 피해 25% 감소. 시전자에게 `2.0P` 보호막. 영역 출입 때 즉시 적용/해제, 다중 결계 피해감소는 최댓값 하나만. 시전자 사망 시 영역 즉시 종료 | CD 22초, 시전 0.50초, 회복 0.30초 | 구조물 보호 불가 |

결계는 이동형 무적 오라가 아니다. 발동 위치에 남는 얇은 청색 경계와 네 개의 수호 기둥을 표시한다. 영혼의 호위의 대상과 보호막 잔여량은 학생 확대 화면에서 읽을 수 있어야 한다.

영혼의 호위가 감속 하나를 해제할 때는 현재 적용 강도가 가장 큰 감속을 제거한다. 강도가 같으면 만료가 더 늦은 것을 고른다. 다른 출처의 약한 감속이 남으면 공통 상태 합성 규칙에 따라 그 감속이 이어진다.

## 5. 역할별 이동·진형·시전 우선순위

영웅은 학생이 출정시킨 뒤 스스로 싸운다. 이 표의 성향은 서버 AI의 입력이지 플레이어가 생존 중 바꾸는 전술 지시가 아니다. 테스트용 AI 학생의 난이도가 달라도 **동일 영웅의 전투 지능은 동일**하다.

| 역할 | 기본 위치 | 접근·이탈 | 우선 표적 | 스킬 판단 |
|---|---|---|---|---|
| tank | 가장 앞의 안전한 공격 자리, 후열보다 40~80 앞 | 아군 합류가 있으면 진입. 빈사 시 짧은 후퇴 허용, 기지까지 자동 귀환 금지 | 근처 아군을 공격하는 적, 접근 가능한 전열, 합법 구조물 | 구제 보호막·방어 → 위협 적 방해 → 피해 |
| melee | 탱커 좌우 공격 자리, 동일 적의 자리를 독점하지 않음 | 우회로가 실제로 열렸을 때 측면 접근. 공격 하나마다 먼 후열 재탐색 금지 | 접근 가능한 적, 확실한 근거리 마무리, 합법 구조물 | 확정 타격 가능한 스킬 → 평타 |
| ranged | 현재 목표와 최대 사거리의 78~92% | 후딜 이후 한 번에 짧게 카이팅. 안전공간 없으면 싸움 지속 | 사거리 안 현재 표적, 접근 적, 노출된 영웅, 합법 구조물 | 위협 제어 → 효율 좋은 직선/광역 → 평타 |
| mage | 전열 뒤 70~120 | 유효 표적을 맞힐 만큼만 전진. 군집 중심을 향해 몸이 들어가지 않음 | 현재 사거리 안 군집, 위협 적, 합법 구조물 | 좋은 군집·방해 → 단일 효율 → 평타 |
| support | 보호 중인 아군 뒤 75~130 | 아군과의 거리 유지. 먼 빈사 아군을 위해 적진 횡단 금지 | 유효한 지원 대상 우선, 공격은 가까운 적 | 해제·보호·치유 → 팀 버프 → 유효 공격 |

세부 이동 경로·공격 자리·타워 어그로·공성 우선순위·막힘 복구는 `02_AI_AND_COMBAT.md`를 따른다. 이 파일의 특정 영웅 예외가 공통 충돌·타워 잠금·행동 불가 규칙을 우회하지 않는다.

## 6. 도트 아트와 애니메이션 규격

### 6.1 참고 원칙과 확인 범위

Teamfight Manager에서 참고할 것은 작은 캐릭터에서도 역할이 읽히는 실루엣, 간결한 전투 자세, 공격·피격의 빠른 전달, 서로 다른 영웅 조합의 관전 재미다. 공식 상점은 영웅별 고유 특성과 두 종류의 스킬, 조합의 중요성을 설명한다. 이 게임은 그 설명을 참고해 독자적인 10~13분 공성 규칙과 레벨 해금 구조로 설계한다.

- 공식 소개: https://store.steampowered.com/app/1372810/Teamfight_Manager/
- 공식 개발자 업데이트: https://steamcommunity.com/app/3009300/allnews/

이 명세의 프레임 수·스프라이트 크기·타이밍·스탯은 자체 설계값이다. 원작 영상의 프레임 단위 분석이나 원본 에셋 추출이 완료되었다고 주장하지 않는다. 실제 제작 때 공식 공개 플레이 영상·스크린샷을 시각 참고로 확인하고, 참고한 자료 URL과 확인한 특징만 `docs/ART_REFERENCE.md`에 기록한다. 원작 스프라이트·캐릭터 디자인·UI·로고·사운드를 복사해 저장소에 넣지 않는다.

### 6.2 원본 크기와 팔레트

- 일반·고급 인간형의 본체 작업 셀은 32 × 40, 전설·골렘은 최대 40 × 48이다. 무기 궤적과 지팡이 발사체를 담는 추가 여백을 본체 충돌 크기에 더하지 않는다.
- 프레임의 발 기준점을 유지한다. 큰 무기를 들어도 바닥 좌표가 움직이지 않는다. 프레임마다 자동 trim한 이미지의 중앙을 피벗으로 삼으면 캐릭터가 흔들리므로 금지한다.
- 캐릭터별 기본 팔레트 8~14색. 외곽선은 짙은 유색, 가장 밝은 점은 얼굴·무기·효과 중심에 제한한다. 부드러운 안티앨리어싱, 사진 텍스처, 벡터식 매끈한 외곽을 쓰지 않는다.
- 팀 구분은 발밑 링, 작은 HP 바 가장자리, 소속 표식으로 한다. 청팀이라고 화염술사의 불을 파랗게 바꾸거나 홍팀이라고 얼음술사를 붉게 칠하지 않는다.
- 희귀도는 초상 테두리·소환 연출·작은 아이콘으로 표시한다. 전설의 몸 전체를 지속적인 번쩍임으로 둘러싸지 않는다.
- `imageSmoothingEnabled=false`에 해당하는 가장 가까운 픽셀 샘플링을 사용한다. 가능한 경우 정수 확대를 쓰며, 화면 맞춤 비정수 배율이 불가피한 호스트 축소에서도 저해상도 원본을 번지게 블러 처리하지 않는다.
- 원본 이미지와 아틀라스를 함께 보관한다. 코드로 원본 도트를 생성한다면 생성 스크립트·팔레트·포즈 정의도 함께 보관한다. 고정된 추상 사각형에 무기 이펙트만 붙이는 형태는 완성 아트로 인정하지 않는다.

### 6.3 방향과 상태

이동·공격 판정은 8방향을 지원한다. 최소 아트 방향은 정면·후면·측면·앞 대각·뒤 대각 다섯 방향을 직접 그리고 좌우 반전을 이용해 8방향을 만든다. 큰 방패·무기의 좌우 손 규칙을 유지해야 하므로 모든 방향을 단순 반전하는 것으로 끝내지 않는다. 몸의 방향은 공격 시작 때 고정하고, 회복 동작 후 다음 목표 방향으로 전환한다.

| 상태 | 최소 독립 자세 수 | 권장 재생 | 필수 내용 |
|---|---:|---|---|
| idle | 2 | 2~3 fps 루프 | 숨·망토 끝의 미세한 변화. 이동하지 않음 |
| walk | 4 | 이동속도와 연동, 6~10 fps | 서로 반대인 두 발 디딤, 상체 1픽셀 변화 |
| basicAttack | 4~6 | 스탯 시간축 | 준비 1~2, 타격 1, 회복 2 이상. 단순 몸체 앞뒤 이동 금지 |
| skill1 | 4~7 | 스킬별 시간축 | 영웅 고유 준비와 효과 생성 자세 |
| skill2 | 5~9 | 스킬별 시간축 | 평타·첫 스킬과 다른 실루엣·무기 동작 |
| hurt | 2 | 0.10~0.18초 표시 | 몸 기울기·짧은 밝기. 서버 행동 잠금과 별개 |
| death | 5 | 0.35~0.65초 | 중심 무너짐, 무기 내림, 바닥 잔상 후 제거 |
| spawn | 3 | 0.35초 | 발밑 소속 링과 몸의 등장, 조작권을 요구하지 않음 |

모든 상태에 모든 방향의 고유 수작업 프레임을 무작정 늘리기보다, 스프라이트 부품과 pose keyframe을 사용해 공통 관절을 재사용할 수 있다. 그러나 영웅별 무기 동작과 시전 자세는 실제 프레임으로 달라야 한다. 달리는 그림 한 장을 흔들기만 하는 구현, 평타와 두 스킬이 모두 같은 그림을 번쩍이는 구현은 실패다.

### 6.4 핵심 액션의 눈에 보이는 차이

| 영웅 | 평타의 핵심 | 첫 스킬의 핵심 | 둘째 스킬의 핵심 |
|---|---|---|---|
| 성전사 | 둔기 내리치기 | 방패 전진 밀어치기 | 방패를 세우며 낮은 금빛 영역 |
| 검사 | 날렵한 양방향 베기 | 검을 세워 받아내고 반격 | 실제 이동 경로의 한 줄 베기 |
| 격투가 | 좌우 직선 주먹 | 서로 다른 세 번 연타 | 낮게 앉았다 위로 치솟음 |
| 궁수 | 시위 당김과 놓기 | 더 긴 시위 준비와 굵은 화살 | 하늘로 활을 들어 바닥에 낙하 |
| 화염술사 | 작은 불덩이 | 큰 불덩이와 착탄 확산 | 지팡이로 가로선을 그어 불길 생성 |
| 얼음술사 | 가는 얼음 파편 | 손을 옆으로 펼치는 부채 | 지팡이 내려찍기와 발목 얼음 |
| 사제 | 약한 빛 구체 | 지팡이를 대상에게 뻗음 | 두 손을 모으고 회복 파동 |
| 야만인 | 무거운 도끼 내려치기 | 몸·도끼 한 바퀴 회전 | 바닥 그림자가 따라오는 도약·착지 |
| 수도승 | 긴 봉 찌르기 | 봉을 눕혀 밀어냄 | 작은 종을 들고 고리 파동 |
| 철갑기사 | 방패 고정·철퇴 휘두름 | 상체 낮춘 직선 돌진 | 발을 넓게 딛고 방패 고정 |
| 수호골렘 | 큰 주먹 내려찍기 | 양손 바닥치기 | 가슴 빛과 짧은 포효 원 |
| 암살자 | 번갈아 단검 찌르기 | 측면으로 실제 이동과 잔상 | 세 번 칼날 교차 |
| 석궁병 | 견착·발사·장전 | 무거운 볼트와 큰 반동 | 끈 달린 구속 탄 |
| 번개술사 | 작은 전기 구체 | 대상 사이의 짧은 번개 연결 | 바닥 예고 뒤 한 줄 낙뢰 |
| 음유시인 | 현 한 번 뜯기 | 현을 빠르게 쓸며 음표 상승 | 악기를 강하게 튕긴 부채 파동 |
| 룬 마법사 | 책 위 사각 탄환 | 세 룬을 차례로 찍음 | 연결 예고 뒤 각각의 룬 폭발 |
| 고대의 존재 | 큰 팔의 무거운 타격 | 손바닥의 인장 각인 | 두 팔 내려찍기·세 구간 균열 |
| 수호령 | 손바닥 충격 | 아군을 향한 한 손의 보호 | 두 팔을 펼쳐 고정 결계 생성 |

### 6.5 아틀라스와 애니메이션 데이터 계약

그래픽 로딩 완료 전에도 오류 안내가 보여야 하며, 아틀라스 파일 누락으로 빈 화면에서 무한 대기하지 않는다. 개발 중 대체 텍스처는 명시적으로 표시하고, 배포 합격 단계에서는 18명 전원 정식 원본 아트가 있어야 한다.

필수 메타데이터 예시는 다음과 같다. 아래는 구현 계약 예시이며 외부 라이브러리의 특정 API가 아니다.

```json
{
  "heroId": "archer",
  "atlasVersion": 1,
  "logicalSize": [32, 40],
  "pivot": [16, 36],
  "directions": ["S", "SE", "E", "NE", "N", "NW", "W", "SW"],
  "animations": {
    "basicAttack.E": {
      "loop": false,
      "windup": {
        "frames": ["archer_atk_e_0", "archer_atk_e_1"],
        "normalizedTimes": [0.0, 0.5]
      },
      "recovery": {
        "frames": ["archer_atk_e_2", "archer_atk_e_3", "archer_atk_e_4"],
        "normalizedTimes": [0.0, 0.25, 0.65]
      },
      "events": [{"name": "projectileRelease", "serverBoundary": "impactTick"}]
    }
  }
}
```

`normalizedTimes`는 각 phase 내부의 0~1 시간 비율이다. windup의 실제 길이는 `impactTick - actionStartTick`, recovery의 실제 길이는 `recoveryEndTick - impactTick`이다. 서로 다른 영웅에게 같은 전체 애니메이션 길이를 강제하지 않는다. 궁수의 기본값은 선딜 0.30초와 후딜 0.25초이므로 실제 동작 길이는 0.55초이고 다음 평타 시작은 이전 시작으로부터 1.10초 뒤다. 중간 0.55초는 이동 가능한 평타 대기다. release 자세는 recovery 첫 프레임에 포함하므로 별도 고정 프레임 시간을 더해 서버 동작을 늘리지 않는다.

04의 서버 계약에 맞춰 `actionId`, `actionStartTick`, `impactTick`, `recoveryEndTick`, `entityId`, `targetEntityId`, `targetPoint`, `facingX`, `facingY`가 애니메이션의 기준이다. 전투 이벤트의 출처는 `sourceEntityId`다. 원거리 공격의 `impactTick`은 발사체 생성 시점이며, 이후 실제 피해 시점은 발사체 충돌 이벤트가 정한다. 위 메타데이터의 `projectileRelease`는 **그래픽 동기화용 표시**이며 클라이언트가 새 피해를 생성하는 권한이 아니다. 실제 발사체·피해는 서버 이벤트를 따른다. 틱과 아트의 선딜이 맞지 않으면 아트를 늘리거나 줄여 일치시킨다. 서버 판정을 아트 재생 완료 콜백에 의존시키지 않는다.

이벤트가 늦게 도착했을 때는 현재 서버 시각에 해당하는 프레임부터 재생한다. 이미 지나간 발사체를 캐릭터 손에서 다시 발사해 두 번 보이지 않게 한다. 재접속 시 오래된 폭발을 전부 다시 재생하지 않고 현재 살아 있는 발사체·장판·진행 중 액션만 복원한다.

### 6.6 타격감과 읽기 쉬운 효과

- 적중 확인은 짧은 몸 색상 변화 60~90ms, 작은 적중 불꽃, 필요한 경우 규칙에 정의된 실제 넉백으로 만든다.
- 강한 타격의 시각적 멈춤은 해당 공격자·피격자의 **렌더 pose**에 최대 45~70ms만 적용한다. 서버 시계, 경기 시계, 다른 라인, 네트워크 전송을 멈추지 않는다.
- 피격 자세가 현재 공격의 서버 선딜·쿨다운을 몰래 초기화하지 않는다. 스턴 없는 피해는 가벼운 오버레이 반응으로도 처리할 수 있다.
- 일반 평타 타격음과 스킬 타격음은 음색을 구분하되 다수가 동시에 싸울 때 같은 소리를 무제한 겹치지 않는다. 오디오 우선순위·동시 발음 수 제한은 허용하지만 실제 시각 판정을 삭제하지 않는다.
- 범위는 바닥 레이어, 유닛은 중간, 무기·타격 효과는 위 레이어로 나눈다. 캐릭터 머리보다 큰 불투명 폭발이 0.15초 넘게 유지되어 다른 행동을 가리지 않도록 한다.
- 광역 예고는 해당 영역의 경계 위주로 보이고, 아군/적군은 링의 작은 끊김 패턴과 색상으로 구분한다. 색상만으로 상태를 구분하지 않는다.
- 비슷한 순간에 많은 피해 숫자가 생기면 같은 대상의 숫자를 짧게 합칠 수 있다. **호스트 화면의 공격 자세·실제 발사체·적중·스킬 영역·스킬 이펙트는 이 이유로 생략하지 않는다.**

### 6.7 18명을 실제로 완성하기 위한 공유 제작 구조

18명 × 여러 방향 × 여러 상태를 모두 독립 수작업 파일로 만드는 대신, **도트 부품·공유 자세·영웅별 덮어쓰기 데이터를 빌드 단계에서 합성하여 PNG 아틀라스로 굽는 방식**을 기본 제작 경로로 삼는다. 이는 캐릭터 수를 줄이거나 영웅을 색상만 바꾸는 대체가 아니다. 반복되는 보행·호흡·피격의 제작 비용을 줄이고 무기·고유 액션에 작업을 집중하는 방식이다.

1. 원본 부품은 머리, 앞·뒤 몸통, 앞·뒤 팔, 앞·뒤 다리, 망토, 주무기, 보조무기로 나눈다. 피벗·손·발·투사체 발사점은 각 방향의 정수 좌표 anchor다. 모든 부품을 표시해야 하는 것은 아니며 수호령처럼 다리가 숨겨진 경우도 명시적으로 생략한다.
2. 아래 다섯 체형의 공통 idle/walk/hurt/death 자세를 만든다. 포즈의 몸통 기울기와 손발 위치는 공유하되 머리 윤곽·장비·몸 폭·팔레트는 영웅마다 다르게 정의한다.
3. 평타는 베기·찌르기·주먹·활·석궁·지팡이·강타·방패 등 공용 motion family에서 가져오고, 영웅마다 선딜과 무기 궤적·몸통 반동을 덮어쓴다. 같은 motion family라도 공격주기는 스탯 데이터의 값을 쓴다.
4. 각 스킬은 `bodyPoseTrack + weaponPoseTrack + effectTrack`을 결합한다. 몸의 공통 시전 자세를 재사용해도 도약, 돌진, 연타, 회전, 발사, 치유의 효과 생성 위치와 경로는 실제 규칙대로 서로 달라야 한다.
5. 방향별 부품 좌표와 pose keyframe을 정수로 래스터화하여 PNG·JSON을 생성한다. 화면 실행 중 매 프레임 새 캔버스를 만들어 굽지 않는다. 런타임은 생성된 아틀라스 프레임을 선택하고 필요한 발사체·영역만 별도 그린다.
6. 좌우 반전은 metadata에서 선언할 수 있다. 방패 손이나 비대칭 무기가 바뀌어 보이는 경우는 해당 방향의 anchor와 장비 레이어를 별도 덮어쓴다. 사진·벡터 회전을 부드럽게 보간해 흐릿한 픽셀을 만들지 않는다.

| 공유 체형 | 영웅 | 반드시 다른 원본 요소 |
|---|---|---|
| 가벼운 인간형 | 검사·격투가·궁수·암살자·석궁병 | 검/장갑/활/쌍단검/석궁, 머리·상의·대기 자세 |
| 갑주 인간형 | 성전사·철갑기사 | 둥근 방패와 망토 / 사각 방패와 전신 갑옷 |
| 로브 인간형 | 화염술사·얼음술사·사제·수도승·번개술사·음유시인·룬 마법사 | 모자·후드·장삼·지팡이·봉·악기·책의 실제 형태 |
| 큰 전위형 | 야만인·수호골렘·고대의 존재 | 살과 도끼 / 돌주먹과 이끼 / 가면과 긴 팔 |
| 영체형 | 수호령 | 수호 가면·손 방패·어깨 망토·떠 있는 발 자세 |

생성 설정은 다음과 같이 기록한다. 예시는 구조 계약이며 전투 데이터의 별도 복사본으로 만들지 않는다.

```json
{
  "heroId": "archer",
  "rig": "light_humanoid",
  "parts": {
    "head": "archer_feather",
    "torso": "archer_green_cloak",
    "weapon": "wooden_bow"
  },
  "poses": {
    "idle": "light_idle",
    "walk": "light_walk",
    "basicAttack": "bow_draw_release",
    "skill1": "bow_heavy_draw",
    "skill2": "bow_sky_shot"
  },
  "weaponSocketsByDirection": "archer_sockets_v1",
  "sourceCell": [32, 40],
  "worldBodySize": [32, 40],
  "footPivot": [16, 36]
}
```

원본 파일 구성의 기본안은 `assets/source/rigs`, `assets/source/parts`, `assets/source/poses`, `assets/source/heroes`, `assets/generated/atlases`, `assets/generated/animations`다. `scripts/build-sprites` 하나로 재생성 가능하게 한다. 기술 스택에 맞는 스크립트 언어를 사용할 수 있으며 특정 그림 도구의 수동 파일만 있어야 하는 의존성을 만들지 않는다. 아틀라스 한 장의 초기 목표 크기는 최대 2048 × 2048이고 넘으면 여러 장으로 나눈다.

전설을 표현하기 위해 본체를 임의로 두세 배 키우지 않는다. 일반·고급 본체의 세계 크기는 32 × 40 이내, 큰 체형·전설은 40 × 48 이내다. 후광·깃발·무기 여백 때문에 본체 중심과 충돌 반경을 확대하지 않는다. 큰 전설 3명이 나란히 서도 넓이 144인 라인에서 다른 영웅의 몸을 가리지 않아야 한다. 특히 고대의 존재를 라인 전체 폭의 보스로 제작하지 않는다.

개발용 영웅 전시 화면에는 18명 전원을 같은 배율로 놓고 방향·상태·레벨·스킬을 선택할 수 있게 한다. 렌더러가 전시 화면과 실제 전투에서 같은 아틀라스를 사용해야 한다. 전시에서는 보이지만 실제 전투에는 임시 도형을 쓰는 이중 구현을 금지한다. 다음 자동 검사를 자산 빌드에 넣는다.

- 모든 `heroId`에 idle/walk/basicAttack/skill1/skill2/hurt/death/spawn과 8방향 해석 결과가 존재한다.
- 모든 프레임의 발 피벗과 worldBodySize가 유효하고, 투사체 발사 socket이 해당 손·무기 근처에 있다.
- 동일한 평타·스킬 1·스킬 2 프레임 열을 이름만 바꿔 참조하는 경우 실패한다. 공통 준비 자세를 공유해도 타격·해방 자세 중 하나 이상은 달라야 한다.
- 팔레트 교체 외의 형태 차이가 없는 영웅 두 개는 육안 검수에서 실패한다. 자동 파일 hash 차이만으로 통과시키지 않는다.
- 아틀라스 누락은 누락된 영웅 ID·상태·방향을 표시하며 빌드를 실패시킨다. 브라우저에서 조용히 무색 사각형으로 대체하지 않는다.
- 원본 부품·포즈 데이터를 고치면 동일 명령으로 산출물을 재생성하고 변경 프레임을 전시 화면에서 확인한다.

이 제작 구조로 첫 버전의 18명을 모두 채운 뒤, 추가 수작업 포즈는 품질을 높이는 과정으로 진행한다. 실제 제출 시에는 18명 각각의 평타와 두 스킬이 준비·해방·회복으로 구분되고, 호스트 전체맵에서도 해당 무기와 핵심 효과가 읽혀야 한다.

## 7. 호스트 전체 전장과 학생 카메라의 공통 표현

호스트는 전체 지도를 항상 본다. 상단 스코어판에 가려지는 전장 영역이 없어야 하며, 전투가 일어난다고 자동 확대·자동 카메라 전환을 하지 않는다. 학생은 자신의 영웅과 바로 주변 전투를 따라가지만 별도의 전투를 시뮬레이션하지 않는다.

렌더링 성능 문제는 배경 캐시, 아틀라스 배치, 이펙트 입자 재사용, 공간 분할, 바뀌지 않은 UI 갱신 생략으로 해결한다. 호스트에서 멀리 있는 전투를 점이나 막대로 축약하거나 발사체를 통째로 빼는 방식은 요구사항 위반이다. 입자의 장식 개수를 줄일 수는 있지만 스킬 종류·영역·발사·적중 시점을 표현하는 핵심 요소는 유지한다.

최소 시각 검수 장면은 다음과 같다.

1. 호스트 1920 × 1080과 1366 × 768에서 전체 2라인, 12개 타워, 2개 넥서스, 모든 생존 유닛이 화면 내에 보인다.
2. 30영웅과 적어도 2웨이브가 겹친 장면에서 위·아래 라인 양쪽의 화염 장벽, 화살비, 연쇄 번개, 보호막을 동시에 확인한다.
3. 학생 태블릿 가로 1024 × 768에서 본인 영웅의 준비·타격·회복 자세를 구분하고, 체력·정비 진입·퀴즈 버튼을 누를 수 있다.
4. 학생 모바일 세로에서도 영웅과 근처 전투가 보이고 퀴즈를 열었다 닫아도 카메라가 전체 맵으로 튀거나 영웅을 잃지 않는다.
5. 사망 판정 즉시 정비 UI를 열고 기존 영웅의 사망 애니메이션을 함께 보여준다. 출정은 사망 후 최소 5초가 지나고 학생이 직접 눌렀을 때만 가능하다. 새 영웅은 아군 본진에서 시작한다.
6. 출정 후 학생의 클릭·드래그·방향키가 영웅 이동·공격·스킬을 바꾸지 않는다. 카메라 확인·퀴즈 응답 이외의 전투 조작이 없어야 한다.

## 8. 데이터와 아트의 완료 조건

- 18명 모두 기본 스탯, 평타, 고유한 스킬 2개, 해금 조건, 음향·도트 동작, 도감 설명을 가진다. 6명만 완성하고 나머지는 추후로 남기는 결과는 첫 버전 완료가 아니다.
- 데이터 기반 스킬 시스템을 만들되 `effectType` 하나에 파라미터만 바꾼 채 모든 스킬을 같은 원형 폭발로 대체하지 않는다. 단일/선/부채/원/지속 영역/보호막/정화/돌진/도약/연쇄/표식 작동을 실제로 구분한다.
- 무기와 손 위치, 발 피벗, 방향 반전, 발사체 출발 위치를 8방향에서 확인한다. 화살이 머리 뒤에서 생기거나 몸 반대쪽으로 날아가는 버그는 실패다.
- 스킬 버튼을 학생에게 노출하지 않는다. 스킬 카드에는 해금 레벨·설명·쿨다운 상태만 보여준다.
- 도감 숫자와 엔진 숫자를 별도 하드코딩하지 않는다. `heroes` 데이터에서 둘 다 생성한다.
- 성장 상태는 개인 영웅 인스턴스에 귀속한다. 같은 종류를 두 번 뽑아도 레벨·강화는 서로 독립이다. 개별 인스턴스 쿨다운을 보존하며, 같은 플레이어·같은 영웅 종류·같은 스킬의 공통 최소 사용 가능 시각도 검사하여 복제본 교대 연사를 막는다.
- 스킬 피해 테스트는 단순 데이터 존재 검사에 그치지 않는다. 움직이는 표적, 죽은 표적, 사거리 이탈, CC 중단, 보호 구조물, 좁은 통로, 겹친 보호막, 여러 룬 시전자까지 검증한다.
- 시각 테스트 결과에는 실제 캡처한 화면·환경·해상도를 기록한다. 모의 데이터·정적 검사만 수행했으면 브라우저나 태블릿에서 직접 확인했다고 쓰지 않는다.
