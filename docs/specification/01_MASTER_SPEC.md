# 클래스 클래시 전체 게임 명세

## 1 목적과 완성 범위

클래스 클래시는 교사가 방을 열고 최대 30명의 학생이 퀴즈로 모은 게임 내 재화로 영웅을 운용하는 2진영 자동 공성 게임이다. 학생은 영웅 한 명을 선택해 상단 또는 하단 라인에 출정시킨다. 출정 후 이동·공격·스킬·전술 판단은 모두 AI가 수행한다. 학생은 전투를 보거나 퀴즈를 푼다. 영웅이 사망하면 정비시간에 다음 출정을 준비한다. 적 넥서스가 파괴되면 승리 팀과 여러 기여상을 발표한다.

첫 제출물은 초기부터 결과까지 이어지는 플레이 가능한 게임이어야 한다. 화면, 전투 엔진, 통신, 퀴즈, 영웅 성장, 뽑기, AI 학생, 시상식 중 어느 하나가 가짜 데이터나 TODO로 남으면 완성으로 간주하지 않는다. 그래픽과 전투는 기능 검증 이후 별개 미래 작업으로 미루지 않는다.

## 2 사용자 확정 사항과 구현 초기값

### 2.1 변경할 수 없는 사용자 확정 요구

| 항목 | 확정 요구 |
| --- | --- |
| 게임명과 저장소 | 클래스 클래시 / Class Clash / YEOMT/Classclash |
| 공통 수업 흐름 | 호스트 방 생성 → 학생 로비 → 퀴즈로 자원 획득 → 게임 운영 → 시상식 |
| 최대 참가 | 사람과 AI 학생을 합해 30명 |
| 진영 | 반드시 2진영 |
| 지도 | 좌우 끝에 넥서스, 상·하 2라인, 넓은 길과 본진 전방 합류 |
| 건물 | 각 팀의 각 라인 일반 타워 2개, 각 넥서스 수호 타워 2개 |
| 승리 | 적 넥서스 파괴 |
| 시간 | 전투 약 10~13분 목표 |
| 출정 | 한 학생당 동시 활성 영웅 1명 |
| 생존 중 | 직접 전투 조작 불가, 퀴즈로 자원 획득 가능 |
| 사망 후 | 정비에서 유지·교체·성장·강화·뽑기·퀴즈·라인 선택 |
| 창고 | 해당 경기에서 뽑은 개인 영웅을 보관, 영웅별 성장 독립 |
| 성장 | 레벨업으로 스킬 해금, 최종 레벨에서 스킬 2개 |
| 퀴즈 | 시작 전 20문제, 전투 중 10문제 묶음, 쿨타임 30초 |
| 뽑기 비용 | 일반 2원, 고급 10원 |
| 전설 | 고급 뽑기에서만 10%, 룬 마법사·고대의 존재·수호령 3명 |
| 미니언 | 팀·라인별 근접 3기와 원거리 4기, 전투 시작 시 첫 스폰 |
| 호스트 | 상단 스코어판, 전체 전장 고정 표시, 모든 액션·이펙트 |
| 학생 | 자신의 영웅을 따라가는 카메라 |
| AI 학생 | 호스트가 로비에서 추가하여 혼자 전체 경기 시험 가능 |
| 아트 | 읽기 쉬운 오리지널 도트 애니메이션, Teamfight Manager 참고 |

‘팀·라인별’ 미니언 편성 및 ‘넥서스당 수호 타워 2개’는 대화의 지도 구조를 구현하는 기준이다. 전체 일반 타워 8개, 수호 타워 4개, 넥서스 2개다.

### 2.2 이번 명세에서 정한 구현용 초기값

아래는 빈칸을 없애기 위한 초깃값이며 사용자 확정 수치와 구별한다. 밸런스 설정으로 분리하고 시험 후 근거와 함께 조정할 수 있다.

| 항목 | 초기값과 목적 |
| --- | --- |
| 정답 보상 | 시작·전투 퀴즈 모두 정답 1개당 1원, 오답 0원 |
| 최초 참가 보장 | 시작 퀴즈 종료 후 일반 영웅 무료 선택권 1회. 0정답도 출정 가능 |
| 일반 확률 | 일반 80% / 고급 20% / 전설 0% |
| 고급 확률 | 일반 30% / 고급 60% / 전설 10% |
| 영웅 수 | 일반 9명, 고급 6명, 전설 3명, 총 18명 |
| 레벨 | 최대 5, Lv.2 첫 스킬, Lv.5 두 번째 스킬 |
| 레벨업 비용 | Lv.1→2 2원 / 2→3 3원 / 3→4 4원 / 4→5 6원 |
| 강화 | 영웅별 최대 3회, 위력 또는 생명, 순서대로 2·4·6원 |
| 사망 대기 | 사망 즉시 정비 진입, 최소 5초 이후 수동 출정 가능 |
| 미니언 주기 | 20초, t=0부터 양 팀·두 라인 동시 생성 |
| 첫 퀴즈 제한 | 기본 제한 없음. 호스트가 미완료 인원을 보고 명시적으로 마감 가능 |
| 첫 출정 준비 | 기본 제한 없음. 전원 준비되면 호스트가 5초 카운트다운 시작 |
| 시간 종료 | 13분 강제 종료 없음. 넥서스 파괴가 정상 종료 |
| 봇 기본 | 표준 프로필, 최대 30명에 포함, 전투 스탯 보너스 없음 |

최소 사망 대기는 자동 부활 타이머가 아니다. 5초가 지나도 출정 버튼을 누르기 전까지 정비에 머문다. 10~13분은 시작 전 퀴즈·로비 시간을 제외한 전투 시간이다.

## 3 전체 단계와 전환

### 3.1 공통 방 단계

~~~mermaid
stateDiagram-v2
    [*] --> LOBBY
    LOBBY --> OPENING_QUIZ: 호스트 시작
    OPENING_QUIZ --> INITIAL_MAINTENANCE: 전원 완료 또는 호스트 마감
    INITIAL_MAINTENANCE --> COUNTDOWN: 전원 준비 후 호스트 시작
    COUNTDOWN --> BATTLE: 5초 경과
    BATTLE --> RESULT: 넥서스 파괴
    BATTLE --> CANCELLED: 호스트 경기 중단
    RESULT --> LOBBY: 새 경기
    CANCELLED --> LOBBY: 새 경기
~~~

호스트 권한이 필요한 전환은 서버가 hostSession을 확인한다. 학생과 AI가 공통 방 단계를 직접 바꾸지 못한다. 상태마다 진입 화면과 재접속 복원 화면이 존재해야 한다. 알 수 없는 단계에서 빈 화면을 보여주는 기본 분기를 금지한다.

### 3.2 학생 개인 상태는 병렬로 관리

전투 상태와 퀴즈 상태를 하나의 변수로 섞지 않는다.

- 전투 상태: WAITING / INITIAL_MAINTENANCE / READY / DEPLOYING / ACTIVE / DEAD_MAINTENANCE / FINISHED.
- 퀴즈 상태: IDLE / ANSWERING / COOLDOWN / OPENING_DONE / LOCKED.
- 연결 상태: ONLINE / RECONNECTING / OFFLINE.
- 화면에서 현재 열린 패널은 서버 게임 상태와 별개로 보관한다.

예: ACTIVE + ANSWERING 상태에서 영웅이 죽으면 DEAD_MAINTENANCE + ANSWERING이 된다. 정답 입력 중인 문제를 닫거나 새 퀴즈로 바꾸지 않는다. 상단에 ‘영웅이 쓰러졌습니다. 퀴즈를 계속 풀거나 정비로 돌아갈 수 있습니다’ 알림만 보여준다. 10문제를 마치면 동일 정비 상태로 복귀한다.

### 3.3 단계별 원자적 처리

- 방 생성: 방 코드·host 권한·기본 퀴즈 설정을 하나의 성공 결과로 반환한다.
- 퀴즈 시작: 명단 잠금, matchId 발급, 이전 경기 개인 자원·영웅·정답·이벤트 제거, 퀴즈 세션 생성.
- 초기 준비 진입: 각 학생 확정 정답 수를 기본 자산으로 반영하고 무료 선택권을 정확히 1회 지급.
- 카운트다운: 팀과 첫 영웅·라인을 잠근다. 첫 선택은 배치 예약이며 아직 살아 있는 전투 엔티티가 아니다.
- BATTLE 경과시간 t=0: 모든 READY 영웅과 첫 미니언 웨이브를 생성한다. 시작 퀴즈부터 흐르던 matchTick은 리셋하지 않고 battleStartTick을 기록하며, 표시 전투 시간만 0에서 시작한다.
- 사망: 해당 activeEntity를 사망 처리한 뒤 activeEntityId를 비우고 deathId와 redeployNotBeforeTick을 갱신한다.
- 재출정: 영웅 소유권·사망 대기·유효한 라인·현재 영웅 부재를 검사하고 1개만 생성한다.
- 정상 종료: 같은 판정 틱의 모든 피해를 정산하고 결과를 한 번 확정한 뒤 입력과 전투를 잠근다.
- 재경기: 룸 참가자·닉네임·AI 프로필·퀴즈 원본만 보존하고 새 matchId를 사용한다. 전투 인스턴스와 성장·골드·쿨타임은 보존하지 않는다.

## 4 호스트와 학생의 화면

### 4.1 입장과 로비

첫 화면의 주 행동은 ‘방 만들기’, ‘참가하기’다. 학생은 방 코드와 닉네임으로 참가하며, 재접속 가능한 경우 ‘이전 참가로 복귀’가 표시된다. 임의의 닉네임만으로 다른 학생 세션을 인수하지 못한다.

호스트 로비에는 방 코드, 참가 링크 복사, QR, 현재/최대 인원, 두 팀 명단, 연결 상태, 퀴즈 설정, ‘AI 추가’, ‘AI로 30명 채우기’, ‘AI 모두 제거’, ‘팀 균형 맞추기’, ‘시작 퀴즈 시작’이 있다. AI는 명단에 AI 표식과 프로필이 보인다. 팀 이동은 드래그뿐 아니라 선택 메뉴로도 가능해야 한다. 사람·AI 합계 최대 30, 기본 팀당 최대 15다. 27명은 14:13으로 배치 가능하다. 시작 퀴즈에 진입한 순간부터 새 학생·AI 추가와 팀 변경은 잠근다. 기존 참가자의 재접속은 허용한다.

### 4.2 호스트 전투 화면

- 상단 고정 스코어판: 팀명·팀 색·넥서스 체력·일반 타워 잔존 수 0~4·수호 타워 잔존 수 0~2·영웅 킬·경과 시간.
- 중앙: 항상 전체 맵. 선택된 영웅을 확대하려고 다른 라인을 화면 밖으로 밀지 않는다.
- 보조 정보: 상·하 라인의 출정 영웅 수, 정비 중 인원, 연결 끊긴 인원, 다음 웨이브까지 시간. 전체맵을 줄이는 상시 큰 패널은 피한다.
- 이벤트: 타워 파괴, 전설 영웅 출정, 넥서스 위험 등 짧은 실제 이벤트만. 존재하지 않은 킬이나 연출용 전황을 만들지 않는다.
- 모든 평타·발사체·스킬 영역·적중·치유·보호막·CC·사망이 표시된다. 숨길 수 있는 것은 중복 숫자·디버그 글자·장식 입자뿐이다.
- 교사 버튼: 전체 소리, 효과음, 방 코드, 수업 일시정지/재개, 경기 중단. 일시정지는 모든 전투·퀴즈·봇 시계를 같이 정지한다. 학생 개인 퀴즈 열기는 전체 경기를 정지하지 않는다.

최소 지원 호스트 화면은 1366×768, 권장 1920×1080이다. 좁은 모바일 호스트에서는 전체맵이 유지되지만 조작은 별도 접이 패널로 이동한다. 기본 화면에 수평 스크롤이 필요하지 않아야 한다.

### 4.3 학생 전투 화면

상단에 이름·팀·출정 영웅·Lv·체력·스킬 해금 및 준비 상태·지갑·퀴즈 진행/쿨타임을 표시한다. 가운데는 영웅 추적 카메라로 주변 전투가 보인다. 조이스틱, 공격 버튼, 이동 명령, 전술 지시 버튼을 제공하지 않는다.

작은 전체맵은 현재 위치와 두 라인 상태를 보여주는 읽기 전용이다. 미니맵을 눌러 영웅 경로를 바꾸지 못한다. 퀴즈 패널은 오른쪽 또는 아래쪽으로 열리고 관전 영역을 남긴다. 작은 휴대폰에서는 문제 패널을 중심으로 하되 상태 바와 사망 알림을 유지한다.

학생이 퀴즈를 푸는 동안 성장·뽑기 버튼을 숨기거나 disabled 처리한다. ACTIVE 상태에서는 직접 API로 호출해도 서버가 거절한다. 생존 중 획득한 돈은 지갑에 즉시 표시되며 다음 정비에서 쓴다.

카메라는 유닛의 발 위치를 부드럽게 따라가고 맵 경계를 넘지 않는다. 자신의 영웅이 사망하면 즉시 정비 UI를 열고 배경에서는 마지막 위치의 0.35~0.65초 사망 모션을 병행한다. 정비 UI를 보기 위해 사망 연출이 끝날 때까지 기다릴 필요는 없다. 퀴즈 입력 중이라면 열린 문제와 입력 포커스를 유지하고 정비 가능 알림만 표시한다.

### 4.4 정비 화면

주요 행동을 한 화면에서 처리한다. 현재 영웅 카드와 전체 창고, 스킬 설명, 레벨업, 위력/생명 강화, 뽑기, 퀴즈, 상·하 라인 선택, 출정 버튼이 필요하다. 라인에는 현재 아군·적군 영웅 수와 남은 타워를 표시한다.

‘그대로 출정’도 비용 없는 명시적 출정이다. 첫 출정 이후 기억하는 기본 영웅·기본 라인은 마지막 사용값이며, 자동으로 다른 영웅을 장착하지 않는다. 출정 직전 카드에 실제 적용 레벨/강화/스킬/체력과 라인을 보여준다. 신규 영웅을 뽑았다고 현재 선택이 갑자기 바뀌면 안 된다.

기본 출정 가능 조건은 영웅 선택, 라인 선택, 최소 사망 대기 종료다. 돈 부족은 출정 자체를 막지 않는다. 퀴즈가 진행 중이라도 닫고 출정할 수 있으며, 미완료 묶음은 동일 문제에서 재개한다. 퀴즈를 반드시 다시 풀어야 부활하는 규칙은 넣지 않는다.

첫 출정 전 ‘준비 완료’를 누르면 READY가 되고 영웅·라인·구매를 잠근다. 카운트다운 전에 ‘준비 취소’를 누르면 INITIAL_MAINTENANCE로 돌아가 다시 선택하거나 구매할 수 있다. 첫 준비 완료는 DEPLOY_HERO를 호출하지 않는다. 첫 영웅은 BATTLE 진입 때 서버가 일괄 생성한다.

### 4.5 미준비 학생이 있을 때 호스트 진행

기본 시작은 전원 준비를 요구한다. 연결이 끊긴 학생 한 명 때문에 수업 전체가 영원히 대기하지 않도록 호스트에게 ‘준비된 인원으로 시작’도 제공한다. 양 팀에 준비된 인원이 최소 1명씩 있어야 하며, 호스트는 아직 준비하지 않은 참가자 명단과 ‘이 학생들은 본진에서 첫 출정을 준비합니다’ 안내를 확인한 뒤 시작한다. 사람이나 AI를 삭제하거나 다른 영웅을 임의 배정하지 않는다.

카운트다운이 끝나면 READY만 t=0에 출정한다. 미준비 참가자는 BATTLE의 DEAD_MAINTENANCE 상태로 옮기되 deathId=null, hasDeployedThisMatch=false로 구분하고 화면에는 ‘첫 출정 준비’라고 표시한다. 무료 선택권을 아직 쓰지 않았다면 이 상태에서 한 번 사용할 수 있다. 그 뒤 정상 정비·라인 선택·수동 출정으로 합류한다. 최초 출정에는 사망 대기 5초를 부과하지 않는다. 한번이라도 출정한 뒤에는 hasDeployedThisMatch를 true로 보존해 이 예외로 다시 무료 선택하거나 즉시 부활하지 못한다.

## 5 퀴즈 상세 규칙

### 5.1 문제 은행

기본 중학교 수준 영어 어휘·문장 의미 문제를 40개 이상 제공한다. 교사가 자신의 문제를 넣을 수 있도록 기존 게임과 같은 붙여넣기 형식을 지원한다.

~~~text
be in charge of | ~을 담당하다 | ~을 기다리다 | ~을 포기하다 | ~에 참여하다
calm | 진정시키다 | 놀라게 하다 | 화나게 하다 | 깨우다
~~~

첫 칸은 문제, 두 번째 칸은 정답, 나머지 3칸은 오답이다. 한 줄 5칸을 기본으로 한다. UTF-8 BOM·공백·빈 줄·Windows 줄바꿈을 처리한다. 빈 문제, 중복 보기, 정답과 동일한 오답, 칸 수 오류, 200자 초과 문제, 80자 초과 보기는 줄 번호와 원인을 표시하고 저장을 막는다. 최대 1000문제, 기본 최소 20개다. 문제 미리보기·문제 수·오류 위치를 제공한다. 교사가 입력한 원문에 HTML이 있어도 실행되지 않는다.

한 묶음 내 중복 문제를 사용하지 않는다. 기본 은행을 포함해 20개 이상 확보하므로 처음 20문제도 모두 달라야 한다. 다음 묶음에서는 미출제 문제를 우선하며 전체 은행 소진 후 다시 섞는다. 각 학생의 문제 순서와 보기 순서는 서버 시드로 섞는다.

### 5.2 시작 퀴즈 20문제

호스트가 시작하면 명단이 잠기고 학생별 20문제 attempt가 생성된다. 한 문제씩 보이고 제출 후 간단한 정오답과 올바른 뜻을 확인한 뒤 다음으로 간다. 다시 고른 답으로 이미 받은 보상을 변경할 수 없다. 시작 정답 수가 초기 골드가 된다. 점수는 사후 클라이언트 합산값이 아니라 서버의 확정 제출 기록으로 계산한다.

전원이 끝나면 준비 단계로 자동 진입한다. 호스트가 먼저 마감하려면 ‘미완료 3명, 남은 문항은 미응답으로 처리’처럼 영향을 보여주고 한 번 확인한다. 이미 확정된 정답 보상은 보존한다. 미응답은 0원이며 정답률 분모는 answeredCount와 totalCount를 나눠 기록한다.

무료 일반 영웅 선택권은 준비 단계 진입 시 1회 지급한다. 학생은 일반 9명 중 1명을 Lv.1로 선택한다. 이는 정답에 따른 자산 차이를 유지하면서 정답 0명의 플레이 불능을 막는 초기 설계다. 기존 선택을 취소해 다른 무료 영웅을 반복 지급받지 못한다.

### 5.3 전투 중 10문제와 30초

- 첫 전투 퀴즈는 BATTLE 진입 즉시 시작 가능하다. 시작 전 20문제는 전투 퀴즈의 30초 쿨타임을 만들지 않는다.
- 퀴즈 시작 요청은 IDLE이거나 기존 attempt 재개일 때만 허용한다.
- 정답 1개 확정마다 1원을 정확히 한 번 지급한다. 묶음 완료 보상이나 만점 추가 재화는 v1에 없다.
- 10번째 답안의 서버 확정 시각부터 30초 후 다음 묶음을 열 수 있다.
- 퀴즈 패널을 닫거나 사망·교체·재접속해도 attempt·문제 순서·제출 답·쿨타임은 유지된다.
- 중간에 닫은 10문제는 동일 묶음을 이어 푼다. 새 쉬운 문제를 얻기 위해 포기·재시작하는 기능은 제공하지 않는다.
- 쿨타임은 서버 시간 기준이다. 표시가 0초여도 서버 판정이 아직 안 되면 ‘곧 시작할 수 있습니다’로 재동기화한다.
- 경기 종료가 확정된 이후 답안은 거절하고 돈을 늘리지 않는다. 종료와 답안이 같은 틱에 들어오면 04의 명령 순서에 따라 판정하고 그 결과를 재전송해도 바꾸지 않는다.
- 정답 여부와 정답 표시는 제출 확정 후 해당 문제에만 반환한다. 다음 문제 정답·서버 문제 은행 전체가 학생에게 전송되면 안 된다.

고정 풀이시간 q초일 때 반복 간격은 q+30초다. q=30초라면 전투 10~13분에서 약 10~13묶음이 가능한 상한이며 실제 관전·정비 시간만큼 줄어든다. 이 수치는 플레이 로그가 아니라 경제 검토용 계산이다.

## 6 자원과 뽑기

### 6.1 재화

화면의 ‘원’은 이 경기에서만 사용하는 학습 재화다. 실제 결제·현금 교환·영구 유료 뽑기는 없다. 경기 시작 자금과 전투 중 재화는 퀴즈 정답에서 생긴다. 킬·미니언 막타·타워 파괴로 추가 개인 골드를 지급하지 않는다. 전투를 잘한 팀의 이득은 전선과 건물이다.

지갑은 0 이상의 정수다. 유일한 수정 경로는 서버의 QUIZ_REWARD, DRAW_PURCHASE, LEVEL_UP, ENHANCE 거래다. 무료 선택권은 별도 1회 플래그다. 서버는 잔액 차감과 결과 지급을 한 트랜잭션으로 확정한다. 새로고침·지연·중복 클릭으로 이중 과금하거나 무료 추가 영웅을 주지 않는다.

### 6.2 티켓 구입과 사용

v1 UI는 ‘일반 뽑기 2원’, ‘고급 뽑기 10원’ 버튼 한 번으로 티켓 구입과 즉시 사용을 원자적으로 처리한다. 사용하지 않은 티켓을 별도 자산으로 쌓을 필요는 없다. 내부 기록에는 ticketType과 cost를 남긴다. 결과가 도착하기 전 재시도는 같은 requestId로 동일 결과를 받는다. 연출을 건너뛰어도 뽑기는 한 번만 일어난다.

초기 확률은 다음과 같다. 천장, 누적 확률 증가, 특정 학생 우대는 v1에 없다.

| 티켓 | 비용 | 일반 | 고급 | 전설 |
| --- | ---: | ---: | ---: | ---: |
| 일반 | 2원 | 80% | 20% | 0% |
| 고급 | 10원 | 30% | 60% | 10% |

등급을 먼저 한 번 추첨한 뒤 해당 풀에서 영웅을 균등 추첨한다. 재추첨 조건과 난수 사용 순서는 서버에서 고정한다. 비용이 낮은 일반 뽑기도 고급 영웅을 얻을 수 있다. 일반으로 전설이 나오는 경로는 없어야 한다.

### 6.3 역할별 풀과 전설 3명의 충돌 해결

전설 3명은 탱커·근접 딜러·마법사에만 있다. 이 상태에서 원거리·지원 역할의 고급 뽑기에 전설 10%를 그대로 약속하면 정의가 불가능하다. 초기 구현은 다음 선택지를 명시적으로 사용한다.

| 뽑기 유형 | 선택 가능한 풀 | 전설 처리 |
| --- | --- | --- |
| 일반 | 전체 / 탱커 / 근접 딜러 / 원거리 / 마법사 / 지원 | 0% |
| 고급 | 전체 / 탱커 / 근접 딜러 / 마법사 | 각 풀에서 10% |
| 고급 원거리·지원 지정 | v1에는 제공하지 않음 | 빈 전설 풀을 재정규화하지 않음 |

고급 전체에서 전설이 나오면 룬 마법사·고대의 존재·수호령 중 균등하게 결정한다. 고급 탱커 지정의 전설은 수호령, 근접은 고대의 존재, 마법사는 룬 마법사다. 일반·고급 등급이 선택되면 선택 역할 내 해당 등급에서 균등 추첨한다. 원거리와 지원의 고급 영웅은 일반 역할 뽑기 또는 고급 전체에서 획득 가능하다.

화면은 선택 풀의 실제 확률과 획득 가능한 영웅을 보여준다. ‘고급 원거리 10% 전설’처럼 존재하지 않는 약속을 표시하지 않는다. 향후 원거리·지원 전설을 추가하면 풀을 확장할 수 있지만 v1의 전설 3명 제한을 임의로 늘리지 않는다. 이 풀 정책은 사용자 확정이 아닌 구현을 위한 명시적 초기 결정이다.

### 6.4 중복과 창고

뽑은 모든 영웅은 별도 ownedHeroInstanceId를 가진다. 같은 성전사가 다시 나오면 별도의 Lv.1 성전사로 창고에 들어간다. 자동 합성, 기존 영웅 레벨 상승, 다른 영웅 강화 이전은 없다. 창고는 이름·등급·역할·레벨·강화로 정렬하고 같은 영웅 복수 보유 수를 표시한다. 카드의 인스턴스 선택은 유지한다.

최대 창고 120개를 안전 상한으로 둔다. 상한이면 구매 전에 차단하고 돈·난수를 소비하지 않는다. v1에는 판매·분해·교환 재화를 추가하지 않는다. 보유 영웅은 경기 종료 후 기록으로만 남고 다음 경기 자산으로 이월되지 않는다.

### 6.5 예시

시작 20문제 중 14개 정답이면 14원과 무료 일반 영웅 1회 선택권을 얻는다. 선택한 성전사를 Lv.2로 올리는 데 2원, 일반 탱커 뽑기 2원, 위력 강화 1회 2원을 쓰면 8원이 남는다. 이후 출정해서 생존 중 10문제 중 7개를 맞히면 15원이 되지만 즉시 강화하지는 못한다. 사망 후 정비에서 그 돈으로 성장·뽑기를 선택한다.

## 7 레벨과 강화

### 7.1 레벨

| 도달 레벨 | 이번 비용 | 누적 비용 | 보유 스킬 |
| --- | ---: | ---: | --- |
| 1 | 0 | 0 | 기본 공격만 |
| 2 | 2 | 2 | 스킬 1 |
| 3 | 3 | 5 | 스킬 1 |
| 4 | 4 | 9 | 스킬 1 |
| 5 | 6 | 15 | 스킬 1·2 |

현재 인스턴스의 레벨만 바뀐다. 레벨은 자동 전투 경험치나 막타로 오르지 않는다. 버튼은 증가 전후 수치와 해금 스킬을 표시하고 잔액 부족·최고 레벨을 설명한다.

### 7.2 강화

영웅별 위력 강화와 생명 강화 합계가 최대 3이다. 첫 번째 강화는 2원, 두 번째 4원, 세 번째 6원이다. 강화 종류별로 각각 3회를 허용하지 않는다.

~~~text
L = level, P = powerEnhancements, V = vitalityEnhancements
0 <= P + V <= 3
maxHP = round(baseHP * (1 + 0.12 * (L - 1)) * (1 + 0.08 * V))
power = round(basePower * (1 + 0.10 * (L - 1)) * (1 + 0.06 * P))
armor = baseArmor + 2 * (L - 1)
~~~

스킬은 power 계수를 사용하며 치유·보호막도 해당 스킬 정의에 따라 함께 성장한다. 이동 속도·공격 간격·공격 범위·CC 지속시간은 레벨과 위력 강화로 늘어나지 않는다. 03에서 따로 적지 않은 성장 계수를 붙이지 않는다. 전설에만 숨은 추가 성장 배율을 주지 않는다.

성장 구매는 초기 준비 또는 사망 후 정비에서만 된다. 따라서 생존 중 체력을 갑자기 채우거나 공격 쿨타임을 초기화하는 경로가 없다. 재출정하면 선택 영웅의 최대 체력으로 출발한다. 정비 중 회복 비용은 없다.

### 7.3 스킬 쿨타임

스킬 준비 시각은 해당 영웅 인스턴스에 저장한다. 사망·창고 보관 중에도 경기 시간이 흐르므로 쿨타임은 자연스럽게 진행한다. 사망·교체·새로고침으로 즉시 준비되지 않는다. 첫 해금 때는 readyAtTick을 현재 경기 틱으로 설정하되, 첫 실제 사용에는 시전 조건·선딜을 적용한다.

같은 영웅 복사본을 번갈아 출정하여 긴 스킬을 초기화하는 우회를 막기 위해 플레이어별 heroDefinitionId+skillId 공유 준비 시각도 보관한다. 사용 가능 시각은 인스턴스와 공유 준비 시각 중 늦은 값이다. 이는 성장 이전이 아니라 동일 학생의 같은 기술 연속 초기화 방지 규칙이다. 서로 다른 영웅의 스킬 준비 시각을 공유하지 않는다. 중복 영웅이 있는 학생에게만 UI에 동일 영웅 기술 대기 표시를 한다.

## 8 지도와 병력

전투 좌표는 1536×768이다. 좌우 대칭이며 가운데 섬을 사이에 둔 넓은 두 길을 사용한다. 실제 좌표·충돌·길찾기는 02의 기준을 따른다. 본진은 넥서스와 수호 타워 뒤의 출정 공간을 갖고, 두 라인은 수호 타워 앞의 넓은 합류 공간에서 만난다. 한쪽 라인만 뚫어도 그 경로로 공성을 진행할 수 있다.

일반 타워는 각 라인 외곽→내곽 순서로 열린다. 한 라인의 내곽 타워까지 파괴하면 두 수호 타워의 공격 잠금이 풀린다. 수호 타워 둘이 모두 파괴되면 넥서스를 공격할 수 있다. 반대쪽 라인 타워를 전부 부숴야만 넥서스에 도달하는 구조는 아니다. 잠금은 상태 표시로 읽히며 잠긴 건물에 AI가 무의미하게 몰려 서 있으면 안 된다.

미니언은 양 진영·상하 라인에서 t=0,20,40초…에 3근접+4원거리씩 동시 생성한다. 한 웨이브 전체는 28기이며 영웅 30명이 모두 출정했다면 첫 웨이브에서 전투 유닛은 58개다. 이전 웨이브 생존분 때문에 숫자는 더 커질 수 있다. 시험은 유닛 58개에만 맞추지 않는다.

모든 활성 영웅은 최초 선택 라인을 따라간다. 전투 AI가 주변 회피·진형·표적 접근을 수행할 수 있지만 중앙을 가로질러 다른 라인으로 임의 이동하지 않는다. 넥서스 전방의 공용 합류 공간에서는 상·하 출정 영웅이 함께 싸울 수 있다. 다음 출정 때 라인을 바꾸는 것은 학생의 정비 선택이다.

## 9 시간과 경기 종료

경과 시간은 BATTLE t=0부터 서버가 센다. 시작 전 문제 풀이·준비·카운트다운은 제외한다. 목표는 표준 30명 경기에서 10~13분에 승부가 나는 것이다. 02의 구조물·미니언 수치를 조절해 검증하며, 단순히 13분에 체력을 비교해 승패를 만들지 않는다.

늦은 경기 완주를 돕는 초기 규칙은 8분 이후 미니언의 구조물 피해 ×1.25, 10분 이후 ×1.5, 12분 이후 ×2.0이다. 시간대별 배율을 현재 값으로 다시 계산하고 곱셈을 누적하지 않는다. 모든 기존·새 미니언에 동시에 적용하며 영웅 상대 피해는 바꾸지 않는다. 이 규칙은 시험 후 조정 가능한 초기 밸런스이며 양 팀에 똑같이 표시한다.

13분이 지나도 넥서스가 살아 있으면 전투는 이어진다. 시간 초과는 튜닝 실패 데이터로 기록한다. 호스트가 수업상 중단할 수 있지만 결과는 ‘중단’이며 승리 팀을 임의로 지정하지 않는다. 두 넥서스가 같은 시뮬레이션 틱에 모두 0이 되면 무승부다. 실제 동시 피해를 처리하기 전에 먼저 순회한 팀을 승리시키지 않는다.

## 10 시상식과 재경기

승리 연출 후 호스트와 학생에게 동일한 확정 결과를 보낸다. 기본 순서는 승리 팀·넥서스 파괴 장면 3초, 팀 전황 4초, 개인상과 자신의 기록이다. 과도한 전체화면 효과가 매 프레임 겹치지 않도록 한다. 학생은 자신의 학습 성과와 전투 기여를 쉽게 찾을 수 있어야 한다.

필수 기록: 시작/전투 퀴즈의 제출·정답 수, 획득·사용 재화, 출정 횟수, 역할별 사용 영웅, 영웅 피해, 구조물 피해, 실제 치유, 실제 흡수 보호막, 실제 받은 피해, CC 기여, 킬·어시스트, 타워 마무리. 과잉 치유와 흡수되지 않은 보호막을 유효 지원량에 더하지 않는다.

시상 기본안:

| 상 | 계산 기준 |
| --- | --- |
| 학습왕 | 확정 정답 수, 동률이면 시도 수 대비 정답률, 완전 동률 공동 수상 |
| 공성왕 | 유효 구조물 피해 |
| 전장의 검 | 적 영웅 유효 피해 |
| 수호의 벽 | 영웅에게 받은 유효 피해 + 아군에게 제공한 실흡수 보호막 |
| 구원의 손 | 아군 영웅 실제 회복량 + 실흡수 보호막 |
| 전술 지원 | 실제 적용한 적 영웅 CC 시간, 겹친 시간 중복 집계 금지 |
| 팀 기여 MVP | 영웅·공성·지원·CC·학습의 정규화 기여 합계 |

MVP는 04의 확정 계산식으로 집계하며 킬 수만으로 결정하지 않는다. 봇은 기록표에 AI 표시가 있고 기본 개인 학생 시상에서는 제외한다. AI만 있는 시험에서는 AI를 포함한 시험용 시상을 보여준다. 기여가 0인 분야는 수상자 없음으로 처리한다. 모든 상을 억지로 서로 다른 사람에게 나눠 주지 않는다.

재경기 버튼은 로비로 돌아간 뒤 새 경기 시작을 준비한다. 직전 승리·사망·쿨타임·지갑·성장·뽑기 결과가 새 경기에 잠시라도 나타나면 안 된다. 같은 방에서 3회 연속 완주해야 한다.

## 11 범위 경계

v1에 반드시 포함할 것은 18명 영웅, 2라인 실제 자동 전투, 호스트/학생 멀티플레이, 편집 가능한 퀴즈, 정비·뽑기·성장, 로비 AI, 시상·재경기, 실제 픽셀 애니메이션이다. 정글, 장비 아이템, 영구 계정 성장, 친구 시스템, 채팅, 과금, 랭크 매칭, 3·4진영, 세 번째 라인, 직접 조작 스킬은 넣지 않는다. 이 경계는 필수 기능을 미루기 위한 축소가 아니라 현재 게임의 초점을 유지하기 위한 것이다.
