# 클래스 클래시 AI와 전투 구현 명세

> 작성 목적: Codex가 이동하는 점이나 체력만 감소하는 모형으로 끝내지 않고, 자동 이동·진형·판단·타격·사망·공성이 실제로 이어지는 플레이어블 전투를 구현한다. 이 문서의 알고리즘과 수치는 구현 기본값이다. 사용자 확정 규칙은 상위 마스터 명세가 우선하며, 밸런스 수치는 자동 경기와 사람이 보는 경기로 조정한다. 목표 경기 시간은 10~13분이며, 아래 수치가 그 시간을 이미 검증했다는 뜻은 아니다.

## 1. 절대 지켜야 하는 전투 규칙

1. 진영은 좌측 A와 우측 B의 두 개뿐이다. 라인은 윗라인과 아랫라인이다.
2. 각 학생이 출정시킬 수 있는 영웅은 동시에 한 명이다. 창고의 다른 영웅은 전장에 존재하지 않는다.
3. 출정한 뒤 학생은 이동, 표적, 스킬, 후퇴, 라인 변경, 강화, 레벨업, 교체를 지시할 수 없다. 학생 화면에서 가능한 능동 행동은 퀴즈 풀이와 관전 UI 조작이다.
4. 사망한 뒤 정비시간에 영웅 교체, 같은 영웅 유지, 레벨업, 강화, 뽑기, 퀴즈, 출정 라인 선택을 수행한다. 학생이 출정 버튼을 눌러야 다시 나온다. 시간 경과에 따른 자동 부활·자동 출정은 구현하지 않는다.
5. 같은 영웅을 다시 내보내도 기존 레벨과 강화는 유지한다. 다른 영웅을 선택하면 그 영웅 인스턴스에 저장된 성장값을 사용한다. 서로 이전하지 않는다.
6. 각 진영의 각 라인에 근접 미니언 3기, 원거리 미니언 4기가 나온다. 첫 웨이브는 전투 시작 시각 0에 생성한다. 이후 20초 주기는 초기 튜닝값이다. 한 웨이브의 전장 전체 신규 미니언 수는 28기다.
7. 각 팀의 각 라인에 일반 타워 2개, 넥서스 입구에 수호 타워 2개를 둔다. 전장 전체는 일반 타워 8개, 수호 타워 4개, 넥서스 2개다.
8. 적 넥서스 파괴가 승리 조건이다. 킬 수, 시간이 끝났을 때의 HP, 보유 골드로 자동 승리를 결정하지 않는다. 호스트의 수업 종료는 별도 중단 결과로 처리한다.
9. 호스트 화면에는 모든 라인의 이동, 평타, 투사체, 스킬, 치유, 보호막, 피격, 사망, 구조물 파괴가 표시되어야 한다. 화면 밖이라고 서버의 전투를 생략하거나 호스트에서 이펙트를 숨겨서는 안 된다.
10. 사람이 맡은 학생과 AI 학생의 영웅은 같은 전투 AI, 같은 수치, 같은 판정식을 사용한다. AI 학생 난이도는 퀴즈·구매·라인 선택 등 관리 판단에만 적용한다.

## 2. 공통 좌표와 시간

### 2.1 월드 좌표

월드 원점은 왼쪽 위, x는 오른쪽, y는 아래쪽이다. 월드 크기는 `1536 × 768`이다. 좌표, 사거리, 속도는 CSS 픽셀과 분리된 월드 단위를 사용한다. 카메라 확대가 판정에 영향을 주어서는 안 된다.

| 항목 | A 진영 | B 진영 |
|---|---:|---:|
| 넥서스 중심 | (92, 384) | (1444, 384) |
| 위쪽 수호 타워 | (220, 324) | (1316, 324) |
| 아래쪽 수호 타워 | (220, 444) | (1316, 444) |
| 영웅 출정 기준점 | (152, 384) | (1384, 384) |
| 윗라인 내부 타워 | (360, 224) | (1176, 224) |
| 윗라인 외부 타워 | (520, 224) | (1016, 224) |
| 아랫라인 내부 타워 | (360, 544) | (1176, 544) |
| 아랫라인 외부 타워 | (520, 544) | (1016, 544) |

윗라인 중심 y는 224, 아랫라인 중심 y는 544다. 직선 구간의 통행 폭은 144, 합류 지대의 폭은 240이다. 지형의 녹색 장식, 도트 그림자, 이펙트는 충돌체가 아니다. 이동 가능한 지형과 장식 지형을 데이터에서 분리한다.

A에서 B 방향 윗라인 기준 경로는 `(152,384) → (300,384) → (380,224) → (1156,224) → (1236,384) → (1384,384)`다. 아랫라인은 경로의 224만 544로 바꾼다. B는 해당 경로를 반대로 사용한다. 두 길이 합쳐지는 장소는 수호 타워의 적 방향 전면이다. 합류점을 한 개의 좌표로 수렴시키지 않고 폭을 가진 통행 영역으로 만든다.

경로는 단순 선분의 배열이 아니라 다음 세 종류의 도형으로 생성한다.

- 라인 구간: 중심 경로를 반지름 72만큼 확장한 캡슐들의 합집합.
- 본진 합류 지대: 중심 y=384, 반높이 120인 넓은 영역과 대각 연결부의 합집합.
- 출정 구역: 넥서스 앞의 안전한 좌우 대칭 영역. 넥서스와 타워의 고체 충돌 반경을 제외한다.

영웅 중심만 길 위에 있으면 되는 방식이 아니다. 해당 영웅의 충돌 원 전체가 이동 가능 영역 안에 있어야 한다. 경로 계산에는 그 영웅 반경만큼 장애물을 확장한 도형을 사용한다.

### 2.2 시뮬레이션 주기

| 처리 | 초기값 | 규칙 |
|---|---:|---|
| 권위 서버 고정 스텝 | 20Hz, 50ms | 게임 시간은 완료된 고정 스텝으로 계산 |
| 전술 AI 재평가 | 5Hz, 200ms | 새 위협·타겟 사망 등 중요 사건에는 즉시 재평가 가능 |
| 이동·충돌·투사체 | 20Hz | AI 재평가 사이에도 기존 명령으로 계속 진행 |
| 렌더링 | 화면 주사율에 따라 최대 60fps 기본 | 서버 두 스냅샷 사이 보간 |
| 타격·스킬 이벤트 | 발생 스텝에서 확정 | 고유 eventId로 중복 표시 방지 |
| 미니언 웨이브 | t=0, 20, 40…초 | 프레임 수가 아니라 서버 게임 시간으로 스케줄 |

느린 탭에서 프레임이 적게 그려져도 공격 횟수, 투사체 이동거리, 퀴즈 쿨타임, 사망 시점은 변하지 않는다. 서버가 잠시 밀리면 밀린 고정 스텝을 순서대로 처리한다. 무제한 따라잡기로 서버를 멈추게 하지 않도록 한 루프당 최대 5스텝을 수행하고 부하 경고를 기록한다. 시간을 통째로 건너뛰거나 피해를 누락해서 따라잡는 방식은 금지한다.

호스트가 수업용 일시정지를 누르면 전투, 퀴즈 30초 쿨타임, 사망 뒤 5초 출정 잠금, 스킬 쿨타임, AI 학생의 사고·답변 시간이 같은 simulation clock으로 함께 멈춘다. 학생이 자기 퀴즈 화면을 열거나 탭을 옮기는 행동은 일시정지가 아니다. 네트워크 접속 유지·보안 토큰 만료 같은 현실 시간 작업은 별도 wall clock을 사용한다.

`MatchState.tick`은 시작 퀴즈에서 matchId를 발급한 뒤 단조 증가한다. BATTLE 진입 때는 tick을 0으로 되돌리지 않고 `battleStartTick`을 기록한다. 화면 경기 시간, 미니언 웨이브, 8·10·12분의 후반 배율은 `(tick - battleStartTick) × 50ms`로 계산한다. 스킬·퀴즈·사망 대기·봇 예약은 절대 tick을 사용한다. 이렇게 해야 초기 준비에서 스킬을 해금한 시각이 전투 시작 때문에 미래로 밀리는 버그가 없다. BATTLE 이전에는 전투 경과 시간과 후반 배율을 계산하지 않는다.

시간 데이터는 부동소수점 초 값을 매 프레임 비교하지 않는다. 콘텐츠를 읽을 때 정수 `durationMs`로 표준화하고 `durationTicks = ceil(durationMs / 50)`으로 올림한다. 230ms 선딜은 5틱=250ms다. 300ms가 부동소수점 오차 때문에 7틱이 되는 구현은 금지한다. 공격주기·선딜·후딜·CC·발사 간격·사망 대기 모두 같은 변환을 쓴다. 명시적인 시각 장식 80ms는 렌더러에서 표현할 수 있으나 판정의 tick을 바꾸지 않는다.

`tick=n`은 완료된 상태의 번호다. 다음 스텝의 모든 명령·사건은 `effectiveTick=n+1`에 귀속하고, 그 스텝이 끝나야 완료 tick이 n+1이 된다. 시전 시작 k, 선딜 W틱이면 impact는 정확히 k+W다. 신규 유닛·발사체는 생성된 tick에 이전 50ms를 이미 이동한 것처럼 적분하지 않는다. 생성 tick 다음 스텝부터 이동한다. 다단히트는 `actionId+hitIndex`별 예정 tick을 각각 한 번 처리한다.

명령을 받는 펌프는 일시정지 중에도 계속 작동한다. 정지 중 RESUME_ROOM, CANCEL_MATCH, 세션 복구가 막히면 안 된다. 게임 시간만 정지하며, 허용하지 않는 게임 변경 요청은 ROOM_PAUSED로 명시적으로 거절한다. 일시정지 중 여러 관리 명령을 처리할 때는 tick 대신 serverReceivedSerial로 선후를 구분한다.

재현을 위한 전투 난수는 seed가 있는 서버 RNG를 사용한다. 전투 RNG, 퀴즈 순서 RNG, AI 학생 관리 RNG의 스트림을 분리한다. 실서비스 뽑기는 04의 서버 CSPRNG를 사용하고 확정한 추첨 결과를 durable 명령 로그에 저장하여 복구 때 재추첨하지 않는다. 자동 경기·경계값 테스트에서만 뽑기 RNG에도 별도 seed 스트림을 주입한다. 퀴즈 버튼을 많이 누른 학생 때문에 전투 난수 순서가 바뀌어서는 안 된다.

## 3. 데이터와 권한 경계

### 3.1 영웅 인스턴스와 출정 생명 분리

`OwnedHero`는 창고에 보관되는 영구적인 경기 내 소유 정보다. `CombatUnit`은 한 번의 출정 동안만 살아 있는 전투 실체다.

```text
OwnedHero
  ownedHeroInstanceId, ownerPlayerId, heroDefinitionId
  level, enhancementChoices[], acquiredAt
  skillReadyAt[2]             # 경기 시간 기준, 사망/교체로 초기화하지 않음

PlayerCombatState
  sharedSkillReadyAt[heroDefinitionId][skillId]
  redeployNotBeforeTick       # 사망 시 currentTick + 100틱

CombatUnit
  entityId, deploymentId, ownedHeroInstanceId, ownerPlayerId, team
  deploymentLane             # TOP 또는 BOTTOM, 생존 중 불변
  currentZone                # BASE_A, TOP, BOTTOM, BASE_B
  position, previousPosition, velocity, facing
  radius, hp, maxHp, armor, attackPower, moveSpeed
  targetId, targetChosenAt, goal, reservedAttackSlot
  actionState, actionId, actionStartTick, impactTick, recoveryEndTick
  statuses[], shieldLayers[], skillState
  damageLedger, stats
```

`deploymentId`는 매 출정 새로 발급한다. 동일한 ownedHeroInstanceId라도 이전 출정의 타격·치유·사망 이벤트를 새 출정에 적용하지 않는다. 영웅 선택·강화 명령에는 현재 matchId와 expectedPhaseRevision을 담고, 경제 변경은 ledgerRevision을 함께 검사한다. 재출정에는 현재 deathId도 확인해 이전 사망의 늦은 명령을 거절한다. 출정 처리와 동시에 학생 상태를 `DEPLOYING`으로 바꾸고 activeEntityId를 점유한 뒤 등장 완료 시 `ACTIVE`로 바꾼다. 연달아 들어온 두 번째 출정 요청은 기존 결과를 반환하고 새 영웅을 추가하지 않는다. 학생 상태 enum은 01·04와 동일한 이름을 사용한다.

### 3.2 서버가 계산해야 하는 항목

표적, 경로, 공격·스킬 선택, 시작과 종료 시각, 피해, 치유, 실드, CC, 쿨타임, 사망, 골드, 퀴즈 채점, 뽑기, 승패는 서버가 확정한다. 클라이언트가 보내는 마우스 좌표나 카메라 좌표를 전투 의도로 해석하지 않는다. 학생 API에는 이동·공격·스킬 명령 자체를 만들지 않는다.

렌더러는 확정된 전투 상태를 읽어 애니메이션을 재생한다. 이펙트가 사라지거나 음량을 줄여도 피해·상태효과는 그대로다. 렌더러의 animationend가 도착해야 피해를 적용하는 구조는 금지한다.

## 4. 한 스텝의 실행 순서

순서를 명시적으로 유지해 같은 입력과 seed가 같은 결과를 만들게 한다.

1. 스텝 시작에 그때까지 도착한 명령 배치를 고정한다. serverReceivedSerial 순으로 권한·현재 단계·개인 상태를 검사하여 출정, 퀴즈 보상, 정비 구매를 처리한다. 이후 도착한 명령은 다음 배치로 넘긴다.
2. 만료된 상태효과·보호막을 정리하고, 예정된 웨이브·출정 유닛을 생성한다.
3. 그 스텝 시작 시 살아 있는 유닛 목록으로 읽기 전용 전장 인식을 만든다.
4. 재평가 시각인 유닛의 AI가 목표와 행동 의도를 생성한다. 이 단계에서 상대 HP를 직접 깎지 않는다.
5. 새 시전·평타의 시작 여부를 검사하고 공격 자리 예약을 갱신한다. 과거에 시작한 동작의 impactTick을 현재 시간으로 매번 덮어쓰지 않는다.
6. 제어 불가·돌진·넉백·일반 이동을 우선순위에 따라 적분하고 지형·유닛 충돌을 해결한다.
7. 이전 스텝부터 존재한 발사체를 이동시키고 선분 충돌을 검사한다. 이번 스텝에 발사되는 발사체는 그 발사 사건의 위치에 생성하고 다음 스텝부터 이동한다.
8. impactTick에 도달한 평타, 스킬, 발사체, 지속 장판의 적중 후보를 모은다.
9. 각 사건의 명중 조건·무적·구조물 보호 조건을 검사한다. 같은 스텝의 유효 피해와 치유를 일괄 계산한다.
10. 피해에 따른 CC·피격·어그로·통계를 기록하고, HP가 0 이하인 유닛과 구조물을 사망 처리한다.
11. 사망에 의한 학생 정비 진입, 타워 단계 해금, 넥서스 파괴에 의한 경기 종료를 확정한다.
12. 새로운 스냅샷과 순서가 있는 전투 이벤트를 만든다.

명령 배치에서 CANCEL_MATCH가 먼저 확정되면 뒤의 답안·구매·출정을 거절하고 해당 스텝의 전투도 진행하지 않는다. 답안이 먼저 확정된 뒤 CANCEL_MATCH가 왔다면 이미 확정한 보상은 취소 결과의 기록에 남는다. 정상적인 넥서스 파괴는 위 11단계에서 결정하므로 그 스텝 시작에 유효하게 처리한 답안 보상은 포함한다. 파괴 확정 이후의 다음 배치 요청은 종료 상태로 거절한다. 이 순서는 명령 재전송이나 재접속으로 바뀌지 않는다.

같은 스텝에 이미 impact가 성립한 공격은 그 공격자의 동시 사망 때문에 소급 취소하지 않는다. 서로 마지막 일격을 교환하면 둘 다 사망할 수 있다. 두 넥서스가 같은 스텝에 파괴되면 무승부로 기록한다. 먼저 배열에 있던 팀만 승리시키지 않는다.

같은 스텝에서 발생한 기절도 이미 성립한 다른 impact를 소급 취소하지 않는다. 기절이 이전 스텝에서 적용되어 현재까지 남아 있다면 준비 중 공격을 취소한다. 충돌 보정은 동시에 계산한 위치 의도로부터 양쪽에 대칭 배분한다. 공격 자리 예약의 완전 동률은 고정 팀 순서가 아니라 경기 seed와 해당 예약 회차를 사용한 안정적인 순번으로 푼다. 매 프레임 새 난수를 뽑아 위치를 흔들지 않는다.

피해와 치유가 같은 스텝에 발생하면, 스텝 시작 HP와 그 스텝의 피해·치유 합계로 최종 HP를 계산한다. 예: 시작 HP 50, 피해 70, 유효 치유 30이면 최종 HP 10이다. 이미 이전 스텝에 사망 확정된 영웅은 치유로 부활하지 않는다. 보호막 소비와 초과 피해 배분은 아래 정산 순서를 따른다.

### 4.1 같은 스텝 안의 효과와 통계 정산

동일한 impact tick의 사건은 단순 entity 배열 순서로 HP를 즉시 바꾸지 않는다. 각 대상별로 다음 순서를 따른다.

1. 스텝 시작에 살아 있는 대상만 후보로 한다. 기존 스턴·침묵 등으로 이미 중단된 시전은 impact 목록에 넣지 않는다. 이미 성립한 투사체 충돌은 시전자 사망과 별개다.
2. 이번 스텝에 완성된 보호막·방어 버프를 유효 대상에게 적용한다. 정화는 이 단계 이전부터 있던 해제 가능한 부정 상태를 제거하며, 아직 적용하지 않은 이번 스텝의 신규 CC까지 막는 면역을 주지 않는다. 같은 보호막 출처의 여러 갱신은 작은 eventSeq부터 적용한다.
3. 모든 공격에 구조물 잠금, 스킬 구조물 배율, 방어력, 피해 감소를 적용한다. 각 공격의 완화 후 피해를 `D_i`, 합계를 `D`로 둔다.
4. 현재 유효한 보호막 총량과 D 중 작은 양 `S`를 흡수한다. 보호막 층은 빠른 expiresAt, 다음 빠른 생성 eventSeq 순으로 소모한다. 동일 tick의 공격자별 실드 흡수 기여는 `S × D_i/D`로 나눈다.
5. HP로 들어갈 피해는 `X=D-S`다. 같은 tick 치유 요청 합계를 H, 시작 체력을 HP0, 최대 체력을 M이라고 할 때 `effectiveHeal=min(H,max(0,M-HP0+X))`다. 최종 HP는 `clamp(HP0-X+effectiveHeal,0,M)`다. 같은 tick의 유효 치유는 각각의 요청 치료량 비율로 나누어 기록한다.
6. 실제 HP 피해 총량은 `effectiveHpDamage=min(X,HP0+effectiveHeal)`다. 공격자별 HP 피해는 `effectiveHpDamage × D_i/D`로 기록한다. D=0이면 각 피해 기여는 0이다. 실드 흡수와 HP 피해를 같은 통계에 중복 합산하지 않는다.
7. 이번 tick의 신규 CC·표식·피격 상태를 eventSeq 순으로 적용한다. 기존 정화에 없던 이번 tick 신규 CC는 정상 적용되며 hardCC 연속 상한·면역 정책은 여전히 검사한다. 최종 HP가 0인 대상의 상태효과는 사망 처리에서 제거한다.
8. 최종 HP가 0인 영웅마다 사망을 정확히 한 번 확정한다. 해당 tick의 유효 HP 피해를 sourceDeploymentId별로 합친 뒤 가장 큰 공격 주체를 마무리자로 정한다. 타워·미니언은 sourceEntityId로 묶는다. 동률이면 각 묶음에서 가장 빠른 피해 eventSeq를 비교한다. 타워·미니언이 마무리자면 해당 팀의 영웅 처치 수만 1 증가하고 개인 킬은 지급하지 않는다. 영웅이면 해당 ownerPlayerId의 개인 킬도 1 증가한다.

예를 들어 HP 100인 대상에게 같은 tick에 A가 완화 후 90, B가 60의 피해를 주고 치유·실드가 없다면 총 유효 HP 피해 100을 A 60, B 40으로 기록한다. A가 마무리자가 되며 죽음과 팀킬은 한 번만 기록한다. A와 B의 배열 순서를 바꿔도 결과가 달라지지 않는다. eventSeq는 명령 수신 순서·예약 사건 순서를 보존하는 서버의 단조 번호이며 브라우저 도착 순서가 아니다.

## 5. 영웅 행동 상태머신

| 상태 | 진입 조건 | 할 수 있는 행동 | 종료 조건 |
|---|---|---|---|
| SPAWNING | 출정 승인 | 등장 애니메이션, 충돌 자리 확보 | 0.35초 뒤 ADVANCE |
| ADVANCE | 전투 상대 없음 | 선택 라인 경로를 따라 진형 이동 | 유효 상대 감지, 목표 도달 |
| APPROACH | 타격 가능한 표적은 있으나 사거리 밖 | 예약 자리로 접근 | 사거리 진입, 위험, 표적 무효 |
| HOLD | 공격 대기·자리 대기 | 바라보기, 소폭 대형 복원 | 공격 가능 또는 목표 변경 |
| WINDUP | 평타·스킬 시작 승인 | 공격 준비 동작, 허용된 스킬만 이동 | impact 또는 취소 |
| RECOVERY | 타격 후 | 후딜 동작; 이동 허용 여부는 공격 정의 | recoveryEndTick 도달 |
| REPOSITION | 역할상 적정 거리 미달·과밀·측면 정렬 | 제한된 위치 이동 | 적정 위치, 최대 1.2초 |
| RETREAT | 위험 지역에서 짧은 전술 후퇴 필요 | 아군 방향 안전 지점으로 이동 | 안전 확보, 최대 후퇴거리 |
| CONTROLLED | 기절·속박·넉백 등 | 상태별 허용 동작만 | 효과 종료 |
| DEAD | 최종 HP ≤0 | 사망 연출; 전투 실체 제거 | 시각 연출 종료 |

상태는 여러 boolean을 모순되게 켜는 방식으로 구현하지 않는다. `WINDUP && moving && stunned && dead`처럼 동시에 성립하는 상태를 막는다. 이동 허용, 공격 허용, 스킬 허용은 주 상태와 상태효과에서 일관된 함수로 계산한다.

`RETREAT`는 학생의 수동 귀환이 아니다. 사거리 재확보·과도한 타워 진입 회피를 위한 짧은 전술 행동이다. 본진까지 도망가 HP가 완전히 회복되는 귀환 시스템은 첫 버전에 없다. 생존 영웅이 창고에 들어가거나 영웅을 교체하지 않는다.

## 6. 이동과 대형

### 6.1 라인을 선이 아닌 면으로 사용하기

각 유닛은 경로를 따라 진행한 길이 `s`와 경로 중심에 대한 가로 오프셋 `lateral`을 가진다. 일반 이동 목표는 경로의 진행 방향으로 48~80만큼 앞선 점에 lateral을 더한 지점이다. 정해진 y 한 줄에 모두 세우지 않는다.

출정 때 역할별 기본 대형 슬롯을 결정한다. 같은 웨이브의 미니언은 앞줄 근접 3기를 lateral `-28,0,+28`, 그 뒤 30만큼 떨어진 원거리 4기를 `-42,-14,+14,+42`에 둔다. 영웅은 해당 라인의 아군 분포에서 빈 슬롯을 선택한다. 탱커는 전열, 근접 딜러는 전열의 양옆, 원거리·마법·지원은 뒤쪽을 사용한다.

전열 기준은 살아 있는 아군의 진행 거리 상위 집단과 실제 접전 위치를 통해 계산한다. 한 명이 깊이 돌진했다고 팀 전체 전열 기준을 그 위치로 바꾸지 않는다. 아군 진행 거리의 70퍼센타일을 기본값으로 하고, 전투 중인 아군의 중앙값을 보조값으로 사용한다. 관측된 유닛 수가 1~2명이면 단순 중앙값으로 폴백한다.

| 역할 | 접전 전 기본 위치 | 접전 중 움직임 |
|---|---|---|
| 탱커 | 전열 기준 +0~18 | 안전한 선두 자리 확보, 아군과 단절 금지 |
| 근접 딜러 | 전열 기준 -8~12, 측면 | 공격 자리 확보, 사거리 밖 적을 짧게 추적 |
| 원거리 | 전열 기준 -70~-110 | 사거리 유지, 위협 접근 시 짧은 후퇴 |
| 마법 | 전열 기준 -60~-100 | 적중 가능한 시전 위치, 후열 유지 |
| 지원 | 전열 기준 -65~-95 | 아군 치료·보호 대상이 사거리 안에 드는 위치 |

플러스 방향은 해당 팀이 적 본진으로 전진하는 방향이다. 몸이 큰 탱커를 보기 위해 과도하게 앞서 보내거나, 지원이 단지 이동속도가 빠르다는 이유로 선두를 달리게 해서는 안 된다.

### 6.2 경로 탐색

전략 경로는 선택된 라인의 waypoint corridor를 사용한다. 지역 장애물 우회는 16 단위 셀의 navigation grid 또는 동등한 navmesh를 이용한다. 매 프레임 모든 유닛에 A*를 실행하지 않는다. 다음 경우에만 지역 경로를 다시 만든다.

- 새로운 공격 자리나 구조물 목표를 받았다.
- 목표까지 직선 이동이 고체 구조물에 막혔다.
- 0.8초 동안 유효 진행이 4 단위 미만이다.
- 타워가 파괴되어 이동 가능 지형이 바뀌었다.

한 번에 최소 0.2초는 기존 경로를 유지하되, 경로가 물리적으로 불가능해졌거나 사망·강제이동이 발생하면 즉시 폐기한다. 외부 타워가 살아 있으면 그 뒤의 적을 쫓아 내부 타워 사이로 지나가는 경로를 허용하지 않는다. 진행 제한선은 현재 공격 가능한 구조물의 적쪽 표면에서 64 단위 뒤로 둔다.

### 6.3 부드러운 충돌과 밀집 해소

영웅 충돌 반경의 기본값은 12, 큰 탱커는 14~16, 미니언은 7~8이다. 실제값은 영웅 정의에서 읽는다. 아군끼리 완전히 무시하고 중첩시키거나, 완전한 벽으로 만들어 한 명 때문에 10명이 멈추는 방식 모두 금지한다.

이동 속도 벡터는 목표 방향, separation, 지형 회피를 합쳐 구한다. separation은 이웃 간 목표 거리보다 가까울 때만 작동한다. 처음 적용할 가중치는 목표 이동 1.0, separation 0.65, 지형 회피 1.6이다. 최종 속도는 moveSpeed를 초과하지 않는다. 공격 windup 중인 유닛의 밀림 저항을 높여 주변 이동 때문에 공격 준비가 계속 실패하지 않게 한다.

고정 스텝마다 가까운 이웃을 공간 해시로 조회한다. 이웃 탐색 셀 크기 64, 분리 반복은 최대 3회다. 강제이동이 아닌 분리 보정은 스텝당 3단위를 넘지 않게 한다. 아직 약간 중첩됐으면 다음 스텝에서 해결한다. 화면에서 순간이동처럼 보이는 큰 위치 보정을 정상 이동에 사용하지 않는다.

영웅 둘이 0.8초 이상 서로 마주 보고 막혔으면 짧은 회피 우선권을 부여한다. 우선권은 경기 seed와 두 entityId의 순서 없는 쌍으로 결정하고 0.6초 동안 유지한다. 한쪽은 길 안쪽의 빈 측면으로 20~32단위 비켜서고 다른 쪽은 기존 방향을 유지한다. 매 스텝 양쪽이 같은 방향으로 춤추는 현상을 막는다.

### 6.4 정체 복구

정체 판정은 기대 이동이 있는데 최근 0.8초 동안 이동거리가 4 미만인 경우다. 평타 후딜, 적정 사거리에서의 HOLD, CC, 의도된 대기에는 적용하지 않는다.

1. 현재 공격 자리의 점유를 확인하고 더 가까운 빈 자리로 바꾼다.
2. 아군에게 막혔다면 빈 측면으로 24~40단위 우회한다.
3. 지형에 막혔다면 local path를 재탐색한다.
4. 2초 이상 해결되지 않으면 현재 목표를 포기하고 같은 라인의 다음 유효 목표를 선택한다.
5. 5초 이상이면 디버그 오류와 리플레이 마커를 남긴다. 정상 경기에서 숨은 순간이동으로 덮지 않는다.

## 7. 전장 인식과 표적 선정

### 7.1 인식 범위

전장 자체에 안개는 두지 않지만, 영웅의 지역 전투 판단은 주변 300 단위와 같은 라인의 전방 상황을 사용한다. 전체 맵의 가장 약한 적을 알고 반대 라인까지 쫓아가지 않는다. 자기 선택 라인과 양 본진 합류 지대가 행동 가능 영역이다. 본진 합류 지대에서는 두 라인에서 들어온 적을 모두 상대할 수 있다.

인지 스냅샷에는 가까운 적, 가까운 아군, 공격 가능한 구조물, 위험 장판, 현재 타워 어그로, 통행 가능 지형, 아군 전열 위치, 각 후보의 현재 점유된 공격 자리를 포함한다. 해당 스냅샷은 같은 AI 평가 주기의 유닛들이 공유한다. 앞서 처리된 유닛이 HP를 깎은 결과 때문에 뒤 유닛의 표적이 바뀌는 순서 편향을 막는다.

### 7.2 유효 표적

다음 조건을 먼저 만족한 후보만 점수화한다.

- 살아 있고 같은 경기이며 적 진영이다.
- 무적·비대상 상태가 아니거나 해당 효과를 무시하는 스킬이 명시되어 있다.
- 배정 라인 또는 현재 본진 합류 지대에 있다.
- 접근 경로가 있고 최대 추적 제한 안에 있다.
- 구조물은 현재 해금된 공성 목표다.

지원의 치유·보호·정화 후보는 아군으로 따로 구한다. 공격 표적과 지원 표적을 하나의 필드에 덮어쓰지 않는다.

공격 표적이 있다고 무조건 APPROACH로 전환하지 않는다. `canPursueTarget`은 해당 공격 자리까지 가도 역할상 허용된 대형·추적 범위가 유지되는지 추가 검사한다. 지원은 치료·보호할 아군을 사거리 밖에 두는 공격 추적을 하지 않는다. 근접 지원인 수도승은 보호할 후열 아군 앞 20~40단위의 호위 지점을 중심으로 반경 60 안에서 공격 자리를 찾는다. 이 범위 밖 적을 때리려고 탱커 앞까지 달려가지 않는다. 보호 대상이 없을 때는 같은 라인의 아군 전열 뒤 위치를 폴백으로 사용한다. 영웅별 명시된 이동 성향은 공통 역할 기본값보다 우선하지만 지형·라인 잠금·추적 상한은 유지한다.

### 7.3 평타 대상 점수

다음은 초기 알고리즘이다. 각 요소는 0~1로 정규화한다.

```text
score = 30 * 접근성
      + 25 * 현재 공격 가능
      + 18 * 현재 표적 유지
      + 18 * 후열 아군에 대한 즉시 위협
      + 10 * 적은 잔여 HP
      + 역할별 우선도
      - 25 * 추가 이동 위험
      - 15 * 공격 자리 혼잡
```

접근성은 `clamp(1 - pathDistance/300, 0, 1)`이다. 현재 공격 가능은 유효 사거리·시야선 안이면 1이다. 추가 이동 위험에는 적 타워 사거리 진입, 아군 전열에서 지나치게 떨어짐, 이동 불가 지형이 포함된다. 혼잡은 예약 자리 수와 실제 근접 접근 가능성을 사용한다.

역할별 보정의 시작값은 탱커가 아군 후열을 위협하는 적 +15, 근접 딜러가 도달 가능한 적 영웅 +10, 원거리·마법이 안전한 거리에서 공격 가능한 영웅 +8이다. 미니언을 무조건 무시하지 않는다. 적 영웅에게 접근하려면 적 미니언 사이를 긴 거리 통과해야 할 경우 가까운 미니언부터 제거한다.

현재 표적을 바꾸는 기준은 새 후보 점수가 기존 후보보다 20% 이상 높고, 0.3초 이상 유지된 경우다. 현재 표적 사망·비대상·접근 불가, 강한 생존 위협, 구조물 해금 변화는 즉시 교체할 수 있다. 공격 windup이 시작됐으면 표적이 유효한 한 그 공격을 마친다.

### 7.4 추적 제한

영웅의 일반 추적은 최초 접전 위치에서 전방 160, 후방 100까지다. 같은 표적 추적은 2.5초 후 재판단한다. 스킬 돌진은 스킬 정의의 별도 최대 거리 안에서만 허용한다. 적이 반대 라인으로 이동했거나 목표까지의 길이 타워 뒤로 깊어지면 추적을 중단한다.

추적 중 더 가까운 유효 적이 공격할 수 있는 위치에 들어왔고 기존 적까지의 도달 시간이 1.2초를 넘으면 가까운 적으로 바꾸는 것을 우선한다. 아무도 치지 못하고 빠른 적을 계속 쫓는 장면을 방지한다.

## 8. 공격 자리와 근접 전투

### 8.1 거리 정의

모든 공격과 스킬의 기본 사거리는 두 충돌체 표면 사이 거리로 통일한다.

`gap(a,b) = max(0, length(a.position-b.position) - a.radius - b.radius)`

중심 거리만으로 사거리를 정의하면 반경이 큰 타워를 근접 영웅이 공격할 수 없는 버그가 생긴다. 영웅 스탯의 근접 사거리 10~20은 이 gap 기준이다. UI와 데이터 문서에도 같은 정의를 적용한다. 원형 장판은 장판 중심에서 대상 충돌 원의 표면까지 거리를 판정하고, 부채꼴·직사각형은 대상 충돌 원과 도형의 교차 여부를 계산한다.

### 8.2 공격 자리 예약

근접 유닛이 표적의 중심으로 걸어가게 하지 않는다. 공격 링의 반지름은 `자기 반경 + 표적 반경 + max(0, attackRange - 3)`이다. 3단위는 사거리 안쪽 여유다. 이 여유를 더하면 gap이 사거리를 초과해 공격을 시작하지 못하므로 반드시 뺀다. 기본 8방향 후보를 만들고, 넓은 구조물은 12~16개를 사용한다.

각 후보에 대해 이동 가능한 지형, 다른 아군의 예약, 현재 적의 위치, 이동 거리, 아군 방향에서 접근하는 각도를 검사한다. 자기 진영 쪽 반원과 양 측면의 후보를 우선한다. 이미 공격 중인 유닛의 자리를 빈 슬롯처럼 빼앗지 않는다. 예약은 0.6초, 실제 공격 중이면 갱신한다.

자리 선택 점수는 `-pathDistance - 2×collisionPenalty - 40×towerDanger + 12×현재자리유지`를 기본으로 한다. 모든 근접 자리가 찼으면 그 표적에게 원을 그리며 몰려드는 대신 다른 근처 적, 미니언, 해금된 구조물을 고른다. 유효한 다른 목표도 없으면 한 걸음 뒤 HOLD로 기다린다.

공격 링은 표적이 크게 이동했을 때 재계산한다. 표적이 스텝당 1~2단위 움직였다는 이유로 모든 공격자가 반대편 자리로 바뀌지 않는다. 같은 슬롯의 각도 번호를 최대한 유지한다.

### 8.3 평타 실행

평타는 반드시 `준비 동작 → 적중 사건 → 후딜 → 다음 공격 가능` 네 시점을 가진다. 공격 주기가 1초라고 체력만 1초마다 깎으면 안 된다.

평타 `attackInterval`은 두 공격의 시작 사이 최소 간격이다. 후딜이 그 간격의 나머지 전체를 잠그는 것은 아니다. 별도 지정이 없는 기본 평타의 후딜은 `ceilTick(min(0.30초, 0.20 × 현재 attackInterval))`이다. 예를 들어 궁수는 주기 1.10초, 선딜 0.30초, 후딜 0.25초이므로 0.55초부터 이동·새 스킬 판단이 가능하고 다음 평타 시작은 1.10초부터다. 후딜이 끝나기 전에는 스킬 정의가 허용한 명시적 예외만 끼어들 수 있다. 허용 예외가 있어도 기존 nextBasicReadyTick을 초기화하지 않는다.

```text
canStartAttack(unit, target):
  alive && !hardCC && action permits attack
  && nowTick >= nextBasicReadyTick
  && target valid
  && gap(unit,target) <= attackRange
  && valid line of attack

startAttack:
  actionId = newId()
  actionState = WINDUP
  targetId = chosen target
  actionStartTick = nowTick
  impactTick = nowTick + windupTicks
  recoveryEndTick = impactTick + recoveryTicks
  nextBasicReadyTick = nowTick + attackIntervalTicks
  emit ATTACK_STARTED(actionId, targetId, timings)

at impactTick:
  if attack is melee:
    validate target alive, range plus small tolerance, attack shape
    enqueue damage and HIT effect at real contact point
  if attack is ranged:
    create projectile from weapon socket with projectileId
  actionState = RECOVERY
```

기본 근접 평타의 적중 허용 오차는 gap 6, 원거리 발사 시 표적 사거리 허용 오차는 8이다. 실제 적중 거리가 크게 벗어난 공격을 무조건 맞게 처리하지 않는다. 근접의 경우 적이 준비 중 도망가 유효 범위를 벗어나면 헛손질이 발생한다. 이 경우 공격 간격은 소모한다.

## 9. 원거리와 지원의 움직임

### 9.1 원거리 거리 유지

원거리의 선호 간격은 사거리의 78~92%다. 표적이 사거리 안에 있으면 공격 가능한 상태를 우선한다. 적이 너무 가까워졌을 때만 재배치한다. 쿨타임마다 의무적으로 뒤로 물러나는 규칙은 넣지 않는다.

위협 반경은 `max(55, enemyMoveSpeed × 0.7 + enemyMeleeRange)`다. 근접 적이 이 범위에 들어왔고 아군 전열이 그 사이를 막지 못하면, 적 반대 방향과 아군 전열 뒤 방향을 합친 방향으로 최대 45단위 이동한다. 한 번의 연속 후퇴는 1.2초, 이전 접전 위치에서 최대 110단위로 제한한다. 그 뒤 다시 사거리·대상·전열을 평가한다.

기본 평타 windup 중에는 적이 가까워졌다는 이유만으로 공격을 취소하지 않는다. 이미 발사한 공격은 후퇴 중에도 계속 이동한다. 지원·마법사의 긴 스킬 준비는 스킬 정의에 따른 이동 잠금과 취소 조건을 사용한다.

### 9.2 지원 포지셔닝

지원 영웅은 가장 멀리 나간 아군 한 명을 무조건 따라가지 않는다. 같은 라인의 아군 중 최소 2명 또는 중요 영웅 1명을 지원 사거리 안에 두는 위치를 선택한다. 후보는 현재 위치, 아군 전열 뒤쪽, 가장 위험한 아군의 후방, 두 치료 후보의 중간 후방 지점이다.

후보 위치 점수는 치료·보호 대상 포함 수, 자신의 안전, 아군과의 연결, 공격 또는 스킬 사거리로 계산한다. 적 타워의 어그로를 받는 아군을 치료하려고 지원까지 타워 정면으로 깊이 들어가는 행동은 위험 페널티로 막는다.

### 9.3 단독 생존

주변 아군이 모두 죽었다면 원거리·지원은 자기 라인의 다음 아군 웨이브 방향으로 최대 180단위 후퇴할 수 있다. 이때 적 넥서스가 한두 번의 유효 공격으로 파괴 가능하고 자기 생존 예상 시간이 충분하면 끝내기를 시도한다. 모든 영웅이 아무 이유 없이 본진으로 복귀하지 않는다.

## 10. 스킬 AI 공통 계약

각 영웅은 최고 레벨에서 정확히 두 스킬을 가진다. 일반 평타는 별도다. 액티브 스킬은 사용자가 누르는 버튼이 아니라 AI가 조건을 보고 실행한다. 전설 영웅의 고유 시각 효과가 자동으로 세 번째 전투 스킬을 추가하는 근거가 되지 않는다.

각 스킬 정의에는 최소 다음 필드를 둔다.

```text
id, unlockLevel, cooldown, range, targetType
castTime, impactOffsets[], recoveryTime
canMoveDuringCast, interruptPolicy
shape, projectile, damage, healing, shielding
statusEffects, structureMultiplier
usageConditions, targetScoring, effectId, animationId
```

스킬을 쓰려면 해금 레벨, 쿨타임, 행동 가능 상태, 유효 표적, 사거리, 지형 및 최소 효과 조건을 모두 만족해야 한다. 미해금 스킬은 AI 후보에 들어가지 않는다.

스킬 쿨타임은 시전 시작 때 `OwnedHero.skillReadyAt`과 `PlayerCombatState.sharedSkillReadyAt[heroDefinitionId][skillId]`에 모두 기록한다. 사용 가능 시각은 두 값 중 늦은 값이다. 기절이나 사망으로 취소되어도 소모한다. 죽었다가 다른 영웅을 거쳐 돌아왔다고 쿨타임을 초기화하지 않는다. 같은 영웅을 중복 뽑아 다른 인스턴스로 교체하는 방법으로도 초기화할 수 없다. 다른 종류의 영웅의 다른 스킬까지 공유해 잠그지는 않는다. 경과한 경기 시간에 따라 자연히 쿨타임이 끝나는 것은 허용한다. 시작 스킬 레벨 해금 직후 정비 중에는 시전하지 않는다.

### 10.1 시전 종류별 공통 사용 조건

| 종류 | 사용 가능한 조건 | 금지해야 하는 낭비 |
|---|---|---|
| 단일 피해 | 유효 적이 시전·적중 범위에 있음 | 이미 죽은 적, 보호 중인 구조물 |
| 광역 피해 | 영웅 2명 이상 또는 영웅 1명+미니언 2기, 또는 미니언 4기 이상 | 비어 있는 곳에 장판 생성 |
| 처형·강한 단일 타격 | 효과가 의미 있는 영웅 또는 공격 가능한 구조물 | 일반 평타 한 번에 죽는 미니언 한 기 |
| 돌진 | 경로가 통하고 도착지가 공격 가능한 지역 | 지형 관통, 잠긴 타워 뒤로 진입 |
| 범위 치유 | 범위 내 아군의 유효 회복량 합계 ≥ 기본 치유량 60% | 모두 만피, 사망자만 있는 범위 |
| 단일 치유 | 결손 HP가 치유량 35% 이상 또는 HP 비율 35% 이하 | 대상이 이미 사망 확정 |
| 보호막 | 0.8초 안에 예상되는 피해 또는 근접 위협 존재 | 전투에서 멀리 떨어진 아군에게 반복 사용 |
| 정화 | 해제 가능한 CC가 실제 존재 | 단지 HP가 낮다는 이유로 정화 |
| 도발 | 후열을 위협하는 적 또는 공격을 막아야 하는 적 다수 | 공격 불가능·면역 대상만 있음 |
| 넉백 | 자신/아군에게 붙은 위협을 떼어낼 이익이 큼 | 아군의 범위 스킬 밖으로 이유 없이 밀기 |

위 표는 영웅별 조건이 없는 경우에만 적용하는 폴백이다. 03에서 특정 스킬에 명시한 대상 수·HP 비율·시전 조건이 있으면 그 조건이 우선하며 공통 표를 추가 AND 조건으로 붙이지 않는다. 그렇지 않으면 ‘영웅 1명에도 사용’으로 설계한 스킬이 공통 ‘2명’ 조건 때문에 영원히 발동하지 않는다. 다만 지형·사거리·행동 불가·구조물 보호 같은 공통 물리 규칙은 영웅별 조건이 우회할 수 없다. 필요한 타겟 수가 모자라더라도 적 넥서스 마무리나 즉시 생존 위협처럼 명시한 예외가 있으면 사용할 수 있다. 예외를 임의로 모든 스킬에 붙이지 않는다.

### 10.2 스킬 선택 우선순위

동시에 두 스킬이 가능하면 생존·아군 구조 목적의 긴급 스킬, 적 넥서스 확정 마무리, 높은 기대 효과의 공격·제어 스킬, 일반 평타 순서로 평가한다. 높은 우선순위라고 준비 중인 정상 공격을 매번 취소하지 않는다. 긴급 끼어들기 허용 여부는 스킬별로 지정한다.

영웅 AI는 무조건 쿨타임이 끝난 스킬부터 쓰지 않는다. 기대 효과는 실제 피해를 받을 수 있는 대상 수, 예상 유효 회복량, 보호 가능한 아군 수, CC가 끊을 수 있는 적 행동을 기준으로 계산한다. 미래 적 움직임은 최대 0.35초의 현재 속도 선형 예측만 사용한다. 완벽한 미래 예지나 플레이어 퀴즈 상태를 이용하지 않는다.

## 11. 피해, 치유, 보호막과 CC

### 11.1 피해 계산

초기 공통식은 `finalDamage = rawDamage × 100 / (100 + armor)`다. armor는 0 이상을 기본으로 한다. 물리·마법의 별도 저항을 첫 버전에서 추가하려면 상위 명세에 명시해야 하며, 임의로 숨은 두 번째 방어 스탯을 만들지 않는다. 부동소수점 누적은 서버 내부에서 유지하고 화면 숫자만 반올림한다. 피해를 매 사건마다 정수로 내림하여 빠른 공격만 손해 보지 않게 한다.

스킬이 주는 피해 감소는 방어 계산 후 추가 적용한다. 서로 다른 피해 감소 효과 r1, r2의 총 감소율은 `1 - (1-r1)×(1-r2)`로 계산하고 최대 60%로 제한한다. 같은 종류의 영역 효과 여러 개는 최댓값 하나만 사용한다. 예를 들어 35% 감소와 25% 감소가 겹치면 총 51.25% 감소다. 보호막은 이 감소까지 적용된 피해를 흡수한다.

구조물에 대한 평타는 기본 100% 피해를 적용하고 구조물 방어력을 거친다. 스킬은 각 스킬의 structureMultiplier를 거친다. 기본값을 묵시적으로 상속하지 말고 모든 스킬에 값을 명시한다. 공통 시작값은 피해 스킬 0.35, 강한 광역 전설 스킬 0.20~0.25다. 치유·CC·넉백은 구조물에 적용하지 않는다.

지원의 치료량과 보호량도 해당 영웅의 성장 후 능력치를 사용한다. 공격 강화가 지원에게 무의미한 구매가 되지 않도록 그 강화가 치료·보호 계수에 미치는지는 성장 명세에서 공통 정의한다.

### 11.2 보호막

보호막은 `sourceSkillId, sourceOwnedHeroInstanceId, amount, expiresAtTick`을 가진 개별 층으로 저장한다. 같은 출처의 동일 스킬 재적용은 남은 값과 새 값 중 큰 쪽으로 갱신하고 만료시각을 갱신한다. 같은 출처가 쿨타임마다 무한 누적되게 하지 않는다. 다른 출처의 실드는 별도로 존재할 수 있으나 총합은 대상 최대 HP의 35%를 초기 상한으로 둔다.

피해는 만료가 빠른 보호막부터 소모한 뒤 HP에 들어간다. 실제 소모된 실드만 보호 기여도에 기록한다. 사용됐지만 맞지 않고 끝난 실드는 시상식의 실제 보호량에 더하지 않는다. 사망하면 모든 실드를 제거한다.

### 11.3 CC와 면역

| 상태 | 이동 | 평타·스킬 | 중첩 정책 |
|---|---|---|---|
| 기절 | 불가 | 불가, 취소 가능한 windup 중단 | 만료시각 max, 지속시간 단순 합산 금지 |
| 띄우기 | 강제 모션만 | 불가 | hardCC 한도 공유 |
| 속박 | 자발 이동 불가 | 범위 안 공격·스킬 가능 | 만료시각 max |
| 감속 | 가능 | 가능 | 가장 강한 감속 하나, 최종 속도 50% 이상 |
| 침묵 | 가능 | 평타 가능, 액티브 스킬 불가 | 만료시각 max |
| 도발 | 도발자 방향 접근 | 가능하면 도발자 대상 공격 | 구조물 면역, hardCC와 분리 |
| 넉백 | 강제이동 | 짧은 피격 모션 | 경로 충돌, 벽을 뚫지 않음 |

연속 hardCC(기절·띄우기)의 상한은 2초다. 0.1초=2틱 이하 간격으로 연장되는 CC도 같은 연속 구간으로 본다. `ccChainStartTick`, `lastHardCcActiveTick`, `hardCcImmuneUntilTick`을 저장한다. 같은 연속 구간의 만료시각은 chainStart+40틱을 넘지 못한다. 2초 상한에 도달하여 강제 해제하면 40틱 동안 hardCC 재적용 면역을 준다. 짧은 스턴의 자연 종료나 정화가 별도의 2초 면역을 새로 주지는 않는다. 3틱 이상 hardCC가 없으면 기존 연속 구간을 종료한다. 면역 중 새 스킬의 피해는 정상 적용하고 hardCC 부분만 무시한다.

정화는 해당 스킬이 해제할 수 있는 부정적 상태만 제거한다. 기존 긍정적 hardCC 면역 타이머를 지우거나 0으로 초기화하지 않는다. 수도승 자신이 스턴·띄우기 상태라면 정화의 종을 시작할 수 없다. 속박·감속 중에는 다른 시전 조건을 만족하면 자신도 정화 대상이 될 수 있다. 정화가 이미 완료된 뒤 같은 스텝의 신규 CC까지 무조건 지우는 무적 효과를 만들어서는 안 된다. 같은 스텝의 상태효과 사건은 아래 정산 규칙의 확정 순서를 따른다. 이 정책은 30명 전투에서 영구 행동불가와 숨은 무적을 동시에 막기 위한 초기값이다.

넉백은 단순 좌표 순간 변경이 아니라 0.12~0.25초 동안 경로를 가진 강제이동이다. 강제이동 도중 벽이나 고체 구조물에 닿으면 접점에서 멈춘다. 충돌에 추가 피해를 주는 스킬로 명시하지 않았다면 벽 충돌 보너스 피해를 만들지 않는다. 스킬 명세에 없는 넉백 무적도 만들지 않는다.

## 12. 발사체, 범위와 시각적 판정

### 12.1 기본 발사체

발사체는 생성 좌표, 속도, 목표 또는 방향, 반경, 잔여 사거리, 충돌 정책, 피해 payload, sourceDeploymentId를 가진다. 서버가 발사체의 앞 스텝 위치에서 다음 위치까지 sweep 검사를 한다. 빠른 화살이 한 스텝 사이 적을 통과하는 현상을 막는다.

- 일반 활·석궁 평타: 지정 표적을 향한 보정형 발사체. 시각적 궤적과 실제 적중 좌표를 일치시킨다.
- 관통 화살·직선 스킬: 발사 방향이 고정되고 경로에 닿는 유효 적을 정의된 최대 횟수만 맞힌다.
- 포물선 범위 스킬: 발사 순간의 목표 지점 또는 제한된 예측 지점에 착탄한다. 표적을 끝없이 추적하지 않는다.
- 타워 탄환: 타워 정의에 따른 목표 추적, 충돌 반경과 적중 시각을 표시한다.

발사 후 공격자가 사망해도 이미 날아가는 발사체는 남는다. 소유 플레이어와 기존 deploymentId를 통계 귀속에 사용한다. 표적이 사망하면 일반 추적 발사체는 마지막 위치로 날아가 사라지며 다른 적으로 자동 변경하지 않는다. 다른 적 충돌 허용 여부는 발사체 정의에 따른다.

### 12.2 시전과 적중의 동일 시간축

서버는 04의 `actionStartTick`, `impactTick`, `recoveryEndTick`과 실제 발사체 생성·충돌 이벤트의 tick을 전송한다. 원거리 동작의 impactTick은 발사 시점이며 실제 피해 시점은 나중의 충돌 이벤트다. 렌더러는 보간 지연만큼 늦춘 서버 시간축에서 이 값을 재생한다. 스냅샷에는 이미 HP가 줄었는데 화살이 아직 중간에 있는 상태를 줄이기 위해 HP 변화도 해당 타격 사건의 재생 시각과 맞춘다. 재접속으로 과거 이벤트가 많아졌을 때는 현재 HP를 기준으로 정착하고 오래된 이벤트를 빠르게 재생하지 않는다. 액션의 windup·recovery phase별로 최소 아트 자세를 배치하고 렌더 주기에 따라 보간한다. 최소 4~6자세가 각각 서버 한 틱 이상을 차지해야 한다는 규칙은 없으며, 아트 자세 수 때문에 서버 선딜을 늘리지 않는다.

원형 장판의 보이는 경계는 실제 반경, 부채꼴의 보이는 각도는 실제 각도, 돌진 잔상은 실제 이동 경로를 따라야 한다. 보기 좋게 만든 이펙트가 다른 라인까지 뻗는데 피해는 작은 원에만 들어가는 식의 불일치를 금지한다.

피격 감각은 짧은 로컬 반짝임, 2~4단위 시각 반동, 적중 스파크, 스킬별 타격 음, 필요한 경우 명시된 넉백으로 만든다. 모든 평타마다 전체 서버나 호스트 카메라를 멈추거나 흔들지 않는다. 시각 hitstop을 쓴다면 해당 캐릭터 애니메이션 40~70ms에만 적용하고 판정 시간은 계속 흐르게 한다.

## 13. 미니언 AI

### 13.1 공통 상태

미니언도 `ADVANCE → APPROACH → WINDUP → RECOVERY → DEAD` 흐름을 사용한다. 다만 영웅보다 단순한 타겟 선택과 대형을 사용한다. 영웅용 장기 후퇴, 정비, 레벨업, 뽑기는 없다.

같은 라인의 가까운 적 유닛이 있으면 우선 교전하고, 없으면 다음 해금 구조물로 전진한다. 원거리 미니언은 사거리 유지와 20단위 이내의 짧은 뒤로 물러남만 한다. 적을 피해 다른 라인으로 달아나지 않는다. 근접 미니언은 공격 자리를 공유하는 동일 알고리즘을 이용하되 영웅보다 낮은 자리 우선순위를 갖는다.

### 13.2 초기 스탯

| 속성 | 근접 미니언 | 원거리 미니언 |
|---|---:|---:|
| HP | 150 | 95 |
| 공격력 | 10 | 12 |
| 방어력 | 8 | 0 |
| 이동속도 | 42/초 | 42/초 |
| 평타 간격 | 1.15초 | 1.35초 |
| 표면 사거리 | 10 | 130 |
| 선딜 | 0.23초 | 0.28초 |
| 후딜 | 0.28초 | 0.30초 |
| 평타 발사체 속도 | 근접 판정 | 260/초 |
| 충돌 반경 | 8 | 7 |

이 값은 영웅의 존재감과 웨이브 소거 시간을 맞추기 위한 초깃값이다. 미니언이 영웅보다 더 강해 영웅의 스킬이 필요 없거나, 첫 평타에 전부 사라져 줄다리기가 없으면 안 된다.

웨이브는 생성 시 좌우 대칭으로 동시에 생성한다. 같은 통행 지점을 점유하면 spawn placement resolver가 해당 진영 출정 영역 안에서 순서대로 빈 슬롯을 찾는다. 유닛 생성량을 줄이거나 기존 미니언을 이유 없이 삭제해 프레임을 확보하지 않는다.

### 13.3 경기 후반 압력

10~13분 내 종료를 돕는 초기 밸런스 장치로, 미니언의 구조물 대상 피해만 양 팀에 대칭 적용한다. 8분부터 ×1.25, 10분부터 ×1.50, 12분부터 ×2.00이다. 배율은 누적해서 곱하지 않고 현재 시간 구간의 한 값만 사용한다. 이미 살아 있는 미니언과 새 미니언 모두 똑같이 적용하며, HP와 영웅·미니언 상대 피해는 이 장치로 올리지 않는다. 정확한 값은 마스터 밸런스 설정에서 한 번만 정의한다.

이 장치로 이기고 있는 팀의 골드나 퀴즈 보상을 몰래 올리지 않는다. 라인에서 교전이 계속되는 한 승패는 실제 공격·생존·공성 결과로 정해져야 한다. 13분이 넘었다고 남은 넥서스 HP가 높은 쪽을 갑자기 승자로 만들지 않는다.

## 14. 구조물과 공성 AI

### 14.1 공성 해금 그래프

각 방어 팀의 윗라인과 아랫라인에 독립된 외부·내부 타워가 있다. 그 라인의 외부 타워가 살아 있으면 내부 타워는 보호된다. 어느 한 라인의 외부와 내부 타워를 모두 파괴하면 넥서스 수호 타워 두 개를 공격할 수 있다. 수호 타워 둘을 모두 파괴하면 넥서스를 공격할 수 있다.

반대 라인의 일반 타워가 남아 있다고 이미 열린 라인의 넥서스 공성을 잠그지 않는다. 반대 라인에서 출정한 영웅도 본인 라인을 따라 본진 합류 지대에 도달하면 열린 수호 타워를 공격할 수 있다. 그러나 생존 중 중앙을 가로질러 라인을 바꾸지는 않는다.

보호된 구조물에 평타, 관통, 장판, 연쇄 피해, 지속 피해가 닿아도 피해는 0이다. 잠긴 구조물에 공격 명령을 내리거나 그 앞에서 기다리는 대신 현재 해금된 목표를 선택한다. 보호 표시와 실제 보호 조건은 같은 서버 데이터에서 생성한다.

### 14.2 초기 구조물 스탯

| 항목 | 외부 타워 | 내부 타워 | 수호 타워 | 넥서스 |
|---|---:|---:|---:|---:|
| 최대 HP | 9,000 | 12,000 | 14,000 | 22,000 |
| 방어력 | 20 | 25 | 30 | 20 |
| 공격력 | 75 | 90 | 125 | 없음 |
| 공격 간격 | 1.2초 | 1.1초 | 1.1초 | 없음 |
| 표면 사거리 | 180 | 180 | 240 | 없음 |
| 선딜 | 0.25초 | 0.25초 | 0.35초 | 없음 |
| 발사체 속도 | 360/초 | 380/초 | 400/초 | 없음 |
| 충돌 반경 | 28 | 30 | 32 | 42 |

수호 타워는 두 개 모두 공격한다. 넥서스에 보이지 않는 세 번째 공격 타워를 추가하지 않는다. HP 회복·타워 재생·억제기·슈퍼 미니언은 별도 채택이 없는 한 넣지 않는다. 모든 값은 첫 전투 시뮬레이션과 사람이 보는 전투로 검증할 초기값이다.

### 14.3 타워 표적과 어그로

타워는 유효 사거리 안의 적을 대상으로 다음 우선순위를 사용한다.

1. 타워 사거리 안의 아군 영웅에게 최근 3초 안에 피해를 준 적 영웅.
2. 이미 공격 중이고 아직 유효한 표적.
3. 가장 가까운 적 근접 미니언.
4. 가장 가까운 적 원거리 미니언.
5. 가장 가까운 적 영웅.

우선순위 1이 여러 명이면 최근 3초의 실제 아군 영웅 피해가 큰 적, 다음은 가까운 적을 선택한다. 아군 영웅에게 시전했으나 빗나간 공격은 어그로를 만들지 않는다. 자힐·아군힐·보호막만으로 적 타워 어그로를 강제로 얻지 않는다.

타워가 한 영웅을 연속 공격하면 피해 배율을 1.0, 1.1, 1.2, 최대 1.3으로 올리는 초기값을 둘 수 있다. 타깃이 바뀌거나 2초 동안 공격이 없으면 초기화한다. 이 배율은 UI 위험 표식으로 인지할 수 있게 한다. 숨은 무제한 증가를 금지한다.

### 14.4 영웅의 타워 진입

타워 공격권 안으로 들어가기 전에 근처 아군 수, 아군 미니언, 자기 HP, 타워의 현재 표적, 자신이 받는 다른 피해를 평가한다.

- 아군 미니언이 타워 어그로를 받고 있으면 자기 사거리를 활용해 공성한다.
- 탱커는 HP 55% 이상이고 주변 아군 영웅 2명 이상이 함께 공격 가능하면 짧게 선두를 잡을 수 있다.
- 비탱커는 아군 미니언도 탱커도 없고 자신이 타워의 첫 표적이 될 상황에서 단독 진입하지 않는다.
- 현재 HP가 예상 다음 타워 2발 피해보다 낮고 안전한 뒤쪽 이동이 가능하면 최대 100단위 후퇴한다.
- 다음 공격 1~2회 안에 해당 구조물이 파괴되고 자신도 그 공격 시점까지 생존할 수 있다면 마무리를 우선한다.

표적이 타워 범위를 나가면 타워는 새 표적을 고른다. 영웅은 사거리 경계를 1~2단위씩 반복 출입하며 타워 평타를 무한 취소시키지 않도록 최소 0.5초의 전술 상태 유지와 12단위의 위험 경계 hysteresis를 사용한다. 타워 발사 후 표적이 나갔다고 탄환을 취소하지 않는다.

### 14.5 수호 타워 두 개 앞의 진형

공성 그룹은 두 수호 타워 앞에 가능한 공격 자리 수, 아군 공격력, 타워 HP를 보고 분산한다. 모든 근접 영웅이 위쪽 수호 타워 하나의 같은 점에 겹치지 않는다. 기본은 HP 비율이 낮은 타워 우선이되 그 타워의 근접 자리가 포화되면 다른 타워로 배정한다. 원거리도 자기 사거리·위험을 반영해 위치를 정한다.

넥서스가 열리고 공격 가능한 위치에 있다면 불필요하게 뒤쪽 미니언을 추적하지 않는다. 자기 주변의 즉시 생존 위협이 없고 넥서스에 피해를 줄 수 있으면 공성을 우선한다. 승리 직전 빠른 적 한 명을 따라 넥서스에서 멀어지는 행동은 허용하지 않는다.

## 15. 사망과 정비 전환

사망 처리에서는 해당 유닛의 공격 자리 예약, 표적 예약, 충돌, 지속 채널, 생명에 귀속된 상태효과를 해제한다. 이미 발사된 투사체와 이미 생성된 독립 장판은 스킬 정의가 허용하는 범위에서 남는다. 생존 중인 것처럼 다시 공격을 예약하지 못하게 상태를 먼저 DEAD로 확정한다.

학생 상태는 바로 DEAD_MAINTENANCE로 바꾸고 다음 정보를 보낸다.

- 사망한 영웅 이름·레벨·강화와 이번 출정 기록.
- 현재 잔액, 창고, 각 영웅의 성장과 두 스킬 해금 상태.
- 현재 두 라인의 아군 영웅 수와 구조물 상황.
- 퀴즈 진행 중이라면 이어 풀기, 가능하다면 새 퀴즈, 쿨타임이면 남은 시간.
- 같은 영웅 유지, 교체, 성장, 뽑기, 라인 선택, 출정.

사망 애니메이션 0.35~0.65초가 끝날 때까지 정비 UI를 막지 않는다. 사망 뒤 최소 5초 동안은 출정 버튼만 잠근다. 이 시간에도 구매, 성장, 영웅·라인 선택, 퀴즈는 가능하다. 5초는 초기 튜닝값이며 자동 부활 시한이 아니다. 5초가 지나도 출정 버튼을 누르지 않으면 계속 정비 상태다. 학생이 퀴즈를 풀고 있는 동안 죽었다면 답을 버리거나 퀴즈 패널을 강제로 닫지 않는다. 작은 사망·정비 알림을 띄우고 현재 문제와 답변 상태를 유지한다. 정비로 돌아왔을 때 출정 선택지를 보여준다.

정비 상태에는 기본 자동 출정 시한이 없다. 늦은 학생은 시간을 쓰는 대가로 전장에 영웅이 없는 상태가 유지된다. AI 학생은 별도의 관리 정책에 따라 구매·출정을 결정하되 같은 최소 5초 잠금을 따른다. 봇의 결정을 실제 학생의 강제 부활 규칙으로 사용하지 않는다.

## 16. 승패와 기록

승패는 NexusDestroyed 사건에서 한 번만 확정한다. 종료 시각 이후 들어온 추가 투사체, 퀴즈 답변, 구매, 출정이 결과를 바꾸지 않는다. 종료 직전 정답 보상의 채택 기준은 공통 서버 이벤트 순서로 정한다. 같은 요청이 재전송돼도 한 번만 처리한다.

전투 통계는 유효 피해, 영웅 피해, 미니언 피해, 구조물 피해, 실제 치유, 실제 보호, CC 기여, 킬, 어시스트, 사망, 출정 횟수를 분리한다. 죽은 상대에게 들어간 초과 피해는 유효 피해로 더하지 않는다. 지원·탱커가 킬 수만으로 불리해지지 않도록 시상식은 역할별 실제 기여를 사용한다.

킬은 마지막 유효 적 피해에 귀속하고, 마지막 피해가 없어 환경·직접 테스트 제거인 경우 킬을 만들지 않는다. 어시스트는 최근 5초 안에 적에게 유효 피해·CC를 가했거나, 직접 교전 중인 아군을 유효 치유·보호한 학생을 후보로 한다. 미니언 마지막 타격으로 사망해도 최근 5초 안의 영웅 기여를 기록하되 킬 주체와 어시스트 정책은 일관되게 표시한다. 경제 보상은 퀴즈 명세를 따르며 자동으로 킬 골드를 추가하지 않는다.

## 17. 성능을 위해 허용하는 것과 금지하는 것

허용: 공간 해시, 관심 영역의 충돌 후보 축소, 공유 전장 인식, AI 평가 분산, 정적 배경 캐시, 스프라이트 아틀라스, 이펙트 객체 풀, 네트워크 델타, 화면 크기에 따른 숫자 크기와 이름표 정리.

금지: 보이는 미니언을 몰래 지우기, 호스트에서 원거리 전장의 스킬을 생략하기, 배경 탭에서 전투 속도를 바꾸기, 타격 판정을 렌더 프레임에 의존하기, 과도한 구조물 피해를 넣어 테스트만 빨리 종료하기, 목표 시간에 맞춰 승자를 정해 피해를 조작하기.

AI는 전투 상태를 읽는 동일 함수로 작성하여 서버 검증과 오프라인 시뮬레이션에서 재사용한다. 테스트에서만 다른 쉬운 전투 엔진을 쓰지 않는다. 자동 경기 배속은 렌더링을 줄이고 고정 스텝을 빨리 호출하는 방식으로 구현하며 dt를 크게 바꾸지 않는다.

## 18. 필수 관측과 디버그 표시

호스트의 개발 모드에는 현재 AI 상태, 표적 ID, 선택 이유, 예약 공격 자리, 경로, 사거리, 다음 스킬 가능 시각, 타워 어그로를 켜고 끌 수 있게 한다. 기본 수업 화면에는 이 개발 텍스트를 보여주지 않는다.

로그에는 `matchId, seed, tick, entityId, deploymentId, actionId, eventId, eventType, targetId, value`를 남긴다. 이벤트마다 전체 상태를 무한 저장하지 말고 주기적 체크포인트와 사건 로그를 조합한다. 같은 seed를 재생했을 때 승패·파괴 순서·피해 합계를 비교할 수 있어야 한다.

전투 비정상 지표를 집계한다: 유효 목표가 있는데 5초 이상 공격·이동이 없는 유닛, 2초 안에 8회 이상 표적 변경, 지형 밖 좌표, 음수/NaN HP, 동일 학생의 복수 활성 영웅, 보호 구조물 피해, 2초 초과 연속 hardCC, 3초 이상 통행 정체, 서버 고정 스텝 누락.

이동 의도가 있지만 아군 몸에 막힌 연속 시간을 별도 측정한다. 정상적인 공격 준비·후딜·사거리 유지·CC 시간은 빼고 계산하여, 이 정체 시간의 p95가 1초 이하여야 한다. 5초 이상 해결되지 않은 사건은 평균값이 좋더라도 실패다. seed를 고정한 장면을 좌우 반전해 팀별 처리 순서 때문에 한쪽만 먼저 자리를 차지하거나 피해를 주는지 확인한다.

### 19.1 사람이 반드시 봐야 하는 전투 장면

자동 테스트만으로 액션 품질을 합격시키지 않는다. 최소 다음 장면을 실제 브라우저에서 녹화하거나 연속 캡처해 확인한다.

- 근접 1 대 1: 준비 자세, 접촉 순간, 피격 반응, 후딜이 구별된다.
- 탱커 2·딜러 3·지원 1의 소규모 교전: 탱커와 후열의 위치, 치료 타이밍, 표적 유지가 읽힌다.
- 30명 전장: 위·아래 두 전장의 공격, 투사체, 스킬을 호스트 전체 화면에서 동시에 볼 수 있다.
- 큰 장판과 전설 스킬이 겹친 장면: 캐릭터와 HP바가 사라질 정도의 불투명 효과가 없다.
- 타워 앞 교전: 미니언이 먼저 진입하고 후열이 따라 공격하며, 지원이 고립된 적을 쫓지 않는다.
- 합류 지대의 수호 타워 공성: 두 라인이 자연스럽게 합쳐지고 폭을 활용하며 정체되지 않는다.
- 사망 후 정비와 재출정: 화면이 배경만 남거나 버튼이 사라지는 공백 상태 없이 이어진다.

### 19.2 경기 길이 검증

표준 AI 학생 30명 경기를 서로 다른 seed로 최소 40회 수행한다. 초기 시간 목표는 종료시간 중앙값 600~780초, 전체의 70% 이상이 600~780초 안에 종료되는 것이다. 정비 속도·퀴즈 정확도·영웅 조합을 바꾼 경기는 별도의 민감도 검사로 추가한다. 각 경기의 종료시간, 승패, 첫외부타워파괴시각, 첫내부타워파괴시각, 수호타워돌입시각, 전설획득수, 영웅사망수, 평균정비시간, 평균유닛수를 기록한다. 경기 종료가 10~13분에 얼마나 분포하는지 실제 측정한다.

승률만 맞는다고 합격시키지 않는다. 10분 전에 일방적으로 종료되는 비율, 15분을 넘기는 비율, 어느 한 라인에만 영웅이 몰리는 비율, 어떤 영웅이 아무것도 못 하고 죽는 비율을 보고 구조물HP·미니언주기·전투이동·성장경제를 조정한다. 튜닝 후에는 같은 검증을 다시 실행하고 변경 전후 결과를 남긴다. 게임 시간을 맞추기 위해 사용자 확정 규칙을 몰래 바꾸지 않는다.
