# 클래스 클래시 AI 학생과 구현 인수 시험 명세

문서 상태: Codex가 구현한 뒤 통과해야 하는 요구사항이다. 이 문서에 적힌 시험은 아직 실행한 결과가 아니다. 실제 결과는 별도의 `TEST_REPORT.md`에 실행 환경, 명령, 커밋, 관측값과 함께 기록한다.

## 1. 목적과 반드시 구분할 두 종류의 AI

클래스 클래시는 학생이 영웅을 직접 조작하지 않는 게임이다. 따라서 다음 두 AI는 별도 모듈이어야 한다.

| 구분 | 적용 대상 | 책임 | 난이도에 따른 차이 |
|---|---|---|---|
| 전투 AI | 인간 학생과 AI 학생이 출정시킨 모든 영웅, 미니언, 포탑 | 이동, 진형, 표적 선택, 평타, 스킬, 공성, 피격·사망 | 없음. 같은 영웅·성장·전황에는 같은 규칙 적용 |
| AI 학생 관리자 | 호스트가 로비에서 추가한 시험 참가자 | 퀴즈 풀이, 자원 사용, 뽑기, 영웅 선택, 정비, 출정 라인 결정 | 퀴즈 정답률·응답 시간과 자원 사용 정책만 다름 |

AI 학생은 보이는 전투를 꾸미기 위한 가짜 유닛이 아니다. 인간 학생과 똑같이 참가자 슬롯, 지갑, 개인 영웅 창고, 퀴즈 진행도, 사망 후 정비 상태를 가진다. 단, 로그인이나 별도의 학생 브라우저 없이 서버 내부 관리자가 학생 명령을 대신 보낸다. AI 학생도 인간 학생과 동일한 명령 검증·채점·지출·출정 경로를 통과해야 한다.

### 1.1 확정 요구와 초기 조정값

사용자 확정 요구는 2진영, 상·하 2라인, 최대 약 30명, 출정 후 직접 개입 불가, 사망 후 정비, 시작 퀴즈 20문제, 경기 중 퀴즈 10문제와 30초 쿨타임, 일반 뽑기 2원, 고급 뽑기 10원, 고급 뽑기에서만 전설 10%, 근접 미니언 3기·원거리 미니언 4기, 호스트의 전체 전장·모든 액션·이펙트 관전이다.

이 문서의 봇 정답률·풀이 시간·정비 사고시간·전략 가중치·성능 예산·최소 사망 대기 5초·미니언 주기 20초는 첫 구현을 위한 조정 가능한 기본값이다. 구현 후 수업 환경과 자동 경기를 근거로 조정할 수 있으나 사용자 확정 요구를 바꾸어서는 안 된다.

## 2. 호스트 로비의 AI 학생 관리

### 2.1 로비에서 제공할 조작

호스트 화면에 `AI 학생 추가` 버튼을 둔다. 다음 항목을 한 작은 패널에서 지정한다.

| 항목 | 값 | 기본값·행동 |
|---|---|---|
| 추가 인원 | 1명부터 남은 슬롯 수까지 | 1명 |
| 진영 | 자동 균형 / 청팀 / 홍팀 | 자동 균형 |
| 학습 프로필 | 기초 / 표준 / 숙련 | 표준 |
| 자원 사용 성향 | 균형 / 성장 우선 / 수집 우선 | 균형 |
| 최초 선호 역할 | 자동 / 탱커 / 근접 / 원거리 / 마법 / 지원 | 자동 |
| 시험 시드 | 숫자 또는 문자열 | 자동 생성. 고급 시험 설정에서만 입력 |

편의 버튼은 `총 10명까지 채우기`, `총 20명까지 채우기`, `총 30명까지 채우기`, `AI 전부 제거`를 제공한다. 기존 인간 참가자를 삭제하거나 바꾸지 않고 빈 슬롯만 채운다. 이미 목표 인원 이상이면 동작하지 않고 현재 인원과 사유를 알려 준다. 전체 수를 30명으로 채울 때 양 팀이 15명씩 되도록 배분한다. 단, 이미 수동으로 배정한 인간 학생을 자동으로 반대 팀에 옮겨서는 안 된다. 한 팀이 15명을 넘는 수동 구성이 있다면 해당 구성부터 정리하도록 표시한다.

참가자 행에는 `AI` 배지, 식별 가능한 별칭, 진영, 학습 프로필, 현재 상태, 연결 종류를 표시한다. 예시는 `AI 새봄 01 · 표준 · 청팀 · 준비 완료`이다. 실제 학생과 혼동할 실명·학교 정보를 자동 생성하지 않는다. 봇 이름 옆에는 제거 버튼과 팀 변경 버튼을 제공한다.

### 2.2 정원과 변경 잠금

정원은 인간과 AI를 합해 최대 30명이다. 호스트는 참가자 정원에 포함되지 않는다. 한 팀 최대 15명을 기본 제한으로 둔다. 인간 1명과 AI 29명, 인간 0명과 AI 30명 모두 시작 가능하다. 두 팀에 최소 1명씩 있어야 실제 전투를 시작할 수 있다.

퀴즈 시작으로 로스터가 잠기면 AI의 추가·삭제·팀 이동·프로필 변경도 잠근다. 경기 중 AI를 추가하거나 제거해 전력을 바꾸는 우회 API를 허용하지 않는다. 경기 종료 후 `같은 참가자로 재경기`를 선택하면 로비로 복귀하여 다시 수정할 수 있다.

AI를 로비에서 삭제할 때 해당 관리자의 타이머, 보류 명령, 세션, 구독을 모두 취소한다. 제거된 봇이 늦게 채점·출정 요청을 보내도 참가자와 경기 식별자로 거부한다. 자동 채우기는 하나의 원자적 서버 명령으로 실행하여 인간 참가 요청과 경합해도 정원을 초과하지 않게 한다.

### 2.3 혼자 시험하는 표준 흐름

1. 호스트가 방을 만든다.
2. `총 30명까지 채우기`로 AI 30명을 추가한다.
3. 두 팀 15명, 프로필과 이름, 준비 상태를 확인한다.
4. 시작 퀴즈를 시작한다. 봇들이 실제 퀴즈 시도를 생성하고 순서대로 답한다.
5. 호스트는 완료 인원과 초기 자산 분포를 확인한 뒤 첫 정비 화면으로 진행한다.
6. AI가 창고와 지갑 범위에서 영웅을 정하고 라인을 선택하여 준비한다.
7. 호스트가 전투를 시작한다. 경기 시각 0에 미니언 첫 웨이브가 나온다.
8. 호스트는 고정 전체 맵에서 모든 전투를 보고, 필요하면 별도의 시험 패널에서 AI 학생 1명의 화면을 읽기 전용으로 확인한다.
9. 넥서스 파괴로 종료한 뒤 실제 이벤트에서 산출한 결과와 시상식을 본다.
10. 같은 방에서 재경기해 이전 자원·영웅·퀴즈·사망 정보가 남지 않는지 확인한다.

시험용 학생 화면 열기는 호스트의 기본 전장 카메라를 바꾸지 않는다. 새 패널 또는 새 탭에 해당 학생과 동일한 읽기 전용 투영을 보여 준다. 호스트가 그 학생의 살아 있는 영웅을 조종하거나 성장시키는 기능을 만들지 않는다.

미준비 인원이 있는 경기 시작은 01의 명시적 호스트 예외를 따른다. 양 팀 최소1명 READY를 확인하고 준비된 인원만 첫 출정한다. 나머지는 hasDeployedThisMatch=false인 첫 정비 상태이며 첫 사망 대기를 부과하지 않는다. 봇의 첫 정비 처리 함수도 공통 방이 이미 BATTLE이면 CLAIM_STARTER→구매/선택→DEPLOY_HERO를 사용하고 SET_READY를 다시 요청하지 않는다. 이 경로를 재접속 장면에 포함하여 미준비 인간1명+준비AI29명 시작 후 인간의 수동 첫출정이 가능하고, 이미출정한사람은무료선택/대기면제를재사용할수없음을검사한다.

## 3. AI 학생의 재현 가능한 학습 행동

### 3.1 세 가지 학습 프로필

| 프로필 | 문제별 정답 확률 | 문제별 응답 시간 | 정비 의사결정 간격 | 설명 |
|---|---:|---:|---:|---|
| 기초 | 0.55 | 균등분포 3.0~6.0초 | 균등분포 1.0~1.8초 | 자산이 적어도 기본 영웅으로 정상 출정 |
| 표준 | 0.75 | 균등분포 2.0~4.0초 | 균등분포 0.6~1.2초 | 일반 수업 시뮬레이션 기준 |
| 숙련 | 0.90 | 균등분포 1.2~2.6초 | 균등분포 0.4~0.8초 | 많은 정답과 계획적인 투자 |

정답 여부는 각 문제에서 독립적인 베르누이 표본으로 결정한다. 예를 들어 표준 봇이 20문제에서 반드시 15문제를 맞히게 강제하지 않는다. 단일 봇·단일 세트에서 목표 확률과 차이가 나는 것은 정상이다. 장기 검증에서는 문제 표본 10,000개 이상으로 분포를 확인한다.

응답 시간은 `min + U × (max-min)`으로 뽑는다. 소수 초를 서버 틱으로 올림하여 제출한다. 예를 들어 2.03초는 20Hz 서버에서 2.05초 이후 첫 처리 틱에 제출한다. 네트워크 응답 속도로 정답 보너스를 주지 않는다. 봇은 문제를 받기 전에 답을 제출할 수 없고, 동시에 두 문제에 답할 수 없다.

모든 봇 타이머는 서버의 일시정지 가능한 `MatchState.tick`에 예약한다. 이 틱은 `OPENING_QUIZ`부터 단조 증가하므로 시작 퀴즈와 첫 준비에도 시간이 흐른다. 전투 경과 초는 `(tick - battleStartTick) / 20`이며 BATTLE 진입 시점을 0초로 표시한다. 서로 다른 실제 속도로 움직이는 두 개의 게임 시계를 만들지 않는다. 봇 답변·정비 사고시간·정체 감시를 브라우저 시계, `Date.now()` 또는 호스트 탭의 타이머에 의존시키지 않는다. 일시정지·서버 복구 중에는 예약 남은 시간과 정체 감시도 함께 멈추고 복원 후 이어서 센다. `setTimeout`을 깨우기 용도로 쓸 수는 있으나 실제 행동 가능 여부는 항상 현재 서버 게임 시간으로 다시 검증한다.

### 3.2 시드와 난수 스트림

봇 재현은 테스트 및 디버깅 기능이다. 각 경기에는 서버가 생성한 `matchSeed`가 있고 봇마다 다음 독립 스트림을 만든다.

| 스트림 | 용도 |
|---|---|
| `quizAccuracy` | 문제별 정답 여부 |
| `quizDelay` | 문제별 응답 시간 |
| `wrongChoice` | 오답 선택지 선택 |
| `managerDelay` | 정비 결정 간격 |
| `managerTieBreak` | 동점 역할·영웅·라인 선택 |

초기 상태는 UTF-8 문자열 `${matchSeed}/bot/${participantId}/${domain}`의 FNV-1a 32비트 해시이다. 해시는 초기값 2166136261에서 시작해 각 UTF-8 바이트에 대해 XOR 후 16777619를 곱하고 unsigned 32비트로 잘라 계산한다. JavaScript에서는 곱셈에 `Math.imul`을 사용한다. 결과가 0이면 `0x6d2b79f5`를 사용한다. 시험용 PRNG는 xorshift32로 고정한다. 매 호출 시 unsigned 32비트 상태 `x`에 `x ^= x << 13`, `x ^= x >>> 17`, `x ^= x << 5`를 적용하고 각 단계의 값을 unsigned 32비트로 정규화한다. 결과 `U = (x + 0.5) / 4294967296`을 사용한다.

언어별 부호·오버플로 차이를 막는 골든 벡터는 다음과 같다. 문자열 `classclash-qa/bot/bot-001/quizAccuracy`의 해시 초기 상태는 3720119544다. 이후 unsigned 출력 5개는 차례대로 3914854217, 2204526550, 3154936600, 2711433423, 4145984173이어야 한다. 이 값은 난수 알고리즘 정의의 계산 예시이며 게임 시험 통과 결과가 아니다.

이 PRNG를 운영 환경의 뽑기 보안 수단으로 사용해서는 안 된다. 운영 뽑기는 서버의 안전한 난수원과 원자적 거래를 사용하고, 자동 시험에서는 주입 가능한 별도 뽑기 스트림으로 결과를 재현한다. 봇의 생각 횟수가 늘었다고 이후 뽑기 결과나 전투 치명타가 달라지는 난수 결합을 만들지 않는다.

문제를 받을 때 정답 여부, 오답 선택, 제출 예정 시각을 한 번 확정해 보류 레코드에 저장한다. 일시 중지·재연결·동일 명령 재시도 때 다시 뽑지 않는다. 경기 재시작은 새로운 `matchId`와 스트림을 사용한다. 같은 시드 재현 기능을 쓰면 참가자 안정 식별자, 문제 배열, 설정, 명령 순서까지 함께 고정한다.

### 3.3 정답과 오답 생성 경계

AI 관리자 자체에는 정답 키 전체를 전달하지 않는다. 서버 내부의 퀴즈 시뮬레이터가 `정답 의도` 또는 `오답 의도`와 해당 문제 ID를 받아 유효한 선택지 ID를 만든다. 그 답을 인간 학생과 동일한 `submitAnswer` 검증 함수로 넣는다. 정답 보너스를 지갑에 직접 더하는 빠른 경로를 만들지 않는다.

정답 의도이면 해당 학생에게 제시된 섞인 선택지 중 정답 ID를 고른다. 오답 의도이면 정답을 제외한 유효한 선택지에서 균등하게 하나를 고른다. 오답 선택지가 없거나 중복된 잘못된 문제는 방 생성 단계에서 거부한다. 정답 키, 봇의 예정 정답, 미래 뽑기 결과를 학생 스냅숏·이벤트·브라우저 번들·공개 진단 패널에 노출하지 않는다.

### 3.4 시작 퀴즈와 경기 중 퀴즈

시작 퀴즈는 봇도 20문제를 끝까지 푼다. 호스트가 먼저 마감하면 아직 제출하지 않은 문제는 미응답으로 처리하고 예약 제출을 취소한다. 정답당 자원은 메인 명세의 설정을 그대로 사용한다. 첫 기본값은 정답당 1원이므로 20문제에서 획득 가능한 자산은 0~20원이다. 문항별 채점 트랜잭션에서 보상은 이미 한 번 지급된다. 초기 준비 단계에 들어간다고 20문제 정답 합계를 지갑에 다시 더하지 않는다. 준비 진입에서는 사용 잠금을 풀고 무료 선택권만 한 번 지급한다. 호스트 준비 화면에서는 봇의 문제 진행 수와 완료 여부를 실제 값으로 보여 준다.

경기 중 퀴즈는 10문제 단위다. 살아 있는 동안의 기본 봇 행동은 퀴즈 가능 시 즉시 새 세트를 시작하여 순차적으로 답하는 것이다. 마지막 문제의 서버 채점이 확정된 시각부터 30초 동안 다음 세트를 시작할 수 없다. 쿨타임 중에는 전장을 관전하며 명령을 낭비하지 않는다.

문제를 푸는 도중 영웅이 죽으면 현재 문제와 세트는 유지한다. 기본 봇은 남은 문제를 끝낸 후 정비 행동을 한다. 남은 문제가 6개 이상이고 최소 사망 대기시간이 끝났다면 현재 문제까지 제출하고 퀴즈 화면을 닫아 먼저 재출정할 수 있다. 이 경우 퀴즈의 문제 순서와 응답 확정 레코드는 그대로 보관하며, 재출정 직후 다음 문제부터 이어서 푼다. 퀴즈를 닫거나 다시 연 행위로 문제·쿨타임·보상을 초기화하지 않는다.

## 4. AI 학생의 정비와 출정 정책

### 4.1 행동 상태

공통 방 단계 이름은 메인 명세와 동일하게 `LOBBY → OPENING_QUIZ → INITIAL_MAINTENANCE → COUNTDOWN → BATTLE → RESULT`를 사용한다. 호스트 중단은 `CANCELLED`다. 플레이어 상태는 첫 준비의 `INITIAL_MAINTENANCE → READY`, 전투의 `ACTIVE ↔ DEAD_MAINTENANCE`, 종료의 `FINISHED`를 사용한다. 봇 전용으로 같은 의미의 `DEPLOYED`, `INITIAL_PREP`, `RESULTS` 같은 프로토콜 상태를 따로 만들지 않는다. 경기 중 퀴즈는 `ACTIVE` 또는 `DEAD_MAINTENANCE` 위에 독립적으로 존재하는 개인 작업이다. `QUIZ_ACTIVE`를 영웅의 생존 상태 대신 사용해서는 안 된다.

### 4.1.1 첫 준비의 전용 정책

첫 준비에서는 사망 후 재출정과 다른 명령 순서를 사용한다.

1. 방이 `INITIAL_MAINTENANCE`이고 본인이 같은 개인 상태인지 확인한다.
2. 무료 선택권이 미사용이면 일반 영웅 하나를 `CLAIM_STARTER`로 선택하고 성공 결과를 기다린다. 자산이 0원이어도 실행한다. 성공한 무료 지급을 다시 청구하지 않는다.
3. 자동 역할의 경우 같은 팀의 이미 선택된 첫 영웅 수를 보고 탱커 20%·근접 27%·원거리 20%·마법 20%·지원 13%의 목표 비중에서 가장 부족한 역할을 고른다. 해당 역할의 일반 영웅들 중 시드로 동점 선택한다. 역할 지정 봇은 지정 역할의 일반 영웅을 고른다. 이 비중은 봇 시험용 초깃값이고 인간의 선택을 제한하지 않는다.
4. 자산 범위에서 정비 쇼핑 정책을 적용한다. 첫 무료 영웅을 받기 전에 돈이 부족하다는 이유로 대기하지 않는다.
5. `SELECT_HERO_AND_LANE`으로 보유 영웅과 첫 라인을 정하고 `SET_READY(true)`를 한 번 보낸다. 최초 영웅 엔티티를 직접 만들거나 `DEPLOY_HERO`를 보내지 않는다.
6. 개인 상태가 `READY`가 되면 쇼핑·선택·퀴즈 요청을 멈추고 호스트의 카운트다운을 기다린다. 이 대기는 정상 상태다. 전원 준비됐어도 봇이 호스트 명령을 대신 보내지 않는다.
7. BATTLE t=0에 서버가 준비된 영웅을 생성한 후 `ACTIVE`로 넘어가야 경기 중 퀴즈와 사망 후 정비 정책을 시작한다.

준비를 다시 수정할 필요가 있으면 카운트다운 전 같은 참가자 권한의 `SET_READY(false)`로 개인 상태를 `INITIAL_MAINTENANCE`로 되돌린 뒤 수정한다. 이때 선택권 사용 여부와 확정 잔액을 유지하고 초기 무료 영웅이나 자산을 재지급하지 않는다. 기본 봇은 READY 이후 공개 전황도 아직 없는 첫 준비에서 불필요하게 준비를 반복 취소하지 않는다.

### 4.1.2 사망 후 정비의 정책

전투 중 `DEAD_MAINTENANCE`에 들어온 봇은 다음 순서로 행동한다.

1. 경기·참가자·사망 세대가 아직 유효한지 확인한다.
2. 진행 중인 퀴즈를 위 규칙에 따라 완료하거나 보관한다.
3. 현재 보유 영웅, 각 영웅의 개별 성장, 자산, 두 라인의 공개 전황을 읽는다.
4. 부족한 역할을 판단하고 필요하면 허용된 뽑기를 최대 1회 수행한다.
5. 출정할 영웅을 선택한다.
6. 잔액 범위에서 레벨업 또는 강화를 최대 2회 수행한다.
7. 출정할 라인을 선택한다.
8. 최소 사망 대기시간이 끝나면 동일 검증 경로로 `DEPLOY_HERO`를 보낸다. 성공 후 `ACTIVE`를 확인하고 정비 관리 루프를 중지한다.

한 정비 방문에서 전체 자산을 수십 번 연속 소비하는 루프를 만들지 않는다. 새 뽑기 결과·성장 결과가 도착하기 전에 이전 상태로 중복 구매하지 않는다. 명령별 성공 응답을 기다리고 최신 버전에서 다음 행동을 결정한다. 예산 부족·상한 도달 등 예상 가능한 거부는 바로 다음 합법 행동으로 넘어간다.

관리자 명령은 봇별로 한 번에 하나만 미확정 상태로 유지한다. API의 `commandId`는 `matchId + participantId + monotonicDecisionCounter`로 만들고 동일 결정의 재시도에서는 같은 값을 사용한다. 이 문서에서 일반적으로 요청 ID 또는 `requestId`라고 부른 것은 별도 프로토콜 필드가 아니라 이 `commandId`를 뜻한다. 출정·교체 명령에는 현재 사망 세대, 성장·뽑기에는 기대 지갑 버전과 소유 영웅 ID를 포함한다. 거부 시 새로운 비용을 차감하지 않고 최신 개인 상태를 읽어 다음 결정을 만든다.

### 4.2 출정 영웅 평가

후보는 자신의 창고에 있는 영웅뿐이다. 등급을 무조건 최우선으로 하지 않는다. 초기 평가식은 다음과 같다.

`heroScore = growthScore + roleNeedScore + matchupScore + continuityScore`

| 항 | 초기 기준 |
|---|---|
| `growthScore` | `(level - 1) × 10 + enhancementCount × 5 + unlockedSkillCount × 8` |
| `roleNeedScore` | 선택 예정 라인에 탱커가 없으면 탱커 +24, 지원이 없고 영웅이 4명 이상이면 지원 +18, 근거리만 3명 이상이면 원거리·마법 +12 |
| `matchupScore` | 적 다수가 근접이면 광역·둔화 영웅 +8, 적 지원이 둘 이상이면 접근 가능한 후열 압박 영웅 +8, 적 전열이 두꺼우면 지속 딜러 +8 |
| `continuityScore` | 직전 출정 영웅 +6. 단, 직전 두 생존 시간이 각각 8초 미만이면 이 보너스 제거 |

`roleNeedScore`와 `matchupScore`는 공개 전황에서만 계산한다. 적의 퀴즈 점수, 잔액, 창고, 미발동 스킬 예정 시각을 읽지 않는다. 서포터와 탱커의 치유·피해 차단 가치를 성장 점수에서 빠뜨리지 않는다. 동점이면 해당 봇의 동점 스트림으로 선택한다. 같은 영웅 인스턴스를 계속 선택하면 그 영웅의 성장만 유지되며 다른 인스턴스의 성장을 합산하지 않는다.

역할 평가가 라인을 필요로 하고 라인 평가가 영웅을 필요로 하는 순환을 피하기 위해, 보유 영웅과 두 라인의 모든 쌍을 먼저 평가한다. 쌍의 초기 점수는 `heroScore(hero, lane) + 8 × laneScore(hero, lane)`이다. 가장 높은 쌍을 임시 결정하고, 성장을 끝낸 뒤 출정 직전 공개 전황이 바뀌었다면 라인만 한 번 재평가한다. 명령 사이마다 영웅을 계속 바꾸며 정비를 끝내지 못하는 반복은 금지한다.

### 4.3 자원 사용 성향

| 성향 | 뽑기 정책 | 성장 정책 |
|---|---|---|
| 균형 | 창고에 서로 다른 역할이 2개 미만이면 일반 뽑기 우선. 주력 Lv.3 이상·자산 14원 이상이면 고급 뽑기 1회 검토 | 선택 영웅의 다음 스킬 해금을 먼저 목표로 하되 재출정에 필요한 별도 비용은 없음 |
| 성장 우선 | 보유 영웅이 있으면 최초 2회 정비는 추가 뽑기 생략. 주력 Lv.5 이후 고급 뽑기 검토 | 주력의 Lv.2 → Lv.5를 우선하고, 이후 강화 |
| 수집 우선 | 역할이 3개 미만이면 정비당 일반 뽑기 1회, 10원 이상 모였고 주력 Lv.2 이상이면 고급 1회 검토 | 선택 영웅을 최소 Lv.2까지 성장시킨 뒤 수집과 번갈아 투자 |

위 정책의 숫자는 초기값이다. 동일 자산에서 음수가 되거나 주력 영웅 없이 뽑기만 반복하는 정책은 허용하지 않는다. 뽑기권을 실제 아이템으로 보유하는 구조이면 구매와 사용을 구분하되 봇도 같은 구조를 사용한다. 최신 메인 명세가 즉시 뽑기를 정하면 이 표의 `뽑기`는 즉시 구매·소환의 원자적 거래를 뜻한다.

일반 뽑기의 역할은 아직 창고에 없는 역할 중 현재 팀에 가장 부족한 역할을 우선한다. 모든 역할을 보유했다면 출정 후보 라인의 역할 부족 점수가 높은 역할을 고른다. 고급 뽑기의 기본 봇 선택은 `전체` 풀이다. 고급 역할 지정 전술을 별도 시험할 때만 탱커·근접·마법 풀 중 하나를 명시적으로 선택한다. 원거리·지원이 필요하다는 이유로 비활성 고급 풀에 요청을 반복하지 않는다. 동일 역할의 중복 영웅도 독립 인스턴스이며 자동 합성·보상 환불이 없다.

기초·표준·숙련은 이 자원 사용 성향과 독립된 속성이다. 숙련에게 무료 자산, 전설 확률 상승, 할인, 체력·피해 증가, 정비 대기 면제, 숨겨진 즉시 스킬을 부여하지 않는다.

### 4.4 라인 선택

라인 평가는 정비 중 한 번만 확정한다. 출정 후에는 영웅이 살아 있는 동안 라인 변경 명령을 내리지 않는다. 두 라인의 상황값은 공개 상태를 0.5초 간격으로 읽는다.

`laneScore = 3 × enemyPressure + 2 × objectiveOpportunity + 2 × roleNeed - 3 × allyPopulationPenalty - 2 × previousOvercrowding`

- `enemyPressure`: 해당 라인에 아군 영웅보다 적 영웅이 1명 많을 때마다 +1, 아군 타워가 공격받고 있으면 +2, 합류부의 아군 수호 타워가 공격받으면 두 라인 중 적 유입이 많은 쪽에 +3.
- `objectiveOpportunity`: 적 외곽 타워 체력 30% 이하이면 +1, 내부 타워 30% 이하이면 +2, 아군 웨이브가 살아 있고 적 영웅 수가 아군보다 적으면 추가 +1.
- `roleNeed`: 출정 후보의 역할이 해당 라인에서 빠져 있으면 +1. 탱커 없이 원거리·지원이 3명 이상이면 탱커 후보에 +2.
- `allyPopulationPenalty`: 현재 출정 영웅과 이미 출정 준비를 확정한 아군을 합해 상대 라인보다 2명 이상 많으면 초과 1명당 +1.
- `previousOvercrowding`: 직전 출정 때 같은 라인에서 공격 자리를 못 얻은 시간이 전체 교전 시간의 30% 이상이면 +1.

여러 봇이 같은 틱에 같은 라인으로 몰리지 않도록 출정 의사결정을 참가자 ID의 안정 정렬 순으로 확정하고, 그 틱에서 확정된 출정 예약을 다음 봇의 인구 계산에 포함한다. 이 예약은 경기 전·정비 중 서버 내부에서만 쓰며 살아 있는 영웅을 이동시키는 지시가 아니다.

### 4.5 정비 무한 대기 방지

사망 후 정비 진입부터 12초가 지났고 퀴즈를 진행 중이지 않으면 추가 쇼핑을 중단하고 현재 창고에서 합법적으로 출정 가능한 영웅을 선택한다. 최소 사망 대기시간이 끝나면 바로 재출정한다. 첫 준비에서 12초가 지나면 추가 쇼핑을 중단하고 영웅·라인 선택과 준비 완료를 마친다. 진행 중인 퀴즈 때문에 정비가 늘어날 수는 있으나, 문제 응답 타이머가 없거나 잘못된 명령 재시도만 반복되는 상태는 오류다.

진행해야 하는 상태에서 서버 게임 시간 25초 동안 봇의 상태 버전·퀴즈 문제 번호·명령 성공 기록에 변화가 없으면 서버 진단 이벤트 `bot_stalled`를 기록한다. `LOBBY`, `READY`, `COUNTDOWN`, 퀴즈 `COOLDOWN`, `RESULT`, `CANCELLED` 및 일시정지는 정상 대기이므로 이 감시에서 제외한다. `OPENING_QUIZ`에서는 현재 문제의 예약 답변을 확인·재개하고, `INITIAL_MAINTENANCE`에서는 미사용 무료 선택권→영웅·라인 선택→준비 완료를 복구한다. `DEAD_MAINTENANCE`에서만 이미 보유한 영웅으로 정상 재출정 명령을 한 번 시도한다. 이 복구도 자산·성장·대기 규칙을 우회하지 않는다. 실패 원인을 호스트 시험 패널에 표시하고 다른 참가자의 경기를 멈추지 않는다. 인간 학생에게 이 자동 출정 복구를 적용하지 않는다. 인간 학생은 정비에서 원하는 만큼 선택한 뒤 직접 출정한다.

## 5. 시험 기능과 운영 기능의 경계

로비의 AI 추가·삭제와 AI만으로 경기하기는 정식 호스트 기능이다. 고정 난수, 특정 전설 강제 소환, 전투 시간 가속, 무적 허수아비, 순간 체력 조정, 서버 틱 단위 진행은 별도 개발 모드에서만 쓴다.

개발 모드는 환경 설정으로 명시적으로 켜고 화면에 `개발 시험` 표시를 유지한다. 공개 학생 API에서 query parameter 하나로 켤 수 없어야 한다. 개발 치트가 작동한 경기는 정상 시상식·학습 기록과 구분한다. 호스트가 AI를 추가한 정상 시험 경기는 일반 규칙을 적용하므로 결과를 정상 산출하되 AI 참가 여부를 명시한다.

호스트 시험 패널은 다음을 읽기 전용으로 보여 준다.

- 경기 ID·설정 버전·시험 시드·현재 틱·실제 경과시간과 시뮬레이션 경과시간.
- 인간/AI 참가 수, 양 팀 인원, 각 봇의 상태·퀴즈 진행·최근 성공 명령·마지막 오류.
- 살아 있는 영웅·근접 미니언·원거리 미니언·발사체·지속 장판 수.
- 서버 틱 p50/p95/p99, 처리 지연, 방송 바이트 수, 클라이언트 프레임 p50/p95.
- 구조물 파괴 순서, 사망→정비→출정 기록, 누락·중복 전투 이벤트 카운터.

개인 퀴즈의 정답 키, 세션 비밀, 숨겨진 창고 정보는 공개 전광판이나 학생 관전자에게 나오지 않는다. 교사의 진단 권한을 학생 권한으로 대체할 수 없어야 한다.

## 8. 경기 길이와 재미 검증

### 8.1 10~13분은 실제 플레이 검증 목표

게임 길이는 넥서스 파괴가 일어나는 결과로 맞춘다. 제한 시간이 되었다고 남은 체력을 비교해 승리시키거나, 보이지 않는 즉사 피해를 넣어 목표 길이를 맞추지 않는다. 장시간 경기 대책을 추가하려면 메인 명세에 시간·효과·화면 고지·양 팀 동등 적용을 명시해야 한다.

첫 수치 조정의 기준 세트는 표준 프로필 AI 30명, 팀당 15명, 양 팀 자원 성향을 대칭으로 구성한 40개 고정 시드다. 40개 중 최소 28개, 즉 70%가 넥서스 파괴로 600~780초 안에 종료하는 것을 초기 튜닝 목표로 둔다. 중앙값도 600~780초 안에 있어야 한다. 15분까지 어느 넥서스도 파괴되지 않는 시드는 미완주로 기록하고 원인을 분석한다. 시험 도구는 15분에 실행을 중단할 수 있지만 이 시험 상한을 제품의 승패 규칙으로 넣어서는 안 된다.

이 목표는 합의되지 않은 보장치가 아니라 튜닝 게이트다. 학생이 정비에서 오래 기다리거나 한쪽 학습 성과가 크게 높으면 경기 길이가 달라질 수 있다. 비대칭 프로필·전술·소수 인원 시험은 별도로 보고하고, 균형 40시드 결과와 섞어 평균을 좋게 만들지 않는다.

## 9. 아트와 애니메이션 수동 검수 게이트

자동 시험이 통과해도 다음 수동 검수 전에는 도트 액션 품질 완료를 선언하지 않는다.

1. 호스트 실제 출력 크기에서 성전사·검사·격투가·궁수·화염술사·얼음술사·사제·야만인·수도승의 역할과 동작을 구분할 수 있어야 한다.
2. 일반·고급·전설 18명 모두 기본 이동·평타·스킬 2개·피격·사망 표현이 있어야 한다. 6명만 완성하고 나머지 이름·색만 바꿔 최종 완료라고 해서는 안 된다.
3. 평타 모션은 준비·타격·회복의 무게가 보이고, 검사는 베기, 격투가는 연속 타격, 궁수는 활 당기기·발사, 사제는 치유 대상과 연결되는 별도 동작이 보여야 한다.
4. 룬 마법사, 고대의 존재, 수호령은 서로 다른 실루엣·움직임·스킬 구도가 있어야 한다. 전설 배지나 큰 원형 이펙트만 추가해서 구분하지 않는다.
5. 피해를 받는 유닛의 반응이 보여야 하지만 매 적중마다 전체 화면을 멈추거나 카메라를 흔들어 다른 라인 관전을 방해하지 않는다.
6. 미니언도 근접·원거리와 팀을 구분할 수 있어야 한다. 작게 보이는 호스트 화면에서 일반 영웅과 미니언이 같은 사각형처럼 보여서는 안 된다.
7. 모든 기능성 효과를 켠 15대15 교전 캡처에서 도로·영웅·HP·팀 색·위험 구역을 읽을 수 있어야 한다.
8. 원작의 스프라이트를 추출하거나 재배포하지 않는다. 참고는 동작의 명료함·대형·공격 리듬·피격의 관계이며 제작물은 오리지널 자산이어야 한다.

검수 자료는 실제 실행 화면이어야 한다. 잘 보이도록 꾸민 정적 콘셉트 이미지·비작동 목업을 플레이 화면 대신 제출하지 않는다. GIF 또는 짧은 영상에는 호스트 전체 맵, 학생 추적 시점, 근접·원거리·지원·전설의 실제 교전, 사망 후 정비와 재출정을 포함한다.

## 10. 성능 측정과 정직한 검증 보고

성능 수치는 장비·브라우저·해상도·DPR·빌드 모드·네트워크·경기 시드·엔티티 수와 함께 기록한다. Node 단위시험 통과와 브라우저 렌더링 성능, AI 관리자 30명과 독립 브라우저 30개, 개발자 PC와 실제 학교 태블릿을 서로 대체하지 않는다.

기준 PC 예시는 일반 노트북 CPU 4코어 이상·메모리 8GB·1920×1080 브라우저 화면이다. 기준 학생 장비는 실제 학교 태블릿 1종을 지정한다. 실제 장비를 확보하지 못하면 해당 목표는 `미검증`이다. 헤드리스 브라우저에서 캔버스가 정상 호출된 것만으로 픽셀 품질이나 실제 GPU FPS를 검증했다고 하지 않는다.

서버 CPU 측정은 한 경기 30명에서 시작하고, 같은 서버에 여러 방을 호스팅하려면 방 수를 별도 부하 차원으로 추가한다. 30명 한 방 시험을 여러 방 동시 운영 보장으로 확대하지 않는다. 네트워크 송신 예산은 엔티티 수·스냅숏 크기를 측정해 보고하며, 예산 초과를 이유로 호스트의 전투 의미 정보를 빼지 않는다.

`TEST_REPORT.md`의 각 시험 결과에는 아래 필드를 둔다.

```text
testId:
status: PASS | FAIL | NOT_RUN | BLOCKED
commit:
environment:
fixture:
seed:
commandOrManualSteps:
expected:
observed:
evidencePath:
remainingRisk:
```

최종 보고에는 구현한 기능, 자동 시험 결과, 브라우저에서 직접 확인한 흐름, 검증하지 못한 학교 실기기·외부 서버 항목, 알려진 결함을 구분한다. 실패한 인수 조건을 문서에서 지우거나 목표를 낮춰 완료 처리하지 않는다. 사용자가 정한 흐름을 끝까지 플레이할 수 있어야 첫 플레이어블 버전으로 인정한다.

## 11. 통합 시 확인할 결정과 충돌 가능 지점

- 역할별 뽑기와 전설 3종의 역할 범위 충돌은 다음 초기안으로 처리한다. 일반 뽑기는 5역할을 모두 지원하고 일반 80%·고급 20%이다. 고급 통합 뽑기는 일반 30%·고급 60%·전설 10%이며, 고급 역할 지정은 전설이 있는 탱커·근접·마법만 허용한다. 고급 원거리·지원 지정은 비활성화하고 그 사유를 화면에 명시한다. 빈 풀 재추첨·역할 외 전설 강제 지급·확률 재정규화는 하지 않는다.
- 시작 퀴즈 0점 학생도 무료 일반 영웅 선택권 1개로 첫 출정할 수 있다. 초기 자산은 퀴즈 정답에 따른 금액 그대로다. 봇도 같은 선택권으로 영웅 하나를 골라야 하고 무료 자산을 따로 받지 않는다.
- 5초 최소 사망 대기는 초기 제안이며 인간 학생 자동 부활은 금지다. 봇의 정상 관리자 재출정과 인간 자동 부활을 혼동하지 않는다.
- 양쪽 넥서스 동시 파괴는 같은 틱 피해를 끝까지 정산한 후 무승부를 기본안으로 제시한다. 종료 판정 우선순위를 전투 명세와 맞춘다.
- 위의 28/40경기 목표와 성능 예산은 구현 후 튜닝·검증 기준이다. 사용자가 보장한 결과 또는 이미 측정한 성능으로 표현하지 않는다.
- 전체 인원 30명의 정원, 팀당 15명 제한, AI 라벨, 로스터 잠금 시점, 시상식에서 AI 표시 정책은 호스트·학생·서버가 같은 설정을 공유해야 한다.
