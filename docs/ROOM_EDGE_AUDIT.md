## 발견 후 수정한 결함

- `deathId`가 생략되면 이전 생명의 지연 요청이 현재 사망 상태에서 적용될 수 있었다. 모든 사망 후 정비 변경에 현재 사망 세대 일치를 요구하도록 룸 코드가 수정되었다.
- 요청 결과가 보유 영웅 객체를 참조하여 이후 성장 시 과거 ACK 내용도 변했다. 확정 응답을 `structuredClone`하여 최초 결과를 보존하도록 수정되었다.

## 저장 관련 후속 수정과 검증

감사 후 위 표의 저장 버전 및 비활성 정리 문제를 수정했다.

- `src/server/versions.ts`에서 규칙 버전, 전체 영웅 콘텐츠 SHA-256, 실행 밸런스와 봇 전술 설정 SHA-256을 계산한다. 키 순서와 무관한 정규화를 사용하며 배열 순서는 보존한다.
- 진행 중인 네 단계는 저장 버전이 없거나 하나라도 다르면 복원을 거절하고 원본 DB를 유지한다. 로비와 이미 확정된 결과는 읽을 수 있으며 결과를 재계산하지 않는다. 게임 시간은 복원 시 경과시키지 않는다.
- `Storage.expireInactive`는 호출자가 지정한 방만 대상으로, 식별자 일치·비활성 단계·24시간을 다시 확인한다. 방과 생성/입장 요청은 한 트랜잭션에서 삭제하고 확정 결과·경제 원장·명령 기록은 보존한다. 현재 접속자 제외와 주기 실행은 서버 인덱스가 담당한다.
- 삭제 중 SQL 실패를 주입해 앞서 삭제했던 방과 요청까지 롤백되는지 확인했다.

`tests/storage-version.test.ts` 19개 PASS. `node node_modules/tsx/dist/cli.mjs --test tests/storage-version.test.ts tests/room-edge.test.ts` 실행은 총 31개 PASS / FAIL 0 / SKIP 0, 타입 검사 종료 코드 0. 이 결과는 저장 계층의 버전·정리 시험이며, 24시간 실제 서버를 켜 둔 운영 시험으로 표시하지 않는다. 이전 버전의 진행 경기 DB는 자동 변환하거나 삭제하지 않으며, 새 시험은 별도 `DATABASE_PATH`에서 수행한다.
