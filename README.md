# 클래스 클래시 · Class Clash 0.2

퀴즈로 얻은 학습 재화로 영웅을 준비하는 2진영·3라인·정글 자동 공성 게임입니다. 호스트는 전체 전장을, 학생은 자신의 영웅을 따라가는 화면을 봅니다. 서버가 채점·재화·뽑기·전투·승패·시상을 결정합니다. 유료 서비스나 외부 계정 없이 로컬에서 실행합니다.

## 0.2 기준과 보존

최종 사용자 확정에 따라 이 채팅의 LOL 3라인·정글 리워크(70987cb)를 유지합니다. 원래 첨부 명세의 2라인 관련 항목은 docs/class-clash-0.2/00_USER_OVERRIDES.md와 유효 계약이 대체합니다. 두 진영,18영웅·36스킬, 학생별 활성 영웅1명, 퀴즈·경제·수동 재출정 규칙은 유지합니다.

승인된 원본은 assets/art-source/source-lock.json에 고정합니다. build/pretest는 기존 도트 생성기를 호출하지 않으며 원본을 읽어 검증·패킹합니다. 원본이 달라지면 실패하고 자동 덮어쓰지 않습니다. 실제 변경은 ENGINE_CHANGELOG.md와 BALANCE_CHANGELOG.md, 실행 결과는 TEST_REPORT.md를 확인하세요.

전체 로컬본에는 사용자가 지정한 학교 교육용 그래픽이 포함됩니다. 공개 소스 브랜치에는 제한된 이미지·동영상·원본 자료를 올리지 않습니다. 공개 소스만 복제한 경우 로컬 승인 자산 묶음을 먼저 복원해야 전체 build와 게임 실행이 가능합니다. 공개 소스 CI의 test:source 통과는 아트·브라우저·전체 경기 통과를 뜻하지 않습니다.

## 설치와 실행

Node.js **24 LTS**와 npm이 필요합니다. 구현 검증 환경은 Node 24.19.0입니다. `package-lock.json`의 정확한 의존성을 사용합니다.

Windows에서는 `start-local.cmd`를 두 번 클릭해 설치·빌드·서버 시작을 진행할 수 있습니다. 열린 서버 창을 유지한 채 아래 로컬 게임 주소를 엽니다.

```sh
npm ci
npm run dev
```

[로컬 게임 열기](http://localhost:3000). 개발 명령 하나로 Vite와 Node 서버를 함께 실행합니다.

운영 형태로 로컬 실행:

```sh
npm run build
npm start
```

빌드된 화면과 `/ws` 연결을 동일한 Node 서버, 기본 3000번 포트에서 제공합니다. 정적 파일만 GitHub Pages에 올리는 것으로 실시간 서버를 대체할 수 없습니다.

## 호스트·학생 테스트

1. **새 방 만들기**를 누릅니다. 방 코드·참가 링크·QR을 학생에게 보여 줍니다.
2. 혼자 시험하려면 **30명 채우기**를 누릅니다. 표준 AI가 청팀·홍팀 각각 15명으로 입장합니다. AI 추가·제거·팀 이동은 로비에서 가능합니다.
3. **시작 퀴즈 시작**을 누릅니다. AI도 20문제를 실제로 제출해 정답당 1원을 얻습니다. 학생은 참가 링크를 다른 브라우저 프로필이나 별도 탭에서 열고 닉네임으로 참가합니다.
4. 시작 퀴즈가 끝나면 일반 영웅 1명을 무료 선택하고 성장·포지션 선택 (탑/미드/바텀/정글) 후 **준비 완료**를 누릅니다. 호스트가 5초 카운트다운을 시작합니다.
5. 전투 중 학생은 자동 전투를 보거나 10문제 묶음을 풉니다. 마지막 답안 확정 후 다음 묶음까지 30초입니다. 살아 있는 영웅은 교체·성장·뽑기·포지션 변경을 할 수 없습니다.
6. 사망하면 정비합니다. 현재 밸런스의 최소 20초 뒤 **출정** 버튼으로 다시 출발합니다. 학생을 자동 부활시키지 않습니다. 퀴즈 중 사망해도 문제와 보상은 유지됩니다. 변경 근거는 CHANGELOG.md에 있습니다.
7. 적 넥서스가 파괴되면 시상식과 실제 개인 기록을 확인합니다. **같은 참가자로 재경기**는 로비로 돌아가 다음 경기를 준비합니다.

사람 1명+AI 29명 시험은 학생을 먼저 참가시킨 후 호스트에서 30명 채우기를 누르면 됩니다. 호스트는 참가 정원에 포함되지 않습니다. 같은 학생 세션을 두 탭에서 열면 새 연결이 제어권을 얻고 이전 탭에 안내합니다. 새로고침은 동일 참가자로 복구됩니다.

## 교실 LAN

PowerShell:

```powershell
$env:HOST='0.0.0.0'
npm start
```

교사와 학생 기기 모두 `http://교사컴퓨터의LAN주소:3000`을 사용합니다. 교사가 LAN 주소로 방을 만들어야 QR에도 학생이 접근할 수 있는 LAN 주소가 들어갑니다. `localhost` QR은 다른 기기에서 사용할 수 없습니다. 교사 컴퓨터의 방화벽에서 해당 포트 접근이 허용되어야 합니다. 기본 바인딩은 `127.0.0.1`입니다. 인터넷 운영에는 별도의 Node 호스팅과 HTTPS/WSS 구성이 필요합니다. 현재 공개 배포와 학교 실기기 시험 여부는 TEST_REPORT.md를 확인하세요.

## 문제 은행

로비 **퀴즈 설정**에 20~1000문제를 붙여 넣습니다. 기본 영어 문제 50개가 포함됩니다. 각 줄은 `문제 | 정답 | 오답 | 오답 | 오답`입니다. 보기 순서는 서버가 섞습니다. 잘못된 행·중복 보기·길이 오류는 저장 전에 거절합니다.

```text
be in charge of | ~을 담당하다 | ~을 기다리다 | ~을 포기하다 | ~에 참여하다
```

## 검증 명령

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run build
npm run test:e2e
npm run test:load
npm run test:soak
npm run test:render-perf
```

- `test`: 먼저 운영 빌드를 자동 생성한 뒤 서버 규칙, 경제·퀴즈·세션·복구, 전투·36개 스킬, 실제 도트 파일을 검사합니다. 새 설치에서도 별도 빌드 없이 실행할 수 있습니다.
- `test:e2e`: 운영 빌드를 실제 Chromium에서 실행해 호스트·학생 UI와 렌더링을 검사하고 화면·기록을 저장합니다. 시험 배속은 화면에 표시합니다. 시험 DB의 위치는 `artifacts/e2e-run-location.json`에 기록합니다. 긴 전투의 기록 부하를 줄이기 위해 trace는 기본 OFF이며 `CLASH_E2E_TRACE=1`일 때만 실패 trace를 보존합니다.
- `test:load`: 호스트 1개와 학생 30개의 독립 WebSocket 인증·600개 답안·출정·중복 뽑기·재접속·실제 전투를 검사합니다. 서버 AI 시험과 구별합니다.
- `test:soak`: 표준 AI 30명, 기본 40개 고정 시드로 같은 실제 전투 엔진을 가속 실행합니다. 15분 관측 상한은 시험만 종료하며 게임의 승리 조건을 바꾸지 않습니다. 미완주 또는 목표 시간 비율 미달이면 종료 코드 1입니다.
- `test:art-preservation`: 전체 build 전후 원본 해시를 비교합니다. 실패하면 종료 코드1입니다.
- `test:v02`: 사람1+AI29의 첫 경기와3회 연속 재경기, 문제 중 사망, 새로고침, 독립 성장, 수동 정글 출진,7종 시상을 실제 브라우저에서 확인합니다. 시험용4배속이며 성능 측정이 아닙니다.
- `test:soak:parallel`: 같은 엔진의40개 표준30AI 고정 시드를2개 작업자로 검사합니다. 모든 결과와 미완주를 기록합니다. 결과 판정용이며 병렬 실행의 틱 시간은 운영 성능값이 아닙니다.
- `test:realtime`: 다른 부하 시험을 종료한 뒤 호스트+학생+29AI의 실제1배속 전투13분을 측정합니다. 조기 넥서스 파괴 시 재경기를 이어 누적 전투13분을 채우며 준비 시간은 제외합니다.
- `test:source`: 학교용 자산을 포함하지 않는 공개 소스 CI의 제한된 서버 규칙 시험입니다. 전체 시험을 대체하지 않습니다.
- `test:render-perf`: 다른 부하 시험을 종료한 뒤 운영 빌드·30 AI·정상 1배속으로 5분 동안 호스트 프레임 간격을 측정합니다. 설정된 p95 기준을 넘으면 종료 코드 1이며 실제 학교 기기 시험은 아닙니다.

Windows에서 물리 GPU를 사용하는 Playwright 시험은 다음처럼 구분해 실행할 수 있습니다. 이 개발 노트북에서는 기본 헤드리스 실행이 SwiftShader를 선택했고, 아래 설정은 실제 Intel Iris Xe / Direct3D11로 확인했습니다. 성능 보고서에는 두 환경을 별도로 기록합니다.

```powershell
$env:CLASH_TEST_GPU='d3d11'
npm run test:render-perf
npm run test:e2e
```

모든 검사 스크립트는 실패 시 0이 아닌 종료 코드를 반환합니다. 결과 JSON·로그·화면 캡처와 재현 가능한 시각 검토 기록은 `artifacts/`에 있습니다. 전체 브라우저 시험은 OS 임시 폴더에 DB·실패 trace를 저장하며 경로를 `artifacts/e2e-run-location.json`에 남깁니다. 동영상은 기본 녹화하지 않습니다. 3회 정상 종료 재경기를 포함하는 전체 시험에는 시간이 걸립니다. 개별 시드 디버깅: PowerShell에서 `$env:SEEDS='1'; $env:SEED_START='1001'; npm run test:soak`.

## 자산과 저장

18종 외형은 사용자가 첨부한 챔피언 패키지의 PNG·fanim 원본을 그대로 사용합니다. LOL 폴더의 1280×1280 맵을 탑·미드·바텀과 양 팀 정글 6캠프에 연결했습니다. 원본 해시·패키지 작성자 정보는 assets/source/jungle-rework/provenance.json, 역할별 외형·클립 연결은 src/shared/champion-art.json에 있습니다. 출처에 별도의 라이선스를 추가하거나 원본을 자체 제작물로 표기하지 않습니다.

[현재 챔피언 애니메이션 검수](http://localhost:3000/champion-review.html)에서 18종의 모든 연결 동작을 볼 수 있습니다. 실제 경기는 서버 적중 틱에 맞추어 공격·스킬 애니메이션을 재생합니다. 기존 두 스킬와 독립 성장 규칙은 유지합니다. 원본에 스킬 클립이 하나인 외형은 두 스킬이 해당 시전 동작을 공유하며, 피해 판정·투사체·영역 효과는 각 스킬 정의를 따릅니다.

정글은 아군 캠프를 먼저 사냥하고, 부족한 전선 지원 또는 적 정글 침투를 결정합니다. 체력이 낮으면 본진으로 돌아가 회복합니다. 캠프는 처치 60초 후 재생성하고 처치자는 체력 18% 회복·25초 이동 속도 12% 증가를 얻습니다. 골드는 퀴즈에서만 얻습니다. 전투 중 포지션 변경은 허용하지 않으며, 사망 후 다음 출진 때 다시 선택합니다.

각 팀·라인의 첫 웨이브는 근접 3 + 원거리 4기입니다. 웨이브 간격 35초, 8/10/12분부터 생성되는 양 팀 미니언의 체력 배수 3/8/12, 공격 배수 2/4/6을 balance 설정에 기록했습니다. 기존 공성 피해 페이즈도 적용됩니다. 미리 정한 시간이 되어 승리하거나 구조물 HP가 자동 감소하지 않습니다.

이전 아트와 보고서는 보존했습니다. art-gallery.html, artifacts/asset-motion, artifacts/world-assets의 결과는 이전 버전 기록입니다. 현재 0.2 증거는 artifacts/v02와 TEST_REPORT.md의 최신 항목을 확인하세요. LOL 리워크 당시 증거는 artifacts/jungle-rework에 별도로 남아 있습니다.

SQLite WAL 파일의 기본 경로는 `data/class-clash-0.2.sqlite`입니다. 기존 `data/class-clash.sqlite`와 `data/class-clash-jungle.sqlite`는 그대로 보존합니다. 서버 재시작 시 일관된 체크포인트를 복구하고, 꺼져 있던 동안 전투 시간을 진행시키지 않습니다. `DATABASE_PATH`, `PORT`, `HOST`, `APP_ORIGIN`은 환경 변수로 설정합니다. `.env.example`은 설정 예시이며 자동으로 읽지 않습니다. 로컬 데이터에는 닉네임·학습·경기 기록이 저장되므로 학교의 보관 정책에 맞춰 관리하세요.

구조와 복구 방식은 ARCHITECTURE.md, 실제 실행 결과와 미검증 항목은 TEST_REPORT.md, 이어서 작업할 상태는 PROGRESS.md에 기록합니다.

전체 소스·승인 자산·검증 영상을 개인 보존용 ZIP으로 만들고 원본 해시를 확인하려면 PowerShell 7에서 실행합니다. DB·비밀 설정·의존성 폴더는 제외하며 기존 ZIP은 덮어쓰지 않습니다.

```powershell
./scripts/package-local.ps1 -OutputName Class_Clash_0.2_Local.zip
./scripts/verify-local-package.ps1 -Archive ./Class_Clash_0.2_Local.zip
```

## 지속 실행 배포

DEPLOYMENT.md의 Node24+WebSocket+영구 SQLite 볼륨+Caddy 구성을 사용합니다. production은 실제 HTTPS APP_ORIGIN, 교사용 HOST_ACCESS_CODE, 영구 DATABASE_PATH가 없으면 시작을 거절합니다. 호스팅 권한이 없는 현재 상태와 외부 검증은 DEPLOYMENT_REPORT.json에 별도로 기록합니다. GitHub PR은 공개 플레이 주소가 아닙니다.
