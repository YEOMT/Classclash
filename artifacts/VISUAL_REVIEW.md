# 실행 화면 검토 기록

검토 환경: Windows, Node 24.19.0, Playwright Chromium, Vite 개발 서버, 일반 게임 속도(20 Hz), 호스트 1366×768 / 학생 1280×800 / 모바일 CSS 뷰포트 390×844. 학교 실기기 검증은 아니다.

## 실행한 흐름

`node node_modules/@playwright/test/cli.js test --config tests/e2e/ui.config.ts`

실행 결과: **PASS, 1개 테스트, 약 1.7분**. 실제 HTTP 방 생성·참가와 인증 WebSocket 명령을 사용하는 브라우저 시험이다. 전투는 실제 서버의 동일 엔진이 계산하며 테스트에서 전투 상태나 승리를 주입하지 않았다.

1. 호스트 방 생성, 학생 1명 참가, AI 29명 채우기와 15 대 15 명단 확인.
2. 학생이 시작 퀴즈 20문제를 화면에서 선택·제출. 다른 AI도 정상 시간에 문항별로 답안 제출.
3. 첫 무료 궁수 선택, 준비 완료, 호스트 5초 카운트다운.
4. 첫 실제 적중이 기록된 전투에서 호스트 전체 전장과 학생 추적 시점 캡처.
5. 학생 새로고침 후 동일 참가자 복귀, 전투 퀴즈 시작, 새로고침 후 동일 attempt 복원·이어 풀기.
6. 모바일 폭 390px에서 퀴즈 화면 유지와 가로 넘침 없음 확인.
7. 실행 중 브라우저 pageerror 없음. 필수 18명 영웅 PNG 로딩 오류 없음. Pixi 실제 프레임 진행 확인.

## 수정 후 다시 확인한 문제

- 개발 서버가 Playwright trace에 저장된 HTML 파일을 보고 페이지를 재시작하던 문제: Vite가 artifacts/data/spec-source/.tools를 감시하지 않도록 수정 후 실제 흐름 재시험.
- 시작 퀴즈 마지막 피드백이 전투 패널에 남던 문제: OPENING_QUIZ 종료 시 패널 상태를 초기화하고 전투 10문제 시작·새로고침·이어 풀기로 회귀 확인.
- 느린 요청의 응답 누락: 서버는 명령 ID를 포함한 실패 ACK를 반환하고, 클라이언트는 15초마다 동일 명령 ID로 재확인한다. 미확정 거래를 새 ID로 자동 구매하지 않는다.
